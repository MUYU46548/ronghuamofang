## 一、结论（先看这段）

1. **最大风险不是功能少，是"假绿灯"。** 整套判据（七维/审美/记忆/卷弧/文体）至今
   **没有一次真模型跑完整本书的证据**，全部是夹具证据。夹具能证明"接线对"，
   证明不了"模型会按格式输出"。
2. **本轮抓出 4 处"配了不生效 / 界面说假话"**（已修，见第二节）。这类问题的共同形态：
   代码写了、单测绿了、界面还告诉你它生效了，但实际没接上。
3. **功能缺口按"会不会让你拿到假结论"排序**，不按开发难度排序（第三节）。

## 三、还没补的（按"会不会给你假结论"排序）

### P0 — 需要真模型的（**结论：现在不跑**）

2026-10-20 实测过一轮，先把数字放这里：

- 引擎是 `hermes`（不是纯 API 直连），模型由 hermes 内部定 = **`mimo-v2.6-flash`**（轻量临时模型），
  `config/system.yaml` 里的 `model.*` 在这条路径上**不生效**。
- 最小任务（"只回复两个字"）实测 **input 6361 / output 14 token，9.7 秒**。
  → **每个子会话冷启动固定吃 ~6.3k 输入 token**，与任务大小无关。7 阶段多批次 = 10 个以上子会话
  → 光固定开销 6–7 万 token，加正文生成是十几万量级。
  ⚠️ 这次测量本身是浪费：agent 冷启动贵是常识，不该花订阅额度去证实。
- **`data/` 为空是正常态**，不是"没开始"。跑批的正确起点是**出厂预设**：
  `python scripts/preset_apply.py --apply <id>`（把 `examples/presets/<id>` 的素材 + 配置铺成当前项目），
  再 `python scripts/orchestrator.py`。5 套预设各带 `verify.must_mention` / `forbidden` 判据
  （`test_presets.py` 261 条断言守着），**它们就是能力验证用例**。
  所以"验证流水线能跑到哪"应该跑预设，而不是现编一本书 —— 本节第一版写"从零生成一本书"是错的。

因此：**现在跑性价比极低**，三条理由——

1. **验证能力的正确方式是跑出厂预设，不是现编一本书。** 预设自带判据，跑完能直接回答
   "这一版能跑到哪、断在哪"；而且预设的章节数固定（4–10 章），成本可预估。
2. **模型是临时的。** 用它测出的"JSON 合规率""文风效果"**不能迁移到正式模型**，等于花钱买不可用结论。
3. **能离线验证的已经验证了。** 接线、N/A、提示词裁剪、拒写、早退、回落告警都有断言
   （`nfctl test` 128 个文件全绿）。

空账本也**不是静默假绿**：评审面板的空态写明「还没有账本 —— 跑过 stage5 之后每章自动生成」。

**什么条件下才真的必须跑**（三条，都不是现在）：

| 触发条件 | 跑什么 | 成本量级 |
|---|---|---|
| 发版前 | 全链一次，产物落 `docs/evidence/` | 十几万 token |
| 你想让真模型评审**自己现成的稿** | 贴 1 章到 `data/chapters/raw/`，只跑 stage5 单批 | 几千 token，且有实用价值 |
| 换成正式模型后校准阈值 | 用同一章对比账本分布 | 同上 |

在此之前，继续做**零 token 的功能**（见 P1/P2）。

## 四、成本预警（按你的实际项目估）

| 项 | 量级 | 说明 |
|---|---|---|
| 3 章项目跑一轮 stage1–7 | 与章节数成正比 | 你当前项目 `chapters: 3`，是试跑的好规模 |
| 每章 stage5 多出的评审输出 | **约 600–800 token/章**（叙事）；散文裁后约省一半 | 12 条举证 JSON vs 原来的自由文本报告 |
| **重跑才是真正的成本** | 每章输入可达上万 token（范文 ≤6000 字 + 记忆块 + 设定） | 任何"判失败 → 重跑"都是成倍烧钱 |
| 建议节奏 | 先跑 5 章 | 看账本合规率与同质化指标，再决定是否跑长篇 |

**省钱的三个开关（都可关）**：
- `book.style_reference_max_chars`（范文注入上限，默认 6000，**每章都要付**）
- `chapter.rolling_volumes: 0`（关分卷滚动）
- 散文/随笔：不分卷、不评无关维度（本轮已生效，token 直接降）
