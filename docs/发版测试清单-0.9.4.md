# 发版测试清单 · v0.9.4（2026-11-17）

> 装在**真实安装环境**上测，不要用 `npm run dev`。开发模式有源码树与 `.venv` 兜底，
> 装完才不会的那些问题（路径、运行时、种子刷新、拆域后端点 404）只有安装版能暴露。
> 每条都写清“怎么点 / 算通过 / 失败了交什么证据”。

**安装包**：`console/dist/ronghuamofang-console-setup-0.9.4.exe`（110.1 MB）

**这一版改了什么**（决定你该重点测哪）：

- 产品行为**不变**，只把 `nf_api.py` 里剩下的一批端点拆成域模块（运行控制 / 配置写侧 /
  素材碎片写侧 / 审稿动作），以及内置手册统一版式。
- 所以重点不是“功能新不新”，而是**装好后所有页签都还能正常读写**（拆域的典型故障是
  “页面打开但保存 404 / 点了没反应”）。
- 另外补了四套零 token 的端到端用例（整章重写落盘、段落精修、停止不亏稿、偏短章策略），
  它们跑在仓库里，不随安装包走；装完能对着下面 B/C 段手点一遍就够。

## A. 安装 / 升级（必做，约 5 分钟，不需要模型）

1. 双击 `ronghuamofang-console-setup-0.9.4.exe`。
2. **安装目录保持向导显示的目录不变**（覆盖旧版），下一步到底。
3. 启动后确认：
   - 窗口正常出现，无黑窗、无控制台闪烁；
   - “关于”里版本是 **0.9.4**；
   - “项目”页里你现有的书还在，章节数/进度与升级前一致。
4. 工作区代码已刷新：打开 `%APPDATA%\绒花墨坊\workspace\.seed-version`，内容应为 **94**。
   （这一步看的是“安装包里的新脚本真的铺进工作区了”，不是版本号自报。）

**算通过**：四条全绿。
**失败样子**：版本还显示 0.9.3 / 书不见了 / `.seed-version` 还是 93。
**交什么证据**：截图（关于页 + 项目页）+ `%APPDATA%\绒花墨坊\workspace\logs\` 里最新日志。

## B. 拆域回归：每个页签还能读写（必做，约 10 分钟，零 token）

这一版把四组端点搬了家，**任何一处 404 都会表现成“按钮点了没反应”**。逐条走：

1. **运行控制**（流水线页）：点一次“预演（dry-run）”。
   - 算通过：出来一段“计划执行 N 个阶段”，且**没有**产生费用、没有新章节。
2. **配置写侧**（设置页）：
   - “预算与止烧 → 单章字数”改一下再改回来（如 4000/7200 → 4200/7200 → 存 → 再改回），
     每次保存都应提示成功，刷新后值还在；
   - “Word 模板”下拉选当前模板再点“应用”，应提示已应用。
3. **素材 / 碎片写侧**（素材页）：
   - 新建一条碎片或改一条已有碎片的正文，保存后列表/正文里能看到新内容；
   - 再导一次同名素材卡，应明确提示“同名素材卡已存在（不覆盖）”。
4. **审稿动作**（审稿页）：对一条已有审查发现点“采纳”或“忽略”，刷新后状态还在。

**算通过**：四组都能读能写，没有“保存失败 / 请求失败 / 404”。
**失败样子**：页面能打开但保存报错、或在日志里出现 `/config/... /materials/... /review/... 404`。
**交什么证据**：哪一条、点了什么、界面文字 + `workspace\logs\` 最新日志。

## C. 重写 / 精修 / 停止（需要真实模型，约 15 分钟，建议 1 章）

这三条是“改错一个字就亏一章”的动作，装完请至少在**一本书的一章**上各走一次：

1. **整章重写**：章节 → 某章旁边“重写”→ 面板出现并在写（有文件尾字数/字节在跳）。
   - 算通过：写完后 `data/chapters/raw/NN.md` 是新稿；旧稿在
     `data/chapters/rewrite_backup/NN_<时间>.md` 里能打开；
   - 再看一眼**别的章没被动**。
   - 想验失败兜底：重写进行中点“中断”，或断网让它失败 —— 回执应写明
     “重写第 N 章失败，**旧稿已自动恢复**”，且 `raw/NN.md` 回到重写前那一版。
2. **段落级精修**：章节 → 精修 → 选一章 → 选一段 → 写意见 → 先看 diff 再采用。
   - 算通过：**只有这一段变了**，其他段落逐字不变；采用后旧稿进了历史（能回退）；
   - 冲突不覆盖：生成候选后手工把这一段改一下，再点采用 → 应提示冲突（现在的正文 /
     候选基于的正文 / 候选 三件都摊开），**不许静默覆盖**；确认后才覆盖。
3. **停止不亏稿**：流水线跑写作时点“中断”。
   - 算通过：`data/state/truncated/chNN_停在_*.txt` 有这次写到的残稿；
     已经写完的章一个字节没变。

**交什么证据**：章节号 + 回执文字截图 + 上面三个路径的文件是否如预期。

## D. 偏短章的处理（需要真实模型，可选，1 章）

1. 临时把“单章字数”调高（如 `6000 / 9000`），跑一章它写不满的章。
2. 看进度/日志里它是怎么处理的：
   - 算通过：字数**严重不足**（低于下限六成）时提示“自动转加强模式（拆段落群逐群补足）”，
     而不是一次次“打回：整章重生成”；
   - 字数只是差一点时提示“打回：定向扩写”。
3. 验完把字数改回 `4000 / 7200`。

**为什么要测**：这一条的历史问题是“弱模型怎么骂都写不长，重写 N 次还是短”，
现在两条路都有明确出口；我要的是你在装好的环境里看到那两句提示语真的出现。

## E. Word / 判定 / 成本（零 token，约 10 分钟）

1. **Word 成品**：流水线 → Word 成品 → 打开 docx：书名/作者已填、章标题层级对、目录域在、
   页边距与模板一致。
2. **判定**：章节 → 判定 → 单章 → 勾一条事件（选分类、填证据句）→ 保存；
   算通过：摘要里“认定 N 件 / 计入 N 件”跟着变。
3. **成本**：成本页的数字应该等于当前这本书 `logs/runs.db` 里的明细之和（本次跑了几次、
   各多少 token）。截图即可，我会据此对账。

## F. 安装版里的外部 Agent（可选，约 10 分钟）

1. 设置 → Agent 接入 → 按页面“复制配置 / 启动提示词”贴给 Hermes。
2. 算通过：对方能列出 `nf_*` 工具，并成功调用一次只读工具（如 `nf_get_state`）。
3. 失败时先说是**哪一层**报错（垫片 / 传输 / 服务），别只说“连不上”。
