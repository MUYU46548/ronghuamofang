## 〇、一句话结论

**Papilot 是竞品，而且是最直接的那种：它在“改文”这一段的手感上完爆我们。**
它把 AI 改稿做成了一条有位置、有备选、有作用域的流水线；我们是“填一句意见 → 点一次 → 出一条候选 → 好看就留、难看再点一次”，加上“一张 40 项的全展开清单 × 两个按钮”。

不是没做裁定 —— 是**裁定没有位置、改稿没有备选、审阅阶段还在花钱**。

上一版本文把它写成“不是竞品，是范式”，那是错的，正是“看到形态不同就判不同类”的老毛病。真实竞争发生在三个旧台账没扫的地方：**GitHub 开源仓**（`voocel/ainovel-cli` 已有 2279 star）、**B 站教程生态**（星月写作 2 万月活、8 人团队月入百万）、**邻域范式**（Papilot 用 LaTeX 重做了 AI 改稿的交互）。

## 三、Papilot 的改文机制：逐条拆

它解决的和 stage5 改稿裁定闸是同一个问题：模型改了源码，人要在脑子里把 diff 翻译成“改完之后是什么样”。
但它给出的不是“更好的 diff”，而是一整套**人可以指挥、可以验收**的机制。八条，全部可移植。

[Papilot](https://papilot.ai)（[GitHub](https://github.com/PapilotAI/papilot)，MIT，2026-10-26 建仓，559 提交，v0.10.2）
来源：`docs/fine-grained-diff.md`（9,083 B，3.1~3.7 原文出处）、`docs/requirements.md`（3.8）、`docs/guide.md`、README。

### 3.1 批注是唯一入口，聊天不是

选中一句话、或框选一个公式/图 → 写批注 → 提交。之后一切操作围绕这条批注展开。

> “Selecting a sent note (or its badge on a change) filters only the highlight overlays and decision targets to the edits associated with that note.”

**这条最狠**：批注不是“记下来以后翻”，是**改稿的句柄**。点批注 = 只看这条批注引起的改动。工具栏可以在“全部改动 / 当前批注”之间切，而且不丢已选项。

### 3.2 一条批注 → 一条主方案 + N 条备选

> “When an editing turn receives PDF notes, its prompt requests the main revision and alternatives with concise titles and reasons together.”

备选条数可调：`Off / Few (1–2，默认) / Balanced (2–3) / More (3–5)`，每条带一句标题和理由。原文明确：**是建议不是配额**，不许为凑数塞弱选项或重复选项；解析器最多接 6 条。

### 3.3 审阅阶段零调用、零编译

> “There is no generation button or inference request when reviewing.”
> “Missing or invalid optional data leaves the main proposal available; it never starts a fallback AI call.”

候选 PDF 按“源码版本 + 改动 + 被拒单元 + 预览格式版本”缓存。**切选项不触发任何 AI 调用，也不重新编译**；选项只是本地草稿，跨批注切换、关面板、刷新都记得。

这是对“抽奖”的正面回答：**花钱的那一次调用，一次性把可控范围买下来了**。后面几十次比较、来回看，一分钱不花。

### 3.4 逐处步进，作用域就是“这一条批注”

底部抽屉一行：左边选项 tab，中间 `‹ 2/5 ›` 在批注之间前后翻（到头就停），右边 接受 / 拒绝 / 评论 + LaTeX 源码开关。

> “Accepting a choice uses that option and **only the current note's edits**.”

拒绝会“immediately restores this note's original source through the review journal and can be undone”——立即恢复这段原文，且可撤销。
**接受的作用域是一条批注的改动，不是整章。** 相邻批注的改动留在文档里当上下文，不参与这次决定。

### 3.5 双向定位：改动 ↔ 页面

每条改动有精确的源码偏移量（exact source offsets）和独立归属的 PDF 标记；点改动跳页面，点页面看改动。比较视图是“原始 PDF vs 只替换这一条批注后的完整方案”并排，其他改动只作上下文可见、不高亮。

### 3.6 评论不立刻发

> “Save comments while reviewing, then explicitly send feedback to the same Codex conversation for another round.”

评论写在 PDF 面板里，留在**未发送草稿**，作者显式发送才回到同一条对话、进入下一轮。这就避开了“每改一次就把想法丢进聊天，然后聊天里堆了几十条互不相干的临时指令”。

### 3.7 粒度清理：不逼人点无意义的项

> “Invisible space/newline adjustments in ordinary prose are grouped with the closest substantive change in the same paragraph.”

普通散文里看不见的空格/换行调整并入**同一段里最近的实质改动**；段落分隔、纯格式、逐字保留的原文保持独立；TeX 构造与参考文献条目是原子的（不拆）；位置模糊的片段**保留历史链接，不猜新位置**。

### 3.8 冲突摊开，不覆盖

每次任务一个独立 git worktree；接受走三方合并；失败时**两个方案与正文都保住，把冲突显示出来而不是覆盖**；冲突后的又一次改稿是新的审阅轮，不自动接受；拒绝/撤销不碰正在跑的 agent 的工作区（要先中断）。

另外两条小的：它自带 7 个技能包（Polish / Proofread / Shorten / Check math / Consistency / Fix LaTeX warnings / Address reviewers），用户可在 `~/.papilot/skills/` 或论文自己的 `.papilot/skills/` 里加 markdown 技能并随稿提交 —— 我们的 `prompts/stage*.md` 是同一族，差别是它的技能跟着稿件走、可提交、可共享；手机可用，Accept / Reject / Comment 在底部一行。

## 四、映射：墨坊已经有什么，真正缺什么

### 4.1 已经有的（有据，不用重做）

| 能力 | 在哪 | 强到什么程度 |
|---|---|---|
| 段落级改稿裁定闸 | `docs/agents/stage5-gate.md`、`scripts/stage5_gate.py`、`tests/unit/test_stage5_gate.py`（23 项） | 段落级 `replace/insert/delete`；**全部勾完才合成**；一条不采用 = 成品与 raw 逐字节一致；`stale` 拒收旧裁定 |
| 产物候选区 + 作者批准 | `scripts/utils/product_gate.py`、`POST /review/products/decide`（GUI-only，22 处引用） | 阶段 1~6 全覆盖；sha 绑内容；作者手改留痕 |
| 在正文上选中就提意见 | `console/src/ParagraphRefinePanel.vue` 全文视图 | 选中文本 → 匹配段落 → 浮动按钮填意见（**只填不发**，防误点付费） |

**逻辑层我们不弱**：`stale` 拒收（raw_sha 对不上就作废旧裁定）、全拒 = 成品与 raw 逐字节一致、候选区按 sha 绑定内容 —— 这几条 Papilot 没有对等物。真正差的是**交互层**，而交互层正是作者每天要用的那一段。

**交互层现状（带行号）**

| 环节 | 墨坊现在 | 取证 |
|---|---|---|
| 改稿入口 | 点选段落 → 4 个快捷档 + 一个文本框自由写 → 点“让 AI 只改这一段” | `console/src/ChapterEditor.vue:888-909` |
| 候选数 | 点一次出 1 条。要第二条得**再点一次**，注释写明理由：“不搞‘一次调用出两条’（那等于每次点击翻倍花钱）” | `ChapterEditor.vue:937-949` |
| 批注 | 能存、能锚定（原文找不到退到前后文指纹 → `drift=True`；都找不到 → `missing` 标红），但**批注不驱动改稿**：“只记下这条批注”写着“不调用模型、不改正文” | `scripts/utils/annotations.py:136-183`、`ChapterEditor.vue:911-913` |
| 裁定面板 | `v-for` 全展开每一处改动，每处两个按钮“采用模型改法 / 保留原文”；没有“跳到正文这一段”、没有步进、没有“只看这一处” | `console/src/Stage5DiffPanel.vue:187-200` |
| 作用域 | 整章列表；合成是“合成全部已定稿”整章 apply | `Stage5DiffPanel.vue:141` |
| 定位方式 | 段落号（`selPara`）是坐标；批注有文本锚（`annotations.py`），裁定项没有 | — |
| 单处撤销 | 裁定项不能单独撤销，只能整章重新合成 | `docs/agents/stage5-gate.md` |

### 三条结论

1. **我们的改稿没有“位置”。** 段落号是坐标，不是锚。批注有锚却不驱动改稿 —— 所以每次都得回聊天里说“再改改那句”。这就是“全靠 agent 对话里临时发东西”的机制来源。
2. **“抽奖”是设计出来的。** 一次调用一条、多一条要再点 —— 省钱的方向对，做法错。正确做法是一次调用出 1 主 + 2 备选，**审阅阶段零调用**：既省，又可控。
3. **我们的裁定是一张清单，不是一条流水线。** 40 项全展开 × 两个按钮，人的实际行为是全勾。我们强制“全勾才合成”在逻辑上更严，但在交互不支持逐处走的情况下，等于把“审”变成了“点”。

### 4.2 差距三层（细目见第三节 3.1~3.8）

**差距 1｜没有备选：点一次出一条，就是抽奖**

一次调用一条，不满意只能再点一次（还要再花一次钱）。Papilot 是“一次调用出 1 主 + N 备选”，审阅时在备选之间切**零成本**。省钱的正确位置是“审阅阶段不调用”，不是“少给几个候选”。

**差距 2｜没有位置：批注不驱动改稿**

作者指着一句话说“这里不对”，系统只把它存成一条批注（`annotations.py` 的 drift/missing 做得很讲究），但不会因此只改这一处、也不会因此只把这一处的改动摆出来。于是只能回聊天里用自然语言再说一遍 —— 抽奖的第二层：说清楚与说不清楚全凭运气。

**差距 3｜没有流水线：整章清单一次勾完**

一次给 40 处改动，人的实际行为是全勾。Papilot 一处一处走，作用域就是这一条批注，接受/拒绝只影响这一处，拒绝立即恢复且可撤销。

**另一条（P2，不是现在的事）｜没有隔离**

它是“一任务一 worktree”。正文在 `data/`（已被 gitignore），不是 git-centric 的仓库结构，硬套工作区等于重做存储层。

### 4.3 一句话定位（建议）

现在对外说法是"半自动长篇小说生成系统"。这句没错，但和 8 个开源仓、15 家 SaaS 说的是同一句话。

Papilot 那种句式可以平移过来：**“不读 diff，在成书的版面上改。”**
它准确、可验证，而且在小说道路上还没人占（2026-11-10 那份调研自己也写了：几家的机制投入几乎全在“生成前怎么记住”，落在“修改时给证据”的只有三处）。Papilot 在 LaTeX 赛道已经证明这个角度成立 —— 它整个卖点就是“别读 `.tex`”。

### 5.2 判据：功能签名，不看形态

从我们自己的能力账本里抽 12 条签名，命中 ≥3 条就进台账 —— **不管它是 GUI、CLI、还是 SaaS**：

```
S1  阶段流水线（素材→设定→大纲→正文→检查→润色）
S2  七维/多维评审 + 引用原文举证
S3  卷弧/多层级滚动规划
S4  step 级断点续跑
S5  伏笔台账（埋/推/收）
S6  三层上下文（固定/滚动摘要/召回）
S7  去 AI 味确定性扫描（只报不改）
S8  候选区 + 人工批准后才合成
S9  段落级改动逐条裁定
S10 多模型/多 provider 路由
S11 任务书派发给外部 agent（自任务模式）
S12 多形态发布（桌面/CLI/MCP/Web）
```

这次实测的分布（自检一下这套签名管不管用）：

| 仓 | 命中签名 | 结论 |
|---|---|---|
| ainovel-cli | S1 S2 S3 S4 S5 S6 S7(部分) S10 = **8** | 必进台账，威胁最高 |
| Biz Novel Studio | S1 S2 S8 S10 S12 = 5 | 必进 |
| autonovel | S1 S2 S7 S9(部分) = 4 | 必进 |
| NovelFlow-AI | S1 S4 S5 S11 = 4 | 必进（S11 同构） |
| 笔仙助手 | S1 S7 S10 = 3 | 进 |
| **Papilot** | S8 S9 = 2 | **仍必进** |

**Papilot 这一行暴露了签名的盲区**：它按功能只命中 2 条（S8 S9），按手感是这一批里对我们威胁最大的。所以签名之外加一条例外：

> **凡在“改这一处”这件事上比我们顺的（批注驱动改稿、一次给多个备选、逐处步进、审阅零成本、双向定位），不看签名直接进台账。** 形态离得越远（LaTeX / 代码 / 设计稿）越要进 —— 差别越远，越可能是我们没想到的解法。

按旧口径（有官网、面向小说、桌面 GUI）这 6 个里只会收进 1 个。

### 5.3 落地形态

- **一个文件**：`docs/竞品台账.md`，只追加不改写，每条带 `首次发现日期 / 仓库或官网 / star 或月活 / 命中签名 / 一句话差异`。
- **一个脚本 + 周更 cron**：跑 5.1 的查询，把新命中与已有台账比对，只输出"新增"和"变化"（star 涨 50% 以上 / 发新版本）。
- **一条报警**：台账最后更新超过 14 天，任何会话开工时先说一句"竞品台账过期 N 天"。

**为什么必须写进文件**：这次漏掉 ainovel-cli 不是能力问题，是"没人记得要查"。靠记性，就会一直漏。
