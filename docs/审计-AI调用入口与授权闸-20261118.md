# AI 调用入口与“授权闸”审计（2026-11-18）

> 命题（作者）：**许可协议 = 总开关。只有用户完成授权确认后，DSH / AI 调用才允许被触发。**
> 本次审的是：两个产品里有没有这个开关，以及有没有绕过它的路。
> 审计对象：绒花墨坊（NovelForge @ `bc90387`）、方寸（fangcun @ `22f7b16`，含未提交改动）、
> 本机 DSH（`%LOCALAPPDATA%\Programs\DeepSeek Harness`，profiles 在 `~/.dsh`）。

---

## 0. 结论（先看这三行）

1. **两个产品都没有“许可协议 / 授权确认”这一层。** 有的是“免责声明”首启弹窗，
   而它的 ack 只存在**渲染层 localStorage**（墨坊 `mofang_disclaimer_ack_v1.1_<sha>`、
   方寸 `fc_disclaimer_ack`），后端 / MCP / CLI **一处都不读**。
   → 所以不是“某几个入口漏了闸”，而是**闸不存在**，所有入口都在闸门外。
2. **墨坊现在唯一的物理闸是 `engine: self`**（`make_client` 直接抛错，界面按钮全灰）。
   而它是一行 HTTP POST 就能改掉的配置项，**且不在 agent 禁止清单里**
   （`tests/http/test_config_writes_http.py` 就是用裸 POST、不带任何 GUI 凭据验证的）。
3. **方寸的 AI 面比“记录台”这个自我认知大得多**：桌面端 11 条 `llm:*` IPC +
   `arch:generate` + MCP 两条 BYOK 工具（`arch_generate` / `plan_draft`）+
   Python 侧 `tegula_llm.py`（CLI 与 planning/writeback 都用它）。同样一条闸都没有。

## 4. 若要把闸真装上，位置只有三个（不是十二个）

1. **咽喉层**：墨坊 `utils/llm_client.make_client()` / `dsh_client.DshClient`，方寸 `llm/chat.ts` 的 `chat()`
   —— 所有入口最终都经过它。装在端点上必漏（第 3 条就是证据）。
2. **ack 状态落服务端**：`workspace/config` 里存 `<协议版本, sha, 时间戳, 来源>`，
   不能 localStorage（换机器/换 profile/清缓存即失效）。
3. **未授权时的行为**：不是报错，而是“引擎锁死 + 端点 403 + 一句话说清去哪确认”；
   同时把 `/config/engine`、`/config/provider`、`/env/set` 收进 `FORBIDDEN_IN_AGENT_MODE`
   （现在这三条对非 GUI 来源是**完全敞开**的，而它们正是"打开钱闸"的三个旋钮）。

> 反面口径提醒：现在两产品的"安全"都建立在“用户没去点”和“引擎恰好是 self”上，
> 不是建立在任何一道校验上。这条要在文档里写清楚，不要留"已受许可协议保护"的印象。
