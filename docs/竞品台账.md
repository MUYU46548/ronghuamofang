## 判据：功能签名，不看形态

从我们自己的能力里抽 12 条。**命中 ≥3 条就进台账，不管它是 GUI、CLI 还是 SaaS。**

```
S1  阶段流水线（素材→设定→大纲→正文→检查→润色）
S2  七维/多维评审 + 引用原文举证
S3  卷弧/多层级滚动规划
S4  step 级断点续跑
S5  伏笔台账（埋/推/收）
S6  三层上下文（固定/滚动摘要/召回）
S7  去 AI 味确定性扫描（只报不改）
S8  候选区 + 人工批准后才合成
S9  段落级改动逐条裁定
S10 多模型 / 多 provider 路由
S11 任务书派发给外部 agent（自任务模式）
S12 多形态发布（桌面/CLI/MCP/Web）
```

**例外条款（2026-11-14 加）**：凡在“改这一处”这件事上比我们顺的（批注驱动改稿、一次给多个备选、
逐处步进、审阅零成本、双向定位），**不看签名直接进台账**。形态离得越远（LaTeX / 代码 / 设计稿）
越要进 —— 差别越远，越可能是我们没想到的解法。
