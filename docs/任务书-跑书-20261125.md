# 任务书 · 跑一本书（交给 DSH 执行）

> 写给执行方（DSH / 任何 agent）。**照单执行，不要发挥**。
> 生成时间：2026-11-25。对应版本：0.9.15。

## 0. 目标与硬约束

**目标**：用出厂预设 `rail-end`（6 章，最小可验证）从阶段 1 跑到阶段 7，
产出一份 Word 成品，并回报一份“验收回执”。

**硬约束（违反即停）**：

1. **不许改任何章节产物的正文**。改稿只走 `reject.py` 或界面；本任务只跑流水线。
2. **不许换模型、不许改 `config/system.yaml` 的 `engine`**。当前 `engine: dsh`。
3. **额度上限**：`config/system.yaml` 的 `budget.token_limit`（默认 1000 万/轮，
   单请求 50000）。超限即停，回报实际消耗，不要重试。
4. **不许用 `git` 之外的命令删除任何文件**；清场只允许 `snapshot.py` + 人工确认。
5. 每步失败就停，把命令 + 完整输出贴回来。**不许"再试一次"式的盲目重跑**。

## 1. 准备（三步，都可逆）

```bash
cd <仓库根>
source .venv/Scripts/activate          # Windows: .venv\Scripts\activate

# 1.1 先自检：环境、YAML、数据一致性
python scripts/nfctl.py check
python scripts/nfctl.py doctor

# 1.2 拍快照（这是回滚点，不拍不许往下跑）
python scripts/snapshot.py --note "跑书前 20261125"

# 1.3 看预设、铺预设（会归档现有工作区数据）
python scripts/preset_apply.py --list
python scripts/preset_apply.py --apply rail-end --dry-run    # 先看计划
python scripts/preset_apply.py --apply rail-end
```

**判据 1**：`--dry-run` 打印的书名/章数/目标目录与你预期一致；
铺完后 `data/books/rail-end/`（或预设指定目录）存在，`data/chapters/raw/` 下应有 6 个章节文件。

## 2. 跑流水线（逐阶段，不要一把梭）

```bash
# 2.1 阶段 1：素材 → 设定集（会停下来等你审批）
python scripts/orchestrator.py --stage 1

# 2.2 阶段 2：设定 → 章纲（同样可能停在审批门）
python scripts/orchestrator.py --stage 2

# 2.3 阶段 3：章纲细化
python scripts/orchestrator.py --stage 3

# 2.4 阶段 4：写正文（最贵的一步，6 章）
python scripts/orchestrator.py --stage 4

# 2.5 阶段 5→6→7：检查 / 润色 / 导出
python scripts/orchestrator.py --from 5
```

**判据 2（每阶段各自验，不用等全跑完）**：

| 阶段 | 成功的样子 | 失败的样子（停） |
|---|---|---|
| 1 | `data/setting/` 有 `setting.json`，角色/地点非空 | 文件为空或只有骨架 |
| 2 | `data/outline/` 有章纲，章数 = 6 | 章纲章数不对 |
| 3 | 每章有细化条目 | 有章缺失 |
| 4 | `data/chapters/raw/` 6 个文件，**每章 ≥ 4000 汉字** | 有章低于下限、或出现 `data/state/truncated/` 残稿 |
| 5 | `data/reports/`（或 `data/state/reports/`）有检查报告 | 报告缺失 |
| 6 | `data/chapters/refined/` 6 个文件 | 有章缺失 |

> 汉字数口径：只数汉字，不含标点与空白。用 `python -c "from utils.word_count import count; ..."`
> 或直接看各阶段日志里的字数。

**如果阶段 1 或 2 停在审批门**：那是设计如此（`gates.material_autonomy: false`）。
回报一句“停在阶段 N 审批门”，等作者在界面里点确认。**不要自行改配置跳过。**

## 3. 导出 Word 并验收

```bash
python scripts/stage7_convert.py
ls -l deliverables/            # 或项目配置里的导出目录
```

**判据 3**：

- 有一个 `.docx`，体积合理（6 章约 > 100 KB）；
- 用 Word/WPS 能打开，目录/章节标题齐全；
- 6 章都在，末章不残缺。

## 5. 出问题怎么处置（按顺序，不要跳）

1. **先看日志**：`logs/runs.db` 里的 `cost_log` 表 —— 跑没跑过、花了多少，以它为准。
   `data/` 为空**不代表没执行**。
2. **截断**（`finish_reason == "length"`）属已知情形：残稿在 `data/state/truncated/`，
   不落盘、exit_code 2。回报即可，不用重跑。
3. **真要回滚**：用第 1.2 步的快照，或 `reject.py` 撤掉某一章产物。**不要手删文件。**
4. 连续两次同一错误 → 停，回报。**不许换模型试**。

## 6. 明确不做的事

- 不跑 `--chapters` 全量之外的额外章节；
- 不跑 e2e（`tests/e2e` 会长期潜伏，且要起 GUI）；
- 不动 `prompts/`（出厂保底不允许现改）；
- 不把工作区里的 `data/` 提交进 git。
