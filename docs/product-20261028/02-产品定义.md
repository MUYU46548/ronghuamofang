## 一、产品一句话定义（对外发布用）

**给写长篇小说的作者用的桌面写作工具：它会读完生成的每一章，逐段逐句告诉你"这一句为什么不能用、在第几段"，并把不合格的章直接标成拒收；同时把两处替作者做决定的写作提示解开，让"要写得克制""不许新增情节"不再由程序规定。**

- 不用【跑命令行、读代码、看日志】；
- 不用【让写稿的模型自己给自己打 8 分】；
- 不用【"再跑一遍出厂预设试试"】来验证有没有变好。

> 一句话价值：**它不再骗你合格，而是有资格对你说"这章不行，是这一句"**；并且不再偷偷规定你该写得多"克制"。

## 二、能力架构（产品提供什么能力）

### 2.0 分层总览与闭环条

```
L1 作者决策层      回答：哪些判断只能由作者做，系统无权代做？
L2 判定能力层      回答：这稿能不能用？哪句不能用？为什么？（系统唯一的质检人）
L3 口径治理层      回答：判定按哪一版标准做的？标准改了，旧结论还算数吗？
                   （兼公共支撑层职责：配置 / 版本 / 记录 / 导出）
L4 生成侧解锁与验证层  回答：哪些"替作者做决定"的锁必须拆掉？拆了怎么证明真拆了？

能力闭环条（贯穿四层）：
  按某版口径判（L3）→ 出缺陷单并定位到段句（L2）→ 作者四选一裁定 + 感受裁定（L1）
  → 口径变更 / 作者不服 → 存量重判（L3）→ 结论单一出口（L3）
  →［P1］重写不合格章 → 成品失效并重出（L3）
```

### 2.1 L1 作者决策层（回答：哪些判断系统无权代做）

| 能力域 | 回答什么业务问题 | 缺了会怎样 | 覆盖场景 | 一期 |
|---|---|---|---|---|
| **A1 事件数闸门（作者勾选）** | 这一章的"事件"到底算不算一个事件？——由作者四选一裁定（人物处境／信息占有／关系／目标），系统只报"疑似凑数" | 事件数又回到"代码数段落"或"模型自评"，等于根因 1 复辟：验收权仍在被考核者手里 | S05、S15 | 是（P0） |
| **A2 感受标准裁定入口** | 这一句"有没有打中"只有作者能答 | 三标准只剩两条可算，第三条被系统假装算出来 → 判据又一次骗人 | S07、S15 | 是（P0） |
| **A3 整本否决与打回** | 读两章决定"继续读不下去"，否掉整本 / 打回某章 | 作者只能在 Word 里骂，系统侧没有任何反馈通道 | S07、S09 | S07 是（P0）／S09 打回动作是（P1，依赖真机重写） |

> 分层定位（要求显式）：**审批门在 L1 归属，在 L3 落地。** 门的"谁有权点头"属 L1；门的"状态怎么变、失效怎么算"属 L3。见 §2.5 边界重叠声明。

### 2.2 L2 判定能力层（回答：这稿能不能用、哪句为什么不能用）

| 能力域 | 回答什么业务问题 | 缺了会怎样 | 覆盖场景 | 一期 |
|---|---|---|---|---|
| **B1 确定性正文体检** | 字数够不够、句长有没有长句、对话标签复用几次、有没有自造计量单位——**全部可数、可复算** | 继续拿模型的"8 分"当质检结果，10/10 全背离的现状不变 | S06、S12、S15 | 是（P0） |
| **B2 伪具体·可替换标准（系统可算的那条）** | 这句能不能"换个数字照样成立"？能 → 是模板不是创作 | 伪具体无清单，作者只能说"垃圾"说不出"哪句"，S15 无法闭环 | S15 | 是（P0） |
| **B3 伪具体·功能标准（系统只召回，作者裁定）** | 这句有没有改变/揭示人物处境、信息占有、关系、目标？ | 系统若自判"有没有用"，就是把主观判断伪装成客观——重犯根因 1 | S15、S05 | 是（P0，见 §六 D3） |
| **B4 病因二分：章纲粒度 vs 正文未落地** | 是"章纲把一班次的连续动作拆成 4 个事件"，还是"章纲有事件、正文没写"？ | 两类混判 → 修错方向：去改正文（真因在章纲），改十次都不会变 | S05、S12 | 是（P0） |
| **B5 三档结论** | 这本书哪些章"能进精修"、哪些"要改"、哪些"直接拒收" | 只有"全绿"和"全红"两种表达，作者拿不到可用判断，S12 无法完成 | S12 | 是（P0） |
| **B6 缺陷单（哪句／为什么／第几段）** | 把结论翻译成"能直接照着改"的清单 | 结论停留在"不达标"，作者仍要自己找——等于没夺回验收权 | S12、S15 | 是（P0） |

> 分层定位（要求显式）：**事件粒度在 L2 的 B4；AI 腔（伪具体）在 L2 的 B1/B2/B3 + L4 的拆锁。**

### 2.4 L4 生成侧解锁与验证层（回答：哪些锁必须拆、怎么证明真拆了）

| 能力域 | 回答什么业务问题 | 缺了会怎样 | 覆盖场景 | 一期 |
|---|---|---|---|---|
| **D1 拆锁：删除硬编码文风与密度上限** | "写得克制""不得新增关键情节"是代码规定的路，还是模型选的路？ | 判定做得再准，产出的还是同一腔调——作者拿到的只是一份"诚实地说这稿不行"的报告 | S06（产出侧） | 是（P0） |
| **D2 离线回测台** | 判据、拆锁的改动，不跑模型能不能验证？ | 每次验证都要烧 token → 用户已明确拒绝"再跑一次试跑"，验证通道等于关闭 | S21 | 是（P0） |

### 3.1 三条必须写进卡里的约束（写入功能定义，不是备注）

**约束 1：事件数不由系统判合格。**
唯一硬门是作者在 S05 的勾选（四选一必填）；系统只报"疑似凑数"，**"疑似凑数"字段绝不进 F06 三档结论的映射规则**。因此 F20（事件数下限）在 P1 落地时必须被实现成"提示阈值"，任何把它变成合格门的实现视为违约。

**约束 2：病因二分，两类不许混判。**
本次 10 章主要病因**不是**"正文未落地章纲"，而是「章纲把同一班次的连续动作当成 4 个独立事件」。F04 与 F05 必须是两条独立规则、两个独立标签。验收要求同一套判定能报出两类且不混：

| 输入 | 必须报出 | 不得报出 |
|---|---|---|
| 原稿第 1 章 | 章纲密度虚高（F04） | 正文未落地章纲（F05） |

## 四、分期

### P0 —— 主题：**让系统有资格判死 + 拆掉替作者做决定的三处锁**

**功能编号**：F01、F02、F03、F03b、F04、F05、F06、F07、F08、F09、F12、F13、F14、F15、F16、F17（共 16 项）

**可形成的闭环**：离线对现有 10 章按某一版口径判定 → 逐章出缺陷单（哪句/为什么/第几段）→ 三档结论（含拒收）→ 作者四选一勾选与逐句裁定 → 一键重判 → 结论单一出口；同时三处提示词锁已解除并有会失败的反证。全程零 token、断网可跑。

**验收线（逐条可判定，禁止用"效果更好"表述）**

| 编号 | 必须成立的断言 | 会失败的反证 |
|---|---|---|
| F01 | 10 章全部产出缺陷单，每条含 `chapter`、`paragraph_index`、`sentence`、`rule_id`、`count` 五字段；缺任一字段断言失败 | 用一句普通文本做夹具，F01 必须报 0 条缺陷；把「十次呼吸之内落不了章」整句替换为普通句，该规则命中计数必须减 1（不变则断言失败） |
| F02 | 召回结果每条带原句位置；作者未裁定前，该条状态为"待裁定"，不得记为"合格" | 用作者已标定的 3 句伪具体正例跑召回，召回为 0 则断言失败（说明召回失效）；用作者已标定的 2 句正例跑，误报超过 0 条则断言失败 |
| F03 | 骨架抽取必须命中《潮汐档案》中「N 次呼吸之内落不了章」「留 N 次余量」两类骨架，并给出命中次数与位置 | 用作者认可的具体句段落跑，骨架命中必须为 0（>0 则断言失败） |
| F03b | 未勾选时该章结论字段为 `null`、状态为「待作者勾选」；勾选后记录含 `chosen`（四值之一）与 `evidence_sentence` 字段 | 构造"只跑判定不勾选"用例，若产出任何非 null 结论则断言失败 |
| F04 | 原稿第 1 章必须报「章纲密度虚高」 | 删除第 1 章章纲一条事件后重跑，若仍报「章纲密度虚高」或**同时**报出 F05，断言失败（对应约束 2） |
| F05 | 上条删事件版本必须报「正文未落地章纲」；原稿不得报此项 | 原稿若报 F05，断言失败 |
| F06 | 10 章输出仅落在「需修改／拒收」两档，**不得出现「可进精修」**（基线 0/10）；每档带触发规则 id | 把基线稿人为补足字数与句长后重判，档位必须变化；不变则断言失败（说明规则未生效） |
| F07 | 每章缺陷单条数 = F01+F02+F03+F04+F05 命中条数之和，不多不少 | 人为增/删一条命中，缺陷单条数必须同步变；不同步则断言失败 |
| F08 | 任一判据参数变化后版本号必须变；报告头必须显示版本号 | 不改参数重复跑，版本号必须不变；变了则断言失败 |
| F09 | 重判后界面不得再显示旧口径的 8/10 章 done；旧结论以历史条目保留且带旧版本号 | 用旧口径跑一次，必须显示旧口径结论并标旧版本号；不显示则断言失败 |
| F12 | 界面存在字符串「存量回测判定，非新跑拦截」；逐句裁定记录含章/段/句定位 | 移除该串后页面断言必须失败 |
| F13 | 全量跑一次，仅允许一份判定记录文件的 mtime 变化 | 若出现第二份文件被写入，断言失败（测试需枚举写入目录） |
| F14 | 断网状态下跑通；运行日志中模型调用次数为 0 | 若产生任何模型调用记录，断言失败 |
| **F15** | `prompts/stage4_writing.md` 中不存在子串「擅长克制叙事」 | 把该子串加回文件，测试**必须失败**（反证测试本身要被验证过一次） |
| **F16** | 同文件不存在子串「不得新增关键情节」 | 同上 |
| **F17** | 无范文输入时，风格指令产出为空（空串/None/空列表，三选一并固定） | 把 `style_analyzer.py:761` 的兜底串加回，测试必须失败 |
| F15–F17 附加 | 每处改动留有 diff 与「为什么删」的记录（commit message 或 `docs/` 一条说明） | 无记录则该改动的验收不通过，不因测试全绿放行（S21） |
| 效果验证 | **不在 P0 验收**。拆锁的效果（产出是否变好）明确推到 P1 的 F18 真机验证 | P0 任何对外表述不得出现"改后效果更好" |

**P0 不做什么**
1. 不跑任何模型（零 token）。
2. 不改 docx 成品文件；报告页须显示"本报告不改变现有成品文件"。
3. 不做成品失效与重出（F10）：它必然要真机重写，破零 token。
4. 不做评审与改稿分离（F11）、评审措辞去模板化（F19）、正例库（F21）。
5. 不做自动重判触发：F09 只做作者手动一键。
6. 不做"伪具体改写器／去 AI 腔改写器"（业务界定已押后：它们预设"生成的稿已够用"）。

**依赖与前置**
- 现有 10 章原稿可读（`workspace/output`，仓库 `data/` 为空是正常态）。
- 判定规则集必须先写出来并冻结一版（对应业务界定 Phase 1 拍板点 1：**判据写不出来，一期全部工作退回模型自评**）。
- 外部依赖：**0 个**（全离线、无模型、无第三方服务、无网络）。这是 P0 范围的关键优势，须在排期上守住。

### P1 —— 主题：**让结论能推动稿子真的变**

**功能编号**：F10、F11、F18、F19、F20、F21

- **验收线**：F10——重写某章后 docx 必须被标失效并给出重出走完 stage5/6/7 的证据（成品 mtime 与内容 hash 变化）；F11——三份对照能回答"模型改了我哪些字"，字符级 diff 可复现；F18——真机产出一章，按 P0 全部规则判定并与 10 章基线对比，形成一页验证单，**允许这是唯一一次烧 token 的真机验证**，且预先报价并向用户确认；F19——评审意见模板句式命中计数可为 0；F20——配置生效但不出现在任何结论字段里（约束 1 回归测试）；F21——正例库能替代无范文兜底。
- **不做什么**：不做多书/多 preset 并发；不做长篇 200 章性能优化；不做模型换代适配。
- **依赖与前置**：模型与真机跑批（需用户批准）；F10 依赖状态机增补（`成品已出` 失效路径）。

### P2 —— 主题：**写作过程中的干预与旧稿复用**

**功能编号**：F22、F23

- **验收线**：F22——中途改方向只影响下一章及以后，且带「作者干预」标记；F23——导入 docx 能定位章节，新书 schema 不被污染。
- **不做什么**：写作中干预不做成"边写边改前文"；不复活已死之单（平台文风预设、多 Agent 自主调度、500 章无人值守、云端账号/发布闭环）。
- **依赖与前置**：P1 全部结论稳定；F22 依赖流式写作能力（待研发确认）。

## 六、待决策事项（给选项与建议，不替产品负责人决定）

**D1｜F11（评审与改稿分离）到底属不属于一期？**
背景冲突：业务界定「一期做什么」第 5 条明确含此项，且 S08 标一期；但本轮用户拍板的一期交付物只写了"报告 + 拆锁"。
- 选项 A：P0 就做（只读对照视图，技术上零 token 可行，现有 10 章 raw/refined 已在盘）。
- 选项 B：移到 P1，P0 严格按"报告 + 拆锁"两条验收。
- **建议 B**。理由：P0 已 16 项，做题纪律优先；F11 不解决根因 1/4/5 中任何一条（根因 1 由 F06/F13 解决）。
- 需产品负责人确认的后果：若选 B，S08 在一期交付里**落空**，需在场景清单上把它标成 P1，不要在验收时按"一期"追。

**D2｜三档结论的档位措辞**
- 选项 A：「可进精修／需修改／拒收」（沿用用户原话"拒收"）。
- 选项 B：「可用／待改／不可用」。
- **建议 A**：与用户原话一致，不引入新词，避免"不可用 vs 拒收"两套说法在文档里漂移。

**D3｜F02「功能标准」由谁判**
- 选项 A：系统自判"这句有没有用"（快，但把主观判断伪装成客观）。
- 选项 B：系统只召回候选，作者四选一裁定（慢，但夺回验收权）。
- **建议 B**，且必须 B。选 A 等于在最后一步重犯根因 1。代价是作者每章要勾 1 次——这正是约束 1 已规定的动作，边际成本为零。

**D4｜事件数下限的默认值与归属**
- 选项 A：系统给默认值（如 ≥2 事件/章）。
- 选项 B：作者按书配置，系统不给默认，只报疑似。
- **建议 B**，且在 P1 落地（F20）。系统给默认值会立刻变成事实上的合格门，违反约束 1。

**D5｜拆锁的"效果"推迟到二期，是否接受**
- 选项 A：接受，P0 只交付"锁已解除"的确定性事实 + P1 给真机验证单。
- 选项 B：不接受，要求 P0 内就给出效果证明。
- **建议 A**，并主张：选 B 会把 P0 拉回"再跑一次试跑"，而用户已明确拒绝这条路（原话：已经跑过很多次试跑了，意义不大）。但选 A 有一个**必须由产品负责人承担的后果**：一期交付物里"稿子本身没变好"是明示的，不能在一期结束时被读成"问题已解决"。

**D6｜节奏指标（最长句 88 字、均句长 11.7–19.3）是否进结论**
- 选项 A：进三档结论映射（"无长句"直接判不合格）。
- 选项 B：只作信息展示，不进结论。
- **建议 B**：把"必须出现长句"写进结论，等于用新条文替代旧口径，是另一种写死（根因 4 的同构错误）。信息展示足够支撑作者判断。

**D7｜F23（老作品 word 导入）是否永久不做**
- 选项 A：P2 做。选项 B：移出路线图。
- **建议 A**，但只在 P1 全部验收通过后启动；否则它会变成"用旧稿绕过新判据"的通道（旧稿没有章纲，F04/F05 无法判），需明确标注"导入稿只跑 F01/F03 类正文规则"。
