## 二、文本形态实测（《潮汐档案》24,189 字）

- 均句长 11.7–19.3 字；**全书最长句 88 字，没有任何长句** → 节奏结构性单一。
- 对话标签重复：「他说」类 21 次、「木野说」10 次；系统应答「该条目不存在／条目不存在」8 次；「回执三十九」8 次。
- 全篇近乎零心理活动、零情绪词、零关系变化。
- 第 1 章全章单一事件（盖章→投井→发现一张字条）；第 2 章单一事件（核清单→差一份）。
- 典型被用户判定为垃圾的句式：「十次呼吸之内落不了章」「留三次余量」「笔尖朝上，放回笔槽」——属于**伪具体**：自造计量单位 + 动作流水账，不推进、不揭示、不产生情绪，且可无限生成（模板而非创作）。
- 用户口径原话：「这类写法属于垃圾，并不好，典型 AI 味，AI 口癖。」

## 三、六条机制根因（全部可定位到文件行）

1. **验收权在模型手里**：`prompts/stage4_writing.md:86` 要求模型在文末写 `<!-- quality: X/10 -->`；`stage4_writing.py:828` 以 `quality_threshold: 6` 收稿。质量分由被考核者自填。
2. **字数判据不是产出闸门**：`is_chapter_complete(path, 5000, 9000)`（`verify_chapter.py:274`）只在 `stage4_writing.py:835` 被用于**断点续跑筛选**，写完当时不校验。
3. **预设判据无运行时消费方**：`verify.min_chapter_words` / `must_mention` 仅被 `tests/unit/test_presets.py:106` 检查"预设文件本身格式合法"，跑完一本书之后没有任何代码核对产物。
4. **风格规格写死在默认档位里**（⚠️ 2026-10-28 修正：原记录误指 `style_analyzer.py:761/809`，它在 `if sent:` 分支内且该模块不在 stage4 主路径上）：
   真实链路 `stage4_writing.py:727 _style_blocks(proj)` → `writing_form.style_blocks(code)` → `prompts/style/{narrative,essay}_{style,para}.md`。
   **`prompts/style/narrative_style.md`（7 条，全部叙事项目必注入，用户 `style: ""` 也照给）**：
   - 用词精确、俭省，以动作、对话、具体感官细节推进情节
   - 避免形容词堆砌，不使用比喻连缀，**不渲染情绪，不铺陈氛围，让事实自己说话**
   - 视角：**严格客观叙事**
   - **不解释人物心理**，心理活动仅通过外在行为、对话潜台词或极简短的内省句暗示
   - 切断非必要注释：读者能从画面自己得出的东西，不要再写一遍
   - 禁止重复冗余
   - 节奏：过渡性内容（行走/等待/日常琐事）略写或不写，只保留对情节推进有影响的动作

   这 7 条**逐条生产**出本次文本形态：零心理活动（第 4 条）、零情绪（第 2 条）、动作流水账（第 1 条）、「十次呼吸之内落章」（第 1+2 条）。
   **这不是 bug，是一份设计好的风格规格被设成默认且不可关闭。** 拆锁对象是这份文件（默认档位改为"不注入风格规格"），不是删文件。
   另：`stage4_writing.md:15`「你是擅长克制叙事的写作者」是同一方向上的第二处。
5. **密度上限被锁死**：`stage4_writing.md:19`「严格遵循本章大纲事件推进；可补充细节，但不得新增关键情节」→ 章大纲一个事件，产出只能一个事件。
6. **评审环节销毁正文（最致命）**：`prompts/stage5_check.md:39` 要求模型输出「修正后的**全文**，无问题则复制原稿」，该文件 `max_tokens: 8000`。6000 字中文 ≈ 8000–9000 token，**装不进去**，模型只能删减。

   实测三稿字数（`chapters/raw` / `checked` / `refined`）：

   | 章 | raw（stage4） | checked（stage5 后） | refined |
   |---|---|---|---|
   | 03 | **5967** | **2186** | 2183 |
   | 05 | **6058** | **1967** | 1969 |
   | 01 | 1960 | 1961 | 1812 |

   死循环：写 6000 字 → 评审压回 2100 → 断点续跑判「不足 5000」→ 重写 → 再压。这解释了 03/05 章在 10-25 与 10-27 被反复重写。

   **既有截断防线拦不住**：`finish_reason` 是 `stop`（模型"成功"输出了更短的全文），不是 `length`。产出契约只拦「被截断」，拦不住「主动缩写」。

   后果：`refined` 建立在 `checked` 之上，**整本书被锁死在 ~2000 字/章**。

   **stage6 是同型"潜在"陷阱，但本次不是被预算削的**（2026-10-28 二次校正）：`prompts/stage6_polish.md` `max_tokens: 4000`，要求「润色后的**全文**写入」并限定「字数变化 ±20% 内、不增删实质性内容」。实测 refined 1812–2252 字**低于** 4000 token 的容量（约 2800–3000 中文字），说明本次差异来自"±20% 不增删"的指令 + **无产物侧校验**（2186→2183 为 −0.1%，1961→1812 为 −7.6%，均在允许范围内），不是预算卡住。

   但它仍是同型陷阱：**stage5 修好之后**（raw 6000 字直达 stage6），4000 token 将装不下 6000 字 → 同样会削。因此预算校验必须覆盖**所有"全文回抄"型阶段**，不能只修 stage5。

   | 阶段 | max_tokens | 要求 | 实测产出 | 是否被预算卡住 |
   |---|---|---|---|---|
   | stage4 写作 | 25000 | 全文 | 1960–2796（作者重写到 5967/6058） | 否 |
   | stage5 评审 | **8000** | 「修正后的全文」 | 1961–2266（6000 字稿被压到 2186） | **是** |
   | stage6 润色 | 4000 | 「润色后的全文」 | 1812–2252 | 否（**但修好 stage5 后会变成"是"**） |

   → 结论精确表述：**stage5 的 `max_tokens: 8000` 是本次"整本书被锁在 2000 字/章"的直接原因**；stage6 是同一把锁的第二个齿，当前被 stage5 挡住了没咬到，拆掉 stage5 就会咬上。

   **伪具体的经济学解释**：预算不足时，细节比情节便宜。写两个事件 → 每个都被压缩、显得仓促；写一个事件 + 把动作拆细 → 省 token 且"看起来有质感"。模型选了后者，于是产出「盖章→压→抬→看→推」「十次呼吸之内落章」。
   **伪具体是 token 稀缺下的最优解，不是审美偏好。不解除预算上限，改任何提示词都会退回同一腔调。**

   病因因此是**四分**：① 章纲密度虚高（同一班次拆条）② 正文未落地章纲 ③ 正文被评审压缩 ④ 正文被润色二次压缩。

## 四、用户的明确口径（不得改判）

- 服务对象：作者本人，写作者，**非程序员**（契约原话「用户永远不会用终端，包括我自己」）；同时是唯一开发者（git 身份 MUYU46548），研发与使用同一人。
- 终态（契约 REV-002）：墨坊产出**「能用级成品 word」** → 作者**直接进入逐字精修**。验收锚点：「一本书从零产 word 坯 → 作者精修一遍 → 反馈坯料行不行」。
- 负面边界：**游戏文案（散布型短文本）永不进墨坊**。
- 交付对象：**对外发布产品**（MIT，已有 NSIS 安装包）。验收线 = 「你能直接开始逐字改」。
- 对"再跑一次出厂预设"的态度：**「已经跑过很多次试跑了，意义不大。而且现在太弱上真书必炸。」**
- 已死之单（不得复活）：平台文风预设（起点/番茄风）、多 Agent 自主调度、500 章无人值守、云端账号/发布闭环。
