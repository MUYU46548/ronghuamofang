## 二、P0 需求明细（用户故事 / 验收 / 反证 / 异常）

### R01 预算—篇幅联动校验（F18b）
- **故事**：作为作者，我要在点"评审/润色"之前就知道这笔钱只够装 2000 字、而我写了 6000 字。
- **处理**：对"全文回抄型阶段"（stage5、stage6、未来同类）执行前校验 `max_tokens ≥ 目标字数 × 系数 × 安全系数`；不满足 → **拒绝执行并报"只够装 N 字，目标 M 字"**，不发起调用。
- **验收**：AC-01-1 造 `max_tokens=4000`+目标 6000 字 → 拒绝执行、报两组数字、**模型调用次数=0**。AC-01-2 系数改为实测标定值 → 同场景通过，校验记录可查标定出处。AC-01-3 系数与安全系数可配、改动留痕（旧/新/改动人/时间），不得写死常量。AC-01-4 真实配置下 stage5(8000) 对 5967/6058 字、stage6(4000) 对 2186/1967 字必须**全部判不足**。AC-01-5 拒绝时不得降级为分段回抄/先概括/只处理部分章。
- **反证**：摘掉校验 → 6000 字稿走 stage6 必复现"输出 1812–2252 字且 `finish_reason=stop`"（既有实测即反证依据；为写反证不另跑模型）。
- **异常/空状态**：目标字数未知 → 拒绝并报"目标字数未知"（不得默认 2000）；系数未标定 → 按最不利取保守值并标"未标定，结论可能偏严"。

### R02 正文销毁检测（F11 · P0 形态 = 离线三稿对照）
- **故事**：作为作者，我要知道这一章从 5967 字变成 2186 字是哪一步干的、删了哪些句子。
- **处理**：对 `raw`/`checked`/`refined` 做**逐句 diff + 字数差 + 段落差**；输出「删除句清单 / 改写句清单（原句→改句）/ 缩减率 / 疑似整章重生成」；判"正文被销毁"并出证据单。**P0 不改造 stage5/6 执行路径**（改造归 R25 真机验证后的二期）。
- **验收**：AC-02-1 03 章必须报「raw 5967 → checked 2186，缩减 63.4%，疑似整章重生成」；05 章报 6058→1967。AC-02-2 逐句 diff 必须给段号 + 原句 + 改/删标记；无段号的条目不计。AC-02-3 累计链 `raw→checked→refined` 缩减率必须单独报（03：5967→2186→2183）。AC-02-4 缩减率超阈值（**初值 5%，可配**）即判"销毁"，进缺陷单；未超则报"轻微精简"，不判销毁。AC-02-5 `raw` 指纹检测：三稿对照过程不得修改任何稿。
- **反证**：把阈值放宽到 50% → 03 章必须由"判销毁"变"不判销毁"（测试变红）；若放宽后结论不变，说明阈值没被消费。
- **异常/空状态**：缺某一版 → 标「该版不存在」，不得记 0 或"无变化"；三版全缺 → 「不可判定：无正文」。

### R03 确定性正文体检（F01）
- **故事**：作为作者，我要一眼看到每章三个版本各多少字、多少段。
- **处理**：字数/段落数/句长分布/对话标签重复/系统应答句重复/标点归一（幂等）+ **`raw↔checked↔refined` 字数差与段落差作常规检查项**（不只在评审时算一次）。
- **验收**：AC-03-1 零误差复现：均句长 11.7–19.3、最长句 88、「他说」类 21、「木野说」10、「该条目不存在」类 8、「回执三十九」8。AC-03-2 逐章三版字数+段落数+差值齐备，缺版标"该版不存在"。AC-03-3 03 章必须报「5967 → 2186 → 2183」。AC-03-4 读数只作依据，不产生档位。AC-03-5 标点归一幂等。
- **反证**：缺版记 0 → "评审删了 4000 字"会显示成"无变化"。
- **异常/空状态**：三版全缺 → 「不可判定：无正文」；仅 refined 存在 → 标"来源版本不可追溯"并阻断判定。

### R04 口径登记与版本化（F08）
- **故事**：作为作者，我要合格线只有一处、能看见版本、能回退。
- **处理**：每条判据登记 判据ID/人话名/类型（阈值·类型·计数·结构·**不可自动判定**）/阈值或定义/适用范围/版本/改动人/生效时间/**消费方标识**；版本只增不改。
- **验收**：AC-04-1 每条判据必须有消费方标识，缺失报「空判据」。AC-04-2 改阈值即产新版本，历史只读。AC-04-3 判定记录必须能反查到匹配版本，否则落「不可判定 A」。AC-04-4 **事件下限 2 必须登记为作者认定口径（不可自动判定型）**，不得登记成系统测量阈值。AC-04-5 守恒阈值、token 系数、安全系数、理由句复用上限必须登记在同一表（不得散落配置文件无人消费）。
- **反证**：任取一条判据改阈值 10 倍而 10 章结论一字不变 → 判定"登记了没人读"，判红（现状 `min_chapter_words` 即此病）。
- **异常/空状态**：登记表为空 → 全部判定「不可判定 A：缺口径」，不得回落内置默认值。

### R05 口径解释卡（F08）
- **故事**：作为作者，我要每条判据一句人话 + 一个引得上原文的例子。
- **验收**：AC-05-1 每条判据都有卡；缺卡 → 报"口径不完整"，该判据结论不得出具。AC-05-2 卡内正例/反例引文必须在原文中存在，对不上则卡作废并计数。AC-05-3 只有 1 种腔调样本 → 卡上标「窄口径」。AC-05-4 对外视图不得出现内部文件名/字段名。
- **反证**：无卡时报告与模型自评一样不可核对；引文对不上的卡让人误以为判据被证明过。
- **异常/空状态**：无正例 → 只出反例并标「无正例」，判据状态标"窄口径"，不得当已验证。

### R06 口径变更存量重判（F09）
- **故事**：作为作者，我要改口径前先知道会推翻哪些章，改完那些章自动变"待重判"。
- **验收**：AC-06-1 改前必须展示受影响章数 + 预计转不合格章数 + 不可重算判据需作者重录条数（**三者分列**）。AC-06-2 改完后"done 且口径版本落后"章数=0。AC-06-3 回退一版 → 全部受影响章标待重判 + 回退原因。AC-06-4 重判离线完成，token=0。AC-06-5 影响面算失败 → 阻断改口径（不得先改后算）。
- **反证**：10-25 口径 `[2000,3000]` → 10-26 改 `[5000,9000]`，`progress.json` 仍 8/10 done、`failed_chapters: []`。
- **异常/空状态**：受影响为 0 也必须给结论（"无存量受影响"），不得空白。

### R07 成品与源稿一致性检测（F10 · P0 形态，不做自动重出）
- **故事**：作为作者，我要成品 docx 与源稿不一致时立刻标"已过期"。
- **处理**：比对成品构建来源（章 × 版本 hash）与当前稿 hash/字数；不一致 → 标**已过期**并指出触发章；**P0 不做自动重出**。
- **验收**：AC-07-1 成品必须能显示"构建自哪一版"；不一致自动标已过期，不等人工发现。AC-07-2 真机数据：`refined/03`=2183 与 `raw/03`=5967 不一致 → 必须报「成品与源稿不一致，判定不可信」。AC-07-3 已过期后进度界面不得显示"可交付/可进精修"。AC-07-4 只提供"重出"入口（人工触发），解过期只能靠重出完成；不提供"清除过期标记"入口。
- **反证**：本次 03/05 重写后 `refined/03` 仍是旧稿、docx 冻结旧版——不检，"判定说 A、用户拿到 B"就是默认行为。
- **异常/空状态**：成品未生成 → 状态"未生成"（语义不同于"已过期"）；重出失败 → 停在"已过期"。

### R08 判定对象冻结与指纹（F13）
- **故事**：作为作者，我要知道系统判的是哪一版，评审改了稿之后还能追问。
- **验收**：AC-08-1 判定输入为只读副本 + 指纹，落盘后不可改写（只可新增版本）。AC-08-2 指纹缺失 → 判定不得开始。AC-08-3 检测到对象被写 → 该判定记录标"对象已变，结论作废"，不得驱动升级。AC-08-4 同一章多版本时，结论必须显示绑定的版本号（不得只显示章号）。
- **反证**：现状 stage5 写 `chapters/checked/`，评分对象是它自己改过的稿——指纹一变结论仍记为"该章通过"。
- **异常/空状态**：快照不可写/磁盘满 → 「不可判定：无法固化对象」。

### R09 伪具体·功能标准测量（F02）
- **故事**：作为作者，我要系统指着第几段第几句说"这句不推进、不揭示、不产生情绪、也不改关系"。
- **处理**：判细节是否服务推进/揭示/情绪/关系；四样都不占 → 标"填满"，给段号 + 原句 + 判据ID。**产出为依据，不是判决。**
- **验收**：AC-09-1 三句（「十次呼吸之内落不了章」「留三次余量」「笔尖朝上，放回笔槽」）必须全部判出并归因，各带段号+原句。AC-09-2 **不漏**：移除三句后重判仍须命中同类新句（≥1 条带位置）；零命中即退化为词表，判红。AC-09-3 任一条目缺段号或引文对不上原文 → 作废并计入作废率。AC-09-4 本项不得单独产生档位。AC-09-5 作者标"打中了"的段落不得单独构成"需重写本章"。
- **反证**：写成禁用词表 → 换腔调即失真（本次腔调是提示词+预算强加的）。反证执行：以"命中词表即报"替换实现，AC-09-2 立即红。
- **异常/空状态**：正文 <200 字 → 「不可判定 A：样本过短」；作者未录裁定 → 感受侧标"未裁定"，不得升级为"可开始逐字改"。

### R10 伪具体·可替换标准测量（F03）
- **故事**：作为作者，我要知道哪些句子是"换个词照样成立"的模板。
- **验收**：AC-10-1 「十次呼吸之内落不了章」「留三次余量」判为"自造计量单位/可无限生成"。AC-10-2 替换测试：把数字/量词换成任意同类值后仍判同类；替换后不再判出 → 说明实为词表。AC-10-3 判据本体不得是具体词列表。AC-10-4 在 R19 基准集上条目数必须为 0。AC-10-5 计数只作依据，不给"AI 腔评分"。
- **反证**：给"AI 腔评分"即回到"质量分由被考核方填"（模型自评 9 分、理由"无抒情副词"，即判据对 AI 腔的定义本身错了）。
- **异常/空状态**：基准集为空 → 不计误报率，标「无基准，不误报未验证」，不得写"已解决"。

### R11 章纲粒度过粗识别（F04 · 病因①）
- **故事**：作为作者，我要知道"这章不够"是因为章纲把一次作业拆成了四件事。
- **验收**：AC-11-1 第 1 章章纲 4 条必须报「章纲密度虚高」，并指明「分列盖章/核对回执/日志划改」为同一次连续动作拆条。AC-11-2 报"4 条全独立"→ 判红。AC-11-3 本项只作**建议**，不得据此自动判合格/不合格。AC-11-4 "同班次"必须写成可执行判断（同场景+时间连续+不改变四类状态）。
- **反证**：不识别拆条 → 把"章纲粒度太细"报成"正文合格"，矛头指错层；若据此自动判不合格，验收权从模型转给判定器（根因 1 复发）。
- **异常/空状态**：无章纲 → 「不可判定：无章纲」，不得用正文反推章纲。

### R12 正文未落地章纲识别（F05 · 病因②）
- **故事**：作为作者，我要分清"章纲写了但正文没写"和"章纲写太细"。
- **验收**：AC-12-1 人为删掉一条章纲事件的稿必须报病因②，且**不得同时**报病因①。AC-12-2 第 1 章原稿只报①，不报②。AC-12-3 两类结论在报告与数据上必须是两个独立字段。AC-12-4 六字段空值单列"字段缺项"，不混入①②。
- **反证**：混报会把矛头指错层（本次 10 章几乎全是①，混成②会去改提示词逼正文多写）。
- **异常/空状态**：无章纲 → 不可判定；章纲字段全空 → 只报"字段缺项"。

### R13 作者裁定入口（感受标准，F12）
- **故事**：作为作者，我要能对任一段说"打中了/没打中，因为……"，以便"有没有被打动"由我判。
- **验收**：AC-13-1 可对任一段录入：段号+原句+感受类型（**二值**）+**一句理由（必填）**+时间；理由为空不许落库。AC-13-2 原句对不上原文 → 作废。AC-13-3 与系统测量相反时派生冲突标记，双方依据并列；系统原值不可删改。AC-13-4 不得出现"分数/等级"字段。AC-13-5 作者可修正，旧版留档、不得物理删除。
- **反证**：让模型/规则判"是否打动人"即把不可自动判定项量化（审美五问"打动人心"给 8 分而作者判"垃圾"）；允许无理由裁定则退化成随手点击。
- **异常/空状态**：未录任何裁定 → 标"未裁定"，不得升级为"可开始逐字改"；裁定条数极少 → 标"裁定覆盖不足"。

### R14 缺陷单（F07）
- **故事**：作为作者，我要每条问题都写成"第几段、什么毛病、往哪改、原句是什么"。
- **验收**：AC-14-1 每条含段号 + 原句 + 引文校验通过 + **稿件版本号**；引不上原文即作废并计作废率。AC-14-2 "无部位结论"（用词不佳/略显平/可加强）条数=0。AC-14-3 打回"重写本章"必须带理由，理由与命中条目ID绑定可回看。AC-14-4 缺陷单不得含模型自评分作条目（只可出现在依据展示区）。AC-14-5 同一章两版本不得共用一份缺陷单。
- **反证**：允许无部位，S15 诉求原样抛回作者；允许跨版本复用，会在被压缩的稿上给出已删掉的段号。
- **异常/空状态**：全部条目引文失效 → 缺陷单为空 + 标「判定失效」，不得显示"无缺陷"。

### R15 三档结论（F06）
- **故事**：作为作者，我要一个"能不能开始改"的结论和该往哪改，而不是分数。
- **处理**：需重写本章（≥1 条章级依据：病因①且作者认定事件<2；或"整章一事件"读数）／需定点重写（有带段号缺陷且缺陷段占比≥【阈值待业务确认】）／可开始逐字改（无章级依据、段级缺陷不超阈值、作者认定事件≥2、无未消解冲突）；另设**不可判定**，原因码 A=输入/口径缺失，B=**对象链被压缩/版本不可比**。
- **验收**：AC-15-1 10 章全落三档或不可判定，无空档，理由引用具体条目ID。AC-15-2 需定点重写必须给段号集合。AC-15-3 需重写本章必须给 ≥1 条章级依据且**不得是字数**。AC-15-4 **03 章必须输出「不可判定（B）：5967 → 2186 → 2183，成品取自被两次压缩后的版本，判定不可信」**，不给档位不给分数。AC-15-5 输出无总分/quality/评分字段。AC-15-6 阈值缺失 → 「不可判定 A：阈值未定」。AC-15-7 事件数必须取 R24 勾选记录，系统测量读数不得替代（分区展示）。
- **反证**：给单一分数即回到"8/9 分无信息量"；用默认阈值兜底会让档位有结论而无依据。
- **异常/空状态**：冲突未消解 → 至少落"需定点重写"，不得落"可开始逐字改"。

### R16 判定记录单一出口（F13）
- **故事**：作为作者，我要"凭什么说这章不行"和"拿给别人看的说明"是同一份东西的两个面。
- **验收**：AC-16-1 一条记录必须齐备 **稿件版本 × 口径版本 × 判定结果** + 证据分级 + 场景口径标记。AC-16-2 对内/对外视图必须由同一记录派生，出现两份互不相干的结论即判红。AC-16-3 记录必须能列出对应的逐句修改痕（原句→改句，来自 R02）。AC-16-4 三者任一缺失 → 记录不得驱动状态升级（落不可判定 A）。AC-16-5 口径版本落后 → 标"落后"（联动 R06）。AC-16-6 对外视图不得出现内部文件名/字段名。
- **反证**：不引修改痕，S08 与 S12 各说一套（现状：评审写 checked、评分对象是自己改过的稿）。
- **异常/空状态**：修改痕缺失 → 记录标"修改痕缺失"，不得据此判"零改动"。

### R17 离线回测台（F14）
- **故事**：作为作者，我要拿现有 10 章跑一遍判定，看改前改后差在哪。
- **验收**：AC-17-1 token 消耗=0（不调模型）。AC-17-2 回测对象必须是 `raw`；用 checked/refined 回测即判红。AC-17-3 出 10 章 × 判据矩阵，每格为数值或显式"不适用（原因）"，不许空格。AC-17-4 汇总数与逐章明细必须一致。AC-17-5 不得出现"已解决 AI 腔/品质提升/效果更好"类表述。
- **反证**：用 refined 回测 = 在已经被削平的稿上验证判定能力，基线自毁。
- **异常/空状态**：缺章纲 → 病因①②标"无法对账"，其余项照跑。

### R18 存量回测声明与证据分级（F14）
- **故事**：作为作者，我要一眼看清这是回测不是拦截，哪些算能力证明、哪些只是流程演示。
- **验收**：AC-18-1 所有报告与界面必须含「存量回测判定，非新跑拦截」（可检索）。AC-18-2 证据分两区：能力证据（第 1 章 1 独立 + 3 连续动作；不漏 + 不误报双向）；demo 证据（R24 勾 1 章）。勾 1 章出现在能力区即判红。AC-18-3 demo 区必须以"流程验证，不构成能力证明"限定。AC-18-4 报告首页显示口径版本、稿件版本、判定时间、证据区归属。
- **反证**：不标注 → 下次真跑白烧（单章 stage4 实测输入 5.4–7.1 万 / 输出 2.1–2.5 万 token）；把 demo 当能力 → "跑通=能用"以更小规模重演。
- **异常/空状态**：无基准集 → 能力证据区写"不误报未验证"，不得用 demo 补位。

### R19 用户供稿基准集（F21 · P0 形态 = 导入入口 + 诚实标注）
- **故事**：作为作者，我要能导入一段我认为合格的稿当尺子，看系统会不会乱报。
- **处理**：提供**通用导入入口**；导入后跑全部判据，输出误报条目数 + 逐条明细（段号+原句）。**不预置任何正例、不内置风格样本**；误报率未标定时**必须在报告上明确写"误报率未标定"**。
- **验收**：AC-19-1 仓库内不得存在预置正例样本（示例/发布树无"满意稿"类样本）。AC-19-2 导入后必须出误报数；>0 时逐条给段号+原句。AC-19-3 导入稿不得进入发布树/示例/文档（禁私例当通例）。AC-19-4 **基准集为空或样本不足时，报告必须显示"误报率未标定"，并禁止出现"零误报/已解决"**。AC-19-5 只有 1 份基准 → 标「窄口径（1 份，腔调 1 种）」。AC-19-6 基准稿只读，判据跑它不得修改、不得回灌示例。
- **反证**：没有基准集就给不出"不误杀"的证据；内置正例违反"用户自选供稿、通用不内置"的拍板与发布树纪律。
- **异常/空状态**：导入稿 <200 字 → 拒收并说明；重复导入 → 保留版本、不重复计数。

### R20 拆锁① 去「擅长克制叙事」（F15）
- **验收**：AC-20-1 断言 `stage4_writing.md` body 不含「擅长克制叙事」。AC-20-2 替换文本不得含风格指向词（克制/内敛/冷静/留白/冷峻）。AC-20-3 反证：原字串加回 → AC-20-1 必红，留"红→撤回"证据。AC-20-4 留 diff + 根因 4 + 一句为什么。AC-20-5 不得以"生成质量提升"作验收。
- **反证**：只删字串不查替换文本 → "删了克制换成冷静"，AC-20-2 即防此。
- **异常/空状态**：改动若与文件头"body 前段逐字不变"的前缀缓存约束冲突（第 6–11 行注释）→ 改动位置与方式**待研发确认**，不得为一行破坏缓存分段。

### R21 拆锁② 放开「不得新增关键情节」（F16）
- **验收**：AC-21-1 断言不含「不得新增关键情节」。AC-21-2 新表述必须同时含"可深化章纲事件/补充使事件成立所必需的情节"与"不得偏离章纲主线"。AC-21-3 不得出现数量规定（不含"必须 N 个/至少 M 个事件"）。AC-21-4 反证：原字串加回 → AC-21-1 必红留证。AC-21-5 同文件其余行不动、不改 max_tokens/temperature、不破坏缓存分段。
- **反证**：换成"必须写出 N 个事件"是把风格锁换成数量锁——模型会报够（故禁止模型自称事件数）。
- **异常/空状态**：改动对既有章纲六字段 strict 校验的冲击 → **待研发确认**；若失败按 R23 异常路径停下报告。

### R22 拆锁③ 默认不注入任何风格规格（F17 · 对象已修正）
- **故事**：作为作者，我要系统不要在我没选风格时替我选一套。
- **对象**：`prompts/style/narrative_style.md`（叙事）与同构 `essay_style.md`（散文），经 `_style_blocks → writing_form.style_blocks(code)` 注入 `{{style_rules}}`。
- **处理**：新增**「无风格」默认档位**——默认不注入任何风格规格（渲染为空或仅剩硬性禁止）。**不删文件**：两个风格文件保留供显式选择；文体 `applicability`（哪些判据适用）与风格文案本就解耦，不受影响。用户要风格时走 R19 供稿导入。
- **验收**
  - AC-22-1 **无风格档位下**，stage4 任务文本中 `{{style_rules}}` 渲染为空或仅剩硬性禁止，**不含下列 7 条中的任何一条**（逐条断言，任一出现即红）：①「用词精确、俭省，以动作、对话、具体感官细节推进情节」②「避免形容词堆砌，不使用比喻连缀，不渲染情绪，不铺陈氛围，让事实自己说话」③「视角：严格客观叙事」④「不解释人物心理，心理活动仅通过外在行为、对话潜台词或极简短的内省句暗示」⑤「切断非必要注释：读者能从画面自己得出的东西，不要再写一遍」⑥「禁止重复冗余」⑦「节奏：过渡性内容（行走/等待/日常琐事）略写或不写，只保留对情节推进有影响的动作」。
  - AC-22-2 `narrative_style.md`/`essay_style.md` 文件保留、可被显式选择，但**默认不取**。
  - AC-22-3 显式选择叙事风格时，7 条按原样注入（证明文件未被破坏、文体分流仍可用）。
  - AC-22-4 **反证**：把默认改回 narrative 档 → AC-22-1 必须变红，留"红→撤回"证据。
  - AC-22-5 留 diff + 根因 4 + 一句为什么（这 7 条逐条生产出本次文本形态：零心理活动←④、零情绪←②、动作流水账←①、「十次呼吸之内落章」←①+②）。
  - AC-22-6 本项不得以"生成质量提升"作验收；效果验证归 R25。
- **反证**：若只是"删 7 条文件"或"改成更短的另一种风格"，文体分流断裂或换汤不换药——AC-22-2/AC-22-3 即防此。
- **异常/空状态**：无风格档位下风格块为空时，模板拼装不得留空标题造成占位符（做法**待研发确认**）；`writing_form` 取不到风格文件时不得回落到叙事档（应视为"无风格"）。

### R23 拆锁与预算同批交付守门（F15·F16·F17 联合）
- **验收**：AC-23-1 生成侧改动清单可逐条枚举且每条映射到白名单（`stage4_writing.md` body 首行、`:19`、`prompts/style/*_style.md` 默认档位）；映射不上即判红。AC-23-2 每处留 diff + 根因号（4 或 5）+ 一句理由。AC-23-3 **交付前必须已有 R01/R02 通过记录**，缺则拆锁标"未达交付条件"。AC-23-4 新增文本检索「写得更好/提升品质/已解决 AI 腔/效果提升」命中数=0。AC-23-5 变更登记"效果验证状态"本期唯一合法值="未验证"，填"已验证"即判红。AC-23-6 若必须动白名单之外 → **停下报主理人**，不得自行扩范围。
- **反证**：不守门会膨胀成"顺手改生成侧"，而判定未立、效果无处验证；预算不解除，密度与风格放开后仍退回同一腔调。
- **异常/空状态**：三处只完成两处 → B 部分标「未完成」，不得算部分完成。

### R24 作者事件勾选闸门（F03b）
- **故事**：作为作者，我要自己勾"这两条是不是能往下走的事"。
- **处理**：类别四选一必填（人物处境/信息占有/关系/目标）；证据句建议填；不填标「无举证」且**不计入下限**；**下限=2 条作者认定**；同一班次连续动作只算 1 条；系统只报"疑似凑数"，**不入三档映射**；下限是作者认定口径，与系统测量读数**分区展示**。
- **验收**：AC-24-1 类别空 → 通过按钮不可用且报"缺类别"。AC-24-2 类别有、证据句空 → 可提交，落「无举证」，计入条数少 1。AC-24-3 计入 <2 → 门不通过，提示"需要 2 条能往下走的事"并显示当前条数。AC-24-4 勾选记录含 章号/条目/类别/证据句或"无举证"/勾选人/时间；重勾以最后版本为准、旧版留档。AC-24-5 第 1 章 4 条按口径只能算 1 条 → **必须不通过**；报"4 条够"或自动合并成 2 条即判红。AC-24-6 疑似凑数提示的存在与否不得改变闸门结论。AC-24-7 报告必须把"作者认定事件数"与"系统测量读数"分两区，合并成单一数字即判红。AC-24-8 勾 1 章为 demo 证据，不得进能力证据区（联动 R18）。AC-24-9 系统不得代勾。
- **反证**：证据句强制 → 人肉成本高到他抗拒使用，退化成"随便点个类别"；类别可选 → 闸门不存在；系统判 2 条是否达成 → 验收权从模型换给判定器。
- **异常/空状态**：未勾就点下一步 → 阻断并显示"0/2"；无章纲 → "闸门不可执行"，不得视为已通过。

## 四、状态机修订（解决两处缺陷）

### 4.1 缺陷一：升级依据来自被考核方
- **升级依据只允许两个来源**：（a）**三元组闭合的判定记录**（稿件版本 × 口径版本 × 判定结果，指纹未变、口径版本=当前）；（b）**作者裁定记录**（感受标准，必带理由与位置）。
- `quality` / 七维维度分 / 审美五问分 / 模型自评文本 **一律降为"依据展示"**，不得出现在任何迁移前置条件里（RULE-1，可核查）。
- **口径版本挂在状态上**：每个状态实例携带 `judged_under_criterion_version`，≠ 当前版本 → 自动降「待重判」。

### 4.2 缺陷二：成品失效与重走
- `已成书` 是**稳定态，非终态**。规则 **ST-1**：任一章文本变更（重写/改稿/口径变更致不合格）→ 成品**立即标已过期**（R07 检测驱动），界面不得显示"可交付/可进精修"；重出由人工触发，只重跑该章 stage5→6 + 全局 stage7 合并，**不连带重跑其它章 stage4/5/6**；旧成品 archived。
- **新增两道执行条件门**（不是判定硬阻断）：stage4→5、5→6 前预算校验（R01）；`checked`/`refined` 落盘前销毁检测（R02，P0 为离线检测 + 报错，执行路径改造归 R25 之后）。

### 4.3 迁移表（要点）

| 事件 | 触发者 | 前置条件 | 数据变化 | 可回退 |
|---|---|---|---|---|
| 开写 | 作者 | 章纲已定 + **R24 门通过（≥2 条计入下限）** + 口径版本已登记 | 新版本、状态=写作中 | 是（→已废止） |
| 判定完成=达标 | 系统 | 三档落"可开始逐字改" | →合格；记录挂三元组 | 是（口径变更/作者否决） |
| 判定完成=未达标 | 系统 | 需定点重写/需重写本章 | →待人工；缺陷单可查 | 是（作者重写） |
| 不可判定 | 系统 | 缺口径/样本过短/版本链断裂 | →待人工 + 原因码 A/B | 否（补齐后重判） |
| 评审落盘 | 系统 | 销毁检测通过 + raw 指纹不变 | 新 checked 版本 + 修改痕 | 是（检测失败则不落盘） |
| 润色落盘 | 系统 | 累计缩减未超阈值 | 新 refined 版本 + 修改痕 | 是 |
| 成书 | 系统 | 全部章已润色 + 成品记录各章版本 hash | →已成书 + 成品版本号 | **是（ST-1）** |
| 口径变更/回退 | 施工位/作者 | 新版本生效 | 记录标"落后"→待重判 | 是（重判完成） |
| 重写本章（S09） | 作者 | 已评审/已润色/已成书/合格 | 新版本 + 旧版→已废止；成品标已过期；须重走 | 是（旧版可查看） |
| 废止 | 作者/系统 | 新版本接替 | 已废止（只读） | 否（终态） |

`待判定` 含三节点（Phase 1 未标注多节点，本处补充，需回 Phase 1 确认）：N1 冻结指纹 → N2 测量（R03 体检 + R09–R12 全部）→ N3 结论（三档/不可判定）。界面显示「第 N/3 节点」，不得显示百分比假进度。

## 五、规则与权限（摘要）

| 规则 | 内容 |
|---|---|
| RULE-1 | 禁止模型自评分作任何升级/降级依据 |
| RULE-2 | 预算不得静默决定篇幅：全文回抄型阶段须过预算校验，装不下即拒绝 |

## 六、异常与边界（摘要）

| 现象 | 期望 | 不得出现 |

| 输入 <200 字 | 「不可判定 A：样本过短」 | 判合格/不合格/静默跳过 |

| 基准集为空 | 标"误报率未标定" + 窄口径 | 内置预置样本/写"已解决" |
| 未勾选就下一步 | 阻断并显示"0/2" | 默认放行/自动代勾 |
| 成品已出又改章 | 立即标已过期 + 指出触发章 | 仍标可交付/静默清除标记 |
| 并发两 job 同章 | 后者拒绝或排队；只允许一条记录当版 | 两版结论并存都能升级 |
| 预算不足 | 拒绝执行、不发起调用 | 静默缩写/分段回抄 |
| 三稿缩减超阈值 | 判销毁、进缺陷单、报缩减量 | 落盘后只在报告提一句 |
| 版本链断裂 | 「不可判定 B：来源版本不可追溯」 | 用现存版本凑数 |
| 中期中断 | 已完成记录可用，未完章回待判定 | 半截记录当结论 |
| 记录删除 | 只可作废（留原因），快照按版本保留 | 物理删除致无法追溯 |
| 外部服务不可用（仅 P1 真跑） | 标「暂不可用/未跑」，不判不合格 | 把故障记成业务违规 |
| token 系数未标定 | 取保守值 + 标"未标定" | 写死 1.5 并当已标定 |
