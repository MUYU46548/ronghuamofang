# 开发路线：把"读改"接进 DSH（2026-11-17）

> 依据：暮雨当天两条判断 —— ① DSH 本来就能调模型、100% 能写，不用验；
> ② 没有插件几乎什么都做不了，跟纯 MCP 一样。
> 本文只写**接下来做什么**，每条都带一条会变红的判据。所有结论来自代码/路由表实读，不靠印象。

## 一句话

上一轮做的 `engine: dsh`（DSH 当引擎）是"跑"那半边，**停在这里不再扩**；
真正缺的是把墨坊的**读改链**变成 agent 面上一等接口，再用一个薄插件把它接进 DSH 会话。
顺序：先补接口（零 token，墨坊仓），再写插件（薄层，新仓），最后收口。

## 一、先纠正方向

| 上一轮做的 | 结论 | 理由 |
|---|---|---|
| `DshClient` + `engine: dsh` 接线 + 设置页卡片 | **保留，不扩、不修凭证** | 它解决的是"墨坊自己跑流水线时换引擎"。DSH 能不能写书不用验（暮雨已判），headless 凭据路由也不必再折腾 |
| 等"切到 dsh 跑一章"取证 | **取消** | 取证成本全在 DSH 侧，收益是"证明已知的事" |
| "没插件什么都做不了" | **成立，且不止缺插件** | 见第二节：读改链的端点在盘上都有，但**一个都没进 agent 白名单** |

## 二、今天核实的缺口（硬证据）

`MCP_TOOLS`（agent 面）与域模块路由表逐条对照，读改链这 8 个端点**存在但不可调**：

| 端点 | 路由在 | agent 白名单 | 缺了会怎样 |
|---|---|---|---|
| `POST /chapters/paragraph/preview` | 有 | **无** | 模型无法"只算不落"地改一段 |
| `POST /chapters/paragraph/apply` | 有 | 无（**当时也没闸**） | 采纳是作者动作 —— 但当时任何来源带 `confirm:true` 就能调，闸门只存在于我的口头描述里 |
| `POST /chapters/paragraph/drop` | 有 | 无 | 放弃候选要靠界面 |
| `GET /chapters/paragraph/diff` | 有 | 无 | 模型看不到自己改了什么 |
| `GET /chapters/paragraphs` | 有 | 无 | 拿不到段落编号与段落级字数 |
| `GET /chapters/annotations` | 有 | 无 | 看不到"未收口批注"清单 —— 这是改稿的入口 |
| `GET /review/structure` | 有 | 无 | 看不到六项分布指标（连排对白/段末短句/问号占比…） |
| `POST /chapters/metrics/annotate` | 有 | 无 | 没法把指标命中项写成批注 |

而 agent 面上**唯一**能改段落正文的是：

```
nf_refine_paragraph  →  POST /refine/paragraph  →  run_paragraph_refine(preview=False)
```

即**直接覆写整章**（旧稿进 `history/`），没有"先看候选"这一步。
这正是 `docs/读改链走查-20261117.md` 里的问题 B，在 agent 面上放大了：
模型只有"整章盲写"一个动作，判据（六项指标、批注、diff）全在它看不见的地方。

所以"纯 MCP 一样做不了事"的真实原因不是工具少，而是**给模型的只有刀，没有尺**。

## 三、路线

### P1 · 墨坊侧：把读改链做成一等接口（1 天，零 token）

| # | 事项 | 落点 | 判据（会红） | 状态 |
|---|---|---|---|---|
| A1 | 白名单补 7 个端点：`preview` / `pending` / `drop` / `diff` / `paragraphs` / `annotations` / `review/structure` / `metrics/annotate` | `scripts/nf_mcp.py` 的 `MCP_TOOLS` | 新用例 `test_read_modify_surface.py`：每个读改链端点必须**要么在白名单、要么在显式 GUI-only 清单里**，漏一个就红 | ✅ 落地（44 → 51 个工具） |
| A2 | **关掉绕过闸门的入口**：`nf_refine_paragraph` 改指 `preview`（只算不落） | `nf_mcp.py` + 用例 | 用例断言"agent 面上不存在无预览、直接落盘的段落改稿入口"；改回去立刻红 | ✅ 落地（用例第 3 条） |
| A2b | **采纳补闸**（A1/A2 做的时候发现的洞）：`/chapters/paragraph/apply` 此前只需 `confirm:true`，任何来源都能写正文 | `refine.py`（`_gui_only`）+ `agent_guard.FORBIDDEN_IN_AGENT_MODE` + `_AGENT_PATH_NOTES` | `e2e_paragraph_refine` 的 P8：无 GUI 双因子的采用 → 403 且正文不动 | ✅ 落地（e2e 17/17） |
| A3 | 采用候选后按原批注重算（原 P1 #5） | `refine.py::recheck_metric_annotation`（apply 回执带 `recheck`）+ `ChapterEditor.vue` 回执文案 + 内置手册 | 用例 `test_paragraph_apply_recheck.py`：不达标时**不许**自动 `resolved`（改成恒 resolved → 红）；达标自动收口；手写批注不动 | ✅ 落地（19/19） |
| A4 | 失败回执分因：截断 / 超时 / 段落数变化；开跑前做预算—篇幅校验 | `refine_paragraph.py`（`_failure_reason` + 前置校验）+ `utils/judge/budget.py::check_whole_chapter_capacity` + 卡片 `max_tokens` 4000→40000 | 用例 `test_paragraph_refine_failures.py`：长章 → 不发请求就拒且**不产生备份**；截断/超时/其它三种文案分得开 | ✅ 落地（20/20） |

**为什么 A2b 必须跟 A2 一起做**：preview 一旦对 Agent 开放，"先看后落"就只剩下"看" ——
它生成完候选、自己点掉"采用"，正文照样被写，而且没有作者的 diff 阅读。
两道闸现在各管一头：**候选可以生成**（preview 开放），**进不进书归作者**（apply 双因子）。

> ⚠️ 教训：这条闸我上一版文档里写成"GUI-only 双因子，设计如此" —— 那是把
> `/chapters/candidates/apply`（多写几版）的守卫记到了 `/chapters/paragraph/apply` 头上。
> 判据写在文档里不算数，写在用例里才算。

A2 是这一批里最值钱的一条：它把"采用"这道闸从**不存在**变成**存在且被用例钉住**。

### P2 · DSH 侧：`dsh-novelforge` 薄插件（2–3 天）—— **仓已建，0.1.0 离线版**

> 仓：`E:\CODE\CangKu\dsh-novelforge`（git 已初始化，首提交 `feat(0.1.0)`）。
> 已落地：`lib/http.js`（只连回环）、`lib/tools.js`（5 个工具，**无"采用"**）、
> `lib/prompt.js`（静态规则段 + 一行现状）、`lib/health.js` + `/mofang/health.json`、`lib/index.js`（宿主薄层）。
> 判据：离线 **30/30**（假宿主 + 假 HTTP，不需要 DSH）；对真墨坊冒烟 **2/2**
> （`nf_api --port 18765 --allow-fake`）。
> **未做**：B4 挂件、proof（会话级"先查判据再改"的比率）、真机 DSH 装一次。

照 `dsh-fangcun` 0.6.x 的骨架做，它已经把宿主事实踩平了（`AGENTS.md` 事实 1–38）。
**业务一行不搬**，插件只做四件事：

| # | 部件 | 内容 | 量 |
|---|---|---|---|
| B1 | `lib/index.js`（唯一 DSH 概念集中地） | `root.inject(['webServer'])`、`root.get('systemPrompt')`、`root.get('tools')`、`root.on('session/event')`；`webserver/index-inject` 必须在 `apply()` 最前面订阅 | 120 行 |
| B2 | `lib/prompt.js` | `systemPrompt.section`：改稿纪律 6 条 —— ①改前先查批注与六项指标 ②只改目标段、其余逐字不动 ③字数按**汉字** ④不许整章重写 ⑤preview 之后必须停手，采纳是作者在墨坊点 ⑥失败先看回执分因（截断/超时/段数变化）。**静态段，不掺动态数据**（别破提示词缓存） | 60 行 |
| B3 | `lib/tool.js` | `tools.register` 4 个：`nf_chapter_ctx`（正文+段落编号+未收口批注+六项指标一屏）、`nf_paragraph_preview`、`nf_paragraph_diff`、`nf_judge_structure`。**不做 apply**（GUI-only，工具说明里写"去墨坊点采用"）。白名单转发、输出有界、`connected:false` 时不冒充"没有批注" | 180 行 |
| B4 | `lib/widget.js` + 路由 | 一个薄浮层：当前书/章、未收口批注 N 条、最近候选的 diff 摘要、一个"打开墨坊"链接。不做编辑、不做重写界面 | 200 行 |
| B5 | `lib/health.js` + `lib/proof.js` | `tools.jsonl` 记工具调用顺序（不记参数）；比 dsh-fangcun 多一条判定：**先查判据再 preview** 的比率 | 80 行 |

`engines.dsh` 只写下限（写上界会让升级后插件静默消失，事实 26）；
`parameters` 必须交完整 JSON Schema、`output.schema` 的 required 每分支填满（事实 23b/24/37）；
打包后跑 `check-packed-schema.mjs`（拿宿主真校验器判，不自造校验器）。

## 四、验收顺序（全部零额度）

1. `test_agent_surface.py` —— 今天会红（6 个缺口），A1/A2 做完转绿。
2. `test_paragraph_apply_recheck.py` —— A3：把"恒 resolved"改回去必须红。
3. 插件离线单测（假 8765）≥60 条 + `npm pack` schema 校验。
4. 真机一次（1 块石头）：DSH 会话说"第 3 章第 7 段别那么口语"，
   看 `tools.jsonl` 顺序是否为 `annotations/structure → preview → 停`，且正文**没被改**。
   这一条同时是 L1 的退出判据：模型是靠工具走，还是自由发挥。

## 五、明确不做

- 不修 DSH headless 凭据、不真跑一章证明"DSH 能写"（已知能写）
- 不把 `apply` 开放给 agent（采纳 = 作者拍板，与审批同族）
- 不在 DSH 里重做墨坊界面（L3）、不做账本进方寸（暮雨已否）
- 不加新判据、新阶段、新面板
- 不为读改改 `prompts/stage*.md` 的前缀段（会破缓存命中）
