## 二、逐条对照

### R1 节级产物（一章写几节、每节多少字、哪一节空了）

| | |
|---|---|
| 落点 | `scripts/utils/sections.py`；stage4 `build_chapter_task`（注入 `{{sections_block}}`）与 `_finalize`（量完落盘 + 速记体判据）；`GET /chapters/sections`；界面 `console/src/ChapterMetrics.vue` |
| 数据 | 大纲写“节列表”→ `data/chapters/NN/sections.json`（逐节汉字/目标/偏移/是否达标）；阈值在 `chapter.section_min_ratio` / `chapter.section_min_hanzi` |
| 判据 | ① 任一节 < 目标 70% 或节均 < 1000 汉字 → `verdict=thin`，**该章判 invalid、不许标完成**；② 声明了节但正文没有 `### 节 N｜名` → `missing_headings`；③ 大纲没写节 → `no_sections` 且 `ok=True`（老工作区零回归） |
| 证据 | `tests/unit/test_sections_and_metrics.py` R1a–R1h（48 条，含 self 引擎与真跑同判据）；`tests/e2e/e2e_chapter_metrics_ui.py` U2（界面真的有逐节表，第二节被标"太短"） |

两种大纲写法都认（单行 `- 节 1｜名｜目标 600｜地点 门厅`、块式 `### 节 1｜名` + `- 目标字数：600`）；
节没写目标字数时按“章目标中值 ÷ 节数”补，并在报告里标 `target_source: derived`（不假装是作者写的）。

### R2 分布型文风指标

| | |
|---|---|
| 落点 | `scripts/utils/prose_metrics.py`；接口 `GET /chapters/metrics`；CLI `scripts/quality_metrics.py` |
| 四个数 | `dialogue_runs`（连续 ≥3 段以引号开头）/ `short_dialogue_ratio`（≤12 汉字的对白占比）/ `end_short_ratio`（段末句 ≤12 汉字的段落占比）/ `say_ask_per_10k`（“说/问”每万字）—— **口径照抄 OB37 的 check_rhythm.py，不重新发明** |
| 判据 | 一份"体检"里这四个数必须同时出现；只有词表命中数不算体检（`gate()` 按红线逐项判，任一项越线即 `fails` 非空） |
| 证据 | `test_sections_and_metrics.py` R2a/R2b（10 条：含"全部红线为 0 时必不过"的反证，以及"AI 腔体检报告必须带四个数"） |

红线在 `config/system.yaml` 的 `prose.thresholds`（可改）：连排对白 ≤8 处/章、短对白 <50%、段末短句 <25%、说问 <180/万字。
**这几条是 OB37 润色后的实测水位，不是普适真理** —— 紧张段落短句多是正当的，所以只报不挡流程。

### R3 指标 → 定位 → 重写闭环

| | |
|---|---|
| 落点 | `prose_metrics.locate()`（段号 + 原句 + 建议动作）→ `to_annotations()`（写进已有的段落批注库）→ 已有的 `POST /chapters/paragraph/preview {annotation_id}`（候选，正文不动） |
| 判据 | 命中项能点开、能定位到段、能生成候选；候选接受后重跑指标，数字必须变（指标是现算的，天然成立） |
| 证据 | `test_sections_and_metrics.py` R3a/R3b（命中项带段号、批注真落盘且说明里带 code）；`e2e_chapter_metrics_ui.py` U5（界面上点"把命中项变成批注"→ 23 条批注落盘） |

**为什么走批注而不是直接改**：`ai_voice` 的纪律是"只报不写回"，在已定稿阶段是对的做法；
批注把"报"接到"改"上，但改不改仍由作者点（回执 §八：金句留不留只有人知道）。

### R4 术语口径表 / 跨章数字台账

| | |
|---|---|
| 落点 | `scripts/utils/glossary.py`；`data/setting/glossary.yaml`（术语 → 取值 / 允许数字 / 首见章 / locked|draft）；`GET/POST /glossary`、`POST /glossary/check`；CLI `quality_metrics.py --glossary` |
| 判据 | ① 改一个数只改 glossary 一处（`upsert_term` 写前备份到 `data/setting/history/`）；② 全书扫描能说出"第 8 章写 47，第 10 章写 32"（`scan_book().by_term[].summary`）；③ 没有口径表 → 零 noise（不报错、不误报） |
| 证据 | `test_glossary_rounds_receipt.py` G1–G7（43 条，含中文数字解析 四十七/十二/三千一百） |

数字抽取只认术语后 16 个字符内的数字，不猜代指 —— 宁可漏报，不可误报（误报会让作者关掉这个功能）。

### R5 轮次语义（一轮 = 一张判据表）

| | |
|---|---|
| 落点 | `scripts/utils/rounds.py`；`data/state/rounds.json`；`GET/POST /rounds`、`POST /rounds/evaluate`；界面轮次下拉 |
| 出厂四轮 | 骨架（节覆盖/章字数）· 语体（碎段比/连排对白）· 扩写（节最小/章最小）· 润色（四个分布型数） |
| 判据 | 切轮次 = 切判据表；`evaluate()` 能回答"这一轮达标了吗、差在哪几项"，且未知判据键一律 400 并列出可用键 |
| 证据 | `test_glossary_rounds_receipt.py` R5a–R5c；`e2e_chapter_metrics_ui.py` U4（界面上判"还差"，逐条给实测值） |

表达式写法 `"<0.12"` / `"<=2"` / `">=15000"` / `"2000"`（无运算符 = 大于等于）。
阈值写成数据而不是代码 —— 回执 §七 的原话是"轮次即判据表"。

### R6 并行外派没有回执

| | |
|---|---|
| 落点 | `scripts/utils/agent_receipt.py`；`scripts/agent_receipt.py`（CLI `--emit/--verify/--list`）；任务书新增“回报契约”；`GET /agent/runs` 每条带 `receipt` |

### R8 时间 / 历法模型

| | |
|---|---|
| 落点 | `glossary.yaml` 的 `calendar`（`era`/`anchor`/`style`/`relative_forbidden`/`prefer_absolute`）；`glossary.check()` 的历法判据 |
| 判据 | ① 约定"只用具体日期"时，正文里的“去年/前年/明年…”被点名；② 约定“X 月 X 日”时，出现“第 N 天”被点名；③ 同一段两种写法混用被点名 |
| 证据 | `test_glossary_rounds_receipt.py` G5（相对时间 + 天数写法各一条） |

**这条只能由作者定**：OB37 的教训是"相对时间"被作者一句"不如直接改成具体日期"全量推翻（23 处返工）。
所以模型只认作者写在 `calendar.style` 里的约定，不替作者选。

## 五、如实声明（没做到的）

1. **节列表不自动生成**：一章切几节是创作决定（回执 §八 第 1 条），大纲没写节就按整章走。
2. **指标只报不挡流程**：红线越了不会拦流水线，只在体检面板与 `gate()` 里标出来 ——
   拦不拦是作者的决定（紧张段落短句多是正当的）。
3. **R6 的回执要执行方配合写**：系统只能保证"没回执不算完成"和"自报与实测不符时以实测为准"，
   不能替外部子任务生成它的体检输出。
4. **R7 的词条内容仍需模型写**：本批只补了"清单 → 三分类 → 沙盒任务书"，
   真正写词条那一步是外部模型按模板写，作者贴进库。
5. **关于"提了没做"**：本文每一条都指向可运行代码与可失败用例；
   如果哪一条只有文字没有用例，按本文开头的纪律**算未落地**，可直接打回。
