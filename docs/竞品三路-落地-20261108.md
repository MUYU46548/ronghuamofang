## 二、逐路说明

### 1 · 选中即改（书童）

书童的正文编辑器在选中文字后弹出“润色 / 扩写 / 改成对话 / 续写”。我们本来就有
“选段 + 写意见 → 只改这一段”的通道（`/refine/paragraph`），缺的是**常用意见的一键入口**。

做法：在段落批注卡里加四个按钮，点了只**把意见填进输入框**，仍要作者点“让 AI 只改这一段”
才发请求 —— 一次误点不会花掉一次调用。2026-11-08 截图目检确认四个按钮在 240px 侧栏内
一行放得下（11px 字号 + 紧内边距）。

判据：`tests/unit/test_chapter_editor.py`（文案/结构）本轮未加新断言，靠截图目检 +
既有编译/用例。

### 2 · 酒馆资料导入（催更姬）

支持两种文件、三种形状：

| 文件 | 认法 |
|---|---|
| 角色卡 `.json` | `{"spec":"chara_card_v2","data":{...}}` 或 v1 平铺字段 |
| 角色卡 `.png` | PNG 的 `tEXt` 块里 `chara`（base64 → JSON），`ccv3` 也认 |
| 世界书 `.json` | `{"entries": {...}}`（`comment/keys/content/disable`） |

纪律（都写进用例）：

- **只写 `materials/raw`**：导入是“把料放进来”，归并仍走阶段 1 与作者审批；
- **同名不覆盖**：第二次导入明确报告“同名素材卡已存在”，要覆盖必须显式 `overwrite`；
- **停用的世界书条目不导入，但点数**（静默少读比报错更糟）；
- 名字里的 `/ \ .. :` 会被替换，落点永远在目标目录内。

判据：`tests/unit/test_tavern_import.py`（23 条，含自造 PNG 夹具）。

### 3 · 裁定落盘可回放（ainovel-cli）

ainovel 的 Arbiter 把每次语义裁定落盘、可回放。我们的 `/intervene` 此前是
“用完即删、删了就没痕迹”。现在补一条**只追加**的流水
`data/state/intervene_history.jsonl`：登记一条 `set`、被取走一条 `used`，
`GET /intervene/history?limit=N` 倒序读回。

范围：**只做插话这一路**。判定引擎的作者裁定本来就有 `data/judge/records.json`
（带时间戳），不重复记；阶段 5 改稿裁定也已有独立账本。
界面入口：流水线 →“一键工作流”卡片右上“插话记录”（正在跑/有待生效指令时，
插话条上也有一个“记录”按钮）—— 不是只有接口能看。

判据：`tests/unit/test_intervene.py` I7（4 条）。

## 三、没做的（如实写）

- 书童的“审稿意见逐条勾选进修稿”“运行侧页批量取消/暂停”“拆解仿写”—— 我们已有对应件
  （stage5 改稿裁定闸、任务面板、成书提炼），本轮不重复造。
- 催更姬的“酒馆提示词预设导入”“整库备份”—— 预设体系与 `snapshot/archive` 已有；
  真要接酒馆预设，等有真实文件再动。
- ainovel 的 Engine/Arbiter/Worker 三段架构 —— 我们是单轮直连 + 外部 Agent 主路径，
  不引入多智能体循环（与“全部做完一次性出包”的排期冲突）。
