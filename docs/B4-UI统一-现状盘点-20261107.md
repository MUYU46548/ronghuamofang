# B4 · UI 统一：先盘现状，再动手（2026-11-07）

> 用户原话（试跑）：“UI 统一问题，我都懒得骂了，天天自创，一点项目记忆都没有。”
> 这张单字面要求“盘清现状 → 抽公共件 → 颜色一律主题变量”。这份文档只做**第一步**（盘现状），
> 并给出分三阶段的执行顺序。**代码这一轮没动** —— 改动面最大的一项，混在功能批次里做最容易翻车。

## 一、盘出来的事实（可复算）

统计口径：`console/src/*.vue` 与 `console/src/style.css`，只数 `#rrggbb` 形态，排除 `var(--x, #fff)` 里的兜底色。

| 项 | 数量 | 说明 |
|---|---|---|
| 组件里**未包在 var() 兜底**里的裸色值 | **30 行**（App.vue 10 / PlotGraph 7 / RoleGraph 5 / PlotBoard 4 / StylePanel 2 / JudgePanel 2） | 这是**真·自创色值**，其余都已经是主题变量或兜底 |
| `style.css` 里的裸色值 | 172 行 | 绝大多数是**主题调色板本身**（`--accent: #6b8afd` 这类），属正常，不在此列 |
| 自带 `<style scoped>` 的组件 | 35 个 | 其中样式行数最多的：ReviewConsole 309 行、ChapterBlueprint 247、StylePanel 136、JudgePanel 115、ChapterEditor 115 |
| 全局已定义的公共类 | `.mini` / `.card` / `.pill` / `.spacer` 等 | 已经在 `style.css` 全局可用 —— 组件里重复定义的多是**面板局部骨架**，不是按钮本身 |

**结论**：问题没有想象中大，但有两条真实的“自创”来源：

1. **裸色值**（30 行，集中在三个图类组件与 App.vue）—— 暗色主题下最容易“看不清”的正是这些；
2. **面板骨架各写一套**（`ReviewConsole` / `ChapterBlueprint` / `JudgePanel` / `ChapterEditor` 各自 100~300 行局部样式，`-grid` / `-head` / `-row` 命名各不同）。

## 二、三阶段（建议按这个顺序，别一次性大改）

### 阶段 1 · 色值归零（低风险，可机械验证）

- 把 30 行裸色值逐个换成主题变量；确实需要的半透明底色改写成
  `rgba(var(--accent-rgb), 0.08)` 这类**由变量派生**的写法（新增 `--accent-rgb` 一族）。
- 判据：`grep -E "#[0-9a-fA-F]{6}" console/src/*.vue | grep -v "var(--"` → **零命中**；
  再加一条用例把它钉住（现在没有任何用例守这条）。
- 反向验证：亮/暗两套主题各截 3 张图（流水线 / 章节 / 设置），人眼确认没有“暗底暗字”。

### 阶段 2 · 抽面板骨架（中风险，改的是结构）

先列清单再动手（现在只有 4 个文件占了大头）：

| 组件 | 样式行数 | 与其他面板重复的骨架 |
|---|---|---|
| `ReviewConsole.vue` | 309 | 三栏 + 卡片 + 统计条 |
| `ChapterBlueprint.vue` | 247 | 卡片 + 表格 + 徽标 |
| `StylePanel.vue` | 136 | 表单行 + 说明块 |
| `JudgePanel.vue` | 115 | 卡片 + 徽标 + 空态 |
| `ChapterEditor.vue` | 115 | 三栏 + 侧栏块 |

只抽**真正重复**的四类：`panel-card`（卡片）、`panel-row`（表单行）、`stat-strip`（统计条）、
`empty-state`（空态）。抽的时候**一次只动一个组件**，改完立刻截图对比（不要攒着一起改）。

### 阶段 3 · 栅格与间距（需要一次拍板）

现在有两套内容宽度：`.content` 1320px（所有页面）、`.content-wide` 1560px（审阅台，B7 加的）。
要不要统一成一档、还是按“读”与“填”分两档，得先定口径 —— 定了之后所有页面跟着走。

## 三、我不建议做的事

- **不建议为了统一重写现有页面布局**：用户看得见的是“颜色乱、卡片样式各写一套”，不是“栅格不对”。
  大改布局会把已经调好的审阅台/审阅流程再翻一遍，收益与风险不匹配。
- **不建议引入 UI 框架**（Element/Tailwind 之类）：本仓是一套手写 CSS + 主题变量，
  引框架等于把 60 个组件全重写一次，且打包体积、离线可用性都要重新验。

## 四、阶段 1 已完成（2026-11-07，`94cf538`）

**做了什么**

| 项 | 改前 | 改后 |
|---|---|---|
| 组件里的裸色值 | 30 行（App.vue 10 / PlotGraph 7 / RoleGraph 5 / PlotBoard 4 / StylePanel 2 / JudgePanel 2） | **0 行**（App.vue 那 10 行是主题调色板定义本身，用例显式豁免） |
| 背景柔光斑 | 每个主题手写 2 行 `background`，共 **22 行**；新增主题忘了补就沿用上一个主题的斑 | **2 行**，由 `var(--accent)` + `var(--bg)` 派生（`color-mix`），新主题自动成立 |
| style.css 其它裸色值 | 品牌紫 `#9b8fc4`、暗色顶栏 `#b9bdd4`、主按钮悬停 `#8a7db6`、错误边 `#d48ca0` 等 | 全部改成 `var(--accent/--muted/--bad)` 或 `color-mix(...)` 派生 |
| 图表色板 | 12 个色值写死在 `.attr("fill")` 里（暗色主题下白底 + 近白节点） | 新增 16 个 `--viz-*` 令牌（亮/暗各一套），组件一律 `var(--viz-*)`；D3 改 `.style()` 让浏览器跟着主题实时重算 |

**确定性验证**（不是肉眼）

- `--viz-1`：亮色 `#6b7fd7` → 暗色 `#8f9ee6`（提亮一档）
- 角色节点底色亮度：亮 **242.6**（近白，正确）→ 暗 **55.1**（深底）；原来暗色下仍是 240+ 的白斑
- 背景光斑亮度：亮 **202.9** → 暗 **74.2**
- 新守卫 `tests/unit/test_ui_tokens.py`（4 条）：组件零裸色值 / 每个 `--viz-*` 暗色必有覆盖 /
  引用的 `--viz-*` 必须真有定义 / SVG 属性里不许写死颜色

**豁免口径（写进用例注释）**：纯白 `#fff`、纯黑 `#000` 不算自创（只用在强调色填充之上的文字/徽标，两种主题都成立）；
`var(--x, #hex)` 里的兜底色允许；`style.css` 里 `--变量: #hex` 是令牌定义本身。

### 6.3 建议的抽取顺序（每次只动一个组件，改完截图对比）

1. **删组件内重复的全局类**（`.spacer` / `.mini` / `.card` / `.pill`）—— 视觉应零变化，风险最低；
2. 加**布局工具类** `.row`（flex + 居中 + gap 8）/ `.row-tight`（gap 6）/ `.row-base`（baseline + gap 10）/
   `.stack`（column + gap 4）/ `.sep-dashed`（虚线上分隔）/ `.focus-accent`（focus 描边）；
3. 逐组件替换，一个组件一次提交，并跑 `e2e_ux_verify`（含 F/G 段）确认无回归；
4. 最后再评估阶段 3（栅格两档 1320 / 1560）。

**这一轮只做完了"列清单"**：抽件本身要边改边看截图，等能稳定截图目检时再做（避免"改完不知道哪里变了"）。
