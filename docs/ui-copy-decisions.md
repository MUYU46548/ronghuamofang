# 界面文案判定与改法（task-20261104-010）

作者原话：

> 整个软件里看不懂的地方太多了，到处都不说人话，就像写出来的文章一样不说人话。

这张卡不是“润色几句”，而是要把**界面上一共说了多少句话**先摊开，再逐条判。
本文件记判定口径与改法；逐条原文在 `docs/ui-copy-audit.md`（工具生成，勿手改）。

## 一、扫了多少

```
python scripts/ui_copy_audit.py --check   # 3568 条可见文案，45 个 .vue 文件
python scripts/ui_copy_audit.py --write   # 刷新 docs/ui-copy-audit.md
```

“可见文案”只算用户真能读到的：

| 收 | 不收 |
|---|---|
| `<template>` 里的文字节点 | `//` 与 `/* */` 注释（注释是写给开发看的，术语随便用） |
| `title` / `placeholder` / `label` / `aria-label` / `alt` | 纯 CSS 类名、`v-if` 表达式 |
| `<script>` 里带中文的提示串（toast、confirm） | 纯英文标识符 |

保守抽取是刻意的：误报会逼人把**注释里的解释**删掉，那正好和这张卡的目的相反。

## 二、判定口径（三类）

| 类型 | 判据 | 例子（改前） | 处理 |
|---|---|---|---|
| ① 自造词 | 中文里没有这个词，或含义被系统改写过，读者无法从字面推出来 | 落盘 / 写盘 / 兜底 / 口径 / 台账 / 施工权 / 拼合 / 垫片 / 代拉 / 水章 | **换成人话**，不再保留旧词 |
| ② 术语 | 词本身成立，但读者不知道它指什么 | 产物 / 体检 / 判定 / 三档 / 七维 / 回测 / 上下文包 / 正典 / 断点续跑 | **当场解释**：标题或首用处加一句括号；全部收进 `help/09-terms.md` |
| ③ 假话 | 说了不存在的东西，或已经过时的状态 | “全书目标字数只能手改配置文件（界面入口还没做）”（0.8.2 已有入口）/ “绒花墨坊有服务器” | **改到与事实一致**；过时说明直接重写 |

## 四、刻意不改的（附理由）

| 词 | 为什么不改 |
|---|---|
| **流水线 / 阶段 1–7** | 全软件最核心的比喻，手册第一篇就在讲七个阶段；换成“处理流程”反而更长 |
| **审批门** | 是产品的一个真实机制（停下来的位置），手册反复解释；改为“确认点”会丢掉“必须过门才能继续”的含义 |
| **判定 / 三档 / 回测** | 是功能名。手册《判定怎么用》整篇在讲，且这里已经给“回测”补了“拿现有稿件跑一遍” |
| **精修 / 润色 / 打回 / 放行** | 中文里已有稳定含义，作者日常用语（“这段帮我精修一下”） |
| **token** | 计费单位，没有更准确的中文替换；界面在首次出现处已写“按 token 计费” |
| **MCP / HTTP / API** | 设置页那一块就是给外部工具接线用的，删掉协议名就没法配 |
| **素材归并** | 阶段 1 的正式名；手册与阶段表都用它，单改一处会不一致 |

## 五、判据与复跑

```
python scripts/ui_copy_audit.py --check     # 命中即退 1（已接进 test_help_and_judge_copy）
python scripts/ui_copy_audit.py --write     # 文案有增删后刷新清单
```

黑名单在 `scripts/ui_copy_audit.py` 的 `BANNED`。加词之前先确认：

1. 它是**开发黑话**，不是领域词（领域词归 `help/09-terms.md` 解释，不进黑名单）；
2. 全仓库能改到 0 条 —— 否则用例天天红，最后一定被人注释掉。

## 六、已知边界（如实说）

- 抽取只认**字面量**。由后端返回、前端直接渲染的错误文案不在这份清单里；
  后端错误里仍可能出现“产物”等词（下次改后端文案时一并处理）。
- 由字符串拼接出来的半句（`"已提交 " + n + " 道工序"`）会被拆成几段，
  清单里看到的是碎片，但黑名单是逐段扫的，漏不掉词。
- 本卡不含**视觉与交互**统一（字号、间距、按钮样式）—— 那是 `task-20261104-013`。
