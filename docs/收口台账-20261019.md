# 绒花墨坊 · 收口台账（2026-10-19）

> 用途：把散在各轮对话里的待办**一次性钉在文件里**。会话会忘，文件不会。
> 更新纪律：每完成一项，改状态 + 写判据；**新增项必须写"为什么"**，否则下一个人看不出它凭什么是待办。
> 后续版本规划：见 `docs/roadmap-2026Q4.md`（v0.7 审美与弧 → v1.0 可交付，含对标与不抄清单）。

## 六、本轮的收口顺序（做完一项划一项）

1. ✅ 开局方案卡（后端 + stage2 注入 + 前端抽屉 + 26 断言 + GUI 5/5）
2. ✅ P2 拆解内核（拆章 + 画像 + 不存原文，27 断言）
3. ✅ P2 few-shot 选择 + 声明弹层（候选内存态、默认 0 勾、未同意拒存；50 断言 + GUI 29/29）
4. ✅ 七维评审（JSON + 原文举证；48 断言 + GUI）
5. ✅ 上下文 memory policy（三层；28 断言）
6. ✅ 卷弧滚动规划（51 断言）
7. ✅ 设定库闭环接线（41 断言）
8. ✅ 声明弹窗改回对话框范式（2026-10-20，用户点名"不会抄自己"）—— 详见 AGENTS.md「弹窗写法」

**顺序依据**：1 是用户当场点名的缺口；2-3 是唯一"动产出"的可选能力；4 提升质量上限；
5-6 是长篇规模的前提；7 是作者体验。每条都能单独交付，不依赖后面的项。

## 附：本轮新增的确定性判据

- 开局方案：`risk` 缺失 → 失败；`finish_reason=length` → 失败；有效方案 <2 → 失败。
  三条都是"宁可不给，也不给假选项"。
