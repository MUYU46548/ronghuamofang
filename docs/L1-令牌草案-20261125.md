## 一、四条原则（后面每一条都是这四条的推论）

1. **令牌先行**：任何颜色、字号、间距、圆角、时长，先有变量名，才许写进组件。
2. **主题 = 一组令牌**（W1 你说"跟着主题色走"）。不是"挑一个强调色"，是"换一套皮肤"，
   强调色是皮肤的一部分。
3. **两套字号互不借用**：UI 字号与阅读字号分开命名，禁止混用。
   **[码]** 界面正文 14px；章节正文（编辑/阅读两态）实测 **15px**、行高 1.95、栏宽 696px
  = 46 个汉字/行 —— 这是"读起来不像书"的主因。（第一版我写"阅读区也是 14px"，实测是 15px，已订正。）
4. **可调项进设置，不写死**（W8 你的原话："很多东西不该在代码里写死，各项目都有这个毛病"）。
   第一批可调的：自动修清单、表格密度、正文行宽、动效开关、当前主题。

### 2.3 为什么强调块上一律压深字（不是审美，是算出来的）

主按钮原来是写死白字。按 WCAG 公式实测这十套：

- **白字**：2.23 – 3.47 : 1 —— 全部不达 4.5，读起来是“能看见但看不清”；
- **深字**：4.87 – 7.36 : 1 —— 全部通过。

浏览器不会因为对比度不够报错，截图也看不出坏，只有连读四十分钟才觉得累。
所以 `--on-accent` 全部给深字，并把这个数钉进门禁（第十节第 7 条）。

**代价说清楚**：浅紫/浅粉的按钮会变成“浅底深字”，不再是常见的“实心白字”。
如果哪天你想要实心白字，就得把强调色压深一档 —— 那是改色值，属于 L1-c，要重出十套截图。

## 五、圆角与阴影：各 2 档

- 圆角：`--r-sm: 8px`（控件、输入、标签）· `--r-lg: 12px`（卡片、抽屉）
- 阴影：`flat`（默认，只有 1px 边框）· `raised`（浮层、抽屉、对话框）

  这就是"看着乱但说不出哪乱"的原因。

## 八、你在 W3 问的那句：空白不是被挡住，是没栅格

你问："印象里应该有大量空位可以放文字，难道被什么东西挡住了？"

**[码]** 查了：没有被遮挡，是**布局没占**。

- `.content` 是单列流式：`max-width: 1600px; margin: 0 auto`，**页面级没有栅格**；
- 全站 28 处 `grid-template-columns`，各写各的（`1fr 1fr`、`1.25fr 1fr`、
  `200px 1fr 260px`、`repeat(auto-fit, minmax(240px,1fr))`……），互相不知道对方存在；
- **[图]** 首屏那张审批卡落在 `auto-fit minmax()` 的网格里，只占了一格，其余列空着 ——
  所以看着右边一大片白，但没有任何东西挡着它。

**L1 的做法**：页面级 12 栏栅格，卡片默认跨 12 栏（或正文 8 栏 + 右栏 4 栏）。
那一片白就变成了"卡片本该有的宽度"，而不是"留白"。

顺带一句：这也是字号问题的真相 —— 不是字太小，是**容器没宽度，字没有地方摊开**。

## 十四、2026-11-25 补记：LOGO 的 BUG 与 L1-c 第一批

### 14.1 LOGO 变成黑字（我改坏的，已修）

上一轮我把 `.brand-mark` 的 `color` 从 `#fff` 改成了 `var(--on-accent)`（理由是主按钮
对比度）。但 LOGO 不是按钮，`--on-accent` 是深色，于是“绒”变黑 —— 作者判为 BUG，正确。

修法不是改回 `#fff`，而是**把 LOGO 变成两张静态图**（作者要求：“LOGO 本身应该是一张不变的图”
“分亮色和暗色两套”）：

| 文件 | 用在哪 |
|---|---|
| `console/src/assets/logo-light.svg` | 亮色主题（`#9b8fc4` 底 + 白字，白字对比 2.95） |
| `console/src/assets/logo-dark.svg` | 暗色主题（`#6f5fa8` 底 + 白字，白字对比 5.50） |

- `.brand-mark` 用 `background: url(...)`，`.is-dark .brand-mark` 换另一张
- 两张图被 Vite 内联成 data URI（构建产物里 `data:image/svg` 出现 2 次），打包态不依赖外部文件

**为什么这次不会再有同类 BUG**：颜色烘在图里，不参与任何主题变量；
`.brand-mark` 里再没有 `color` 可以被人改坏。
**关于 ROSA 的参考**：本机 Obsidian 库（`<本机 vault 路径>`）里只找到 `98 附件/ROSA_LOGO_白底.png` 一张，
没有找到“亮/暗两套 + 站点切换”的实现（那个仓是 Obsidian 库，没有前端代码）。

## 十七、L1-c 第三批：输入控件层（2026-11-25）

作者定：侧栏当前页不用改（不与按钮选中态冲突）。于是进 Field 这一批。

### 17.1 查出来的真问题：根本没有全局基础样式

`grep` 全仓：`input` / `select` / `textarea` **没有任何一条全局基础规则**。
每个面板各写一套 —— 实测 `padding` 有 3 / 4 / 5 / 6px 四种，圆角 7 / 8 两种，
字号 13 / 14 两种。同一屏里两个输入框高低差 4px，而**没有任何判据会发现它**。

### 17.2 做法：`:where()` 基础层

```css
:where(input:not([type="checkbox"]):not([type="radio"]), select, textarea) { … }
```

关键在于 `:where()` 的**特异性是 0**：

- 面板自己的类（`.text-input`、`.prov-input`）照旧能覆盖宽度等个别项；
- 没写的地方自动继承这一套；
- 如果写成普通 `input { … }`，它会反过来压掉面板定制 —— 改一处炸三页。

同时把四个通用类里重复的几何删掉，只留布局：

| 类 | 删掉 | 保留 |
|---|---|---|
| `.text-input` | border / radius / padding / font-size / 颜色 | `flex: 1; min-width: 120px` |
| `.prov-input` | 同上 | `flex: 1; max-width: 320px` |
| `.rate-input` | 同上 | `width: 100%` |
| `.vault-path-input` | 同上 | `flex / min-width / 等宽字体` |

`.scope-input`（工具栏里的紧凑搜索框，高 22px）**故意没统一** —— 它是工具栏密度的例外，
统一到 30px 会把工具条撑高。以后要么给它单独一档密度，要么删掉，但不该混进来。

### 17.3 证据

七页实测（`Temp/pages_shot.py`，只统计可见控件）：

| 页 | 输入/下拉 | 高度分布 | 按钮 | 文字被裁 | 溢出 |
|---|---|---|---|---|---|
| 流水线 | 4 | 全 30px | 47 | 0 | 0 |
| 章节 | 12 | 全 30px | 52 | 0 | 0 |
| 素材 | 3 | 全 30px | 13 | 0 | 0 |
| 设定 | 3 | 全 30px | 16 | 0 | 0 |

| 设置 | 16 | 全 30px | 19 可见 | 0 | 0 |
| 设置（暗色） | 16 | 全 30px | — | 0 | 0 |

暗色下 `color-scheme: dark` 跟着 `is-dark` 走，原生下拉列表不会突然变白。

## 十九、L1-c 第五批：徽标（2026-11-25）

卡片阴影保留、卡片间距不动（作者定）。这一批做徽标。

### 19.1 查出来的问题

全仓徽标实际是 `.pill` 一族（模板里 45 处 `pill` + 34 处 `st-gate` + 24 处 `st-done`
+ 9 处 `st-rej` + 7 处 `st-running` …），另有 `.badge` 用于计数。两个问题：

1. **七条状态色全是硬编码 rgba**（`rgba(201,162,106,.22)` 这种）。换主题时底色纹丝不动，

### 19.2 改法

| 项 | 改前 | 改后 |
|---|---|---|
| 状态底色 | 7 条写死 rgba | `color-mix(in srgb, 主题色 14–20%, transparent)` |
| 同义项 | 各写一条 | 合并成四条语义：灰（pending/retrying/skip）、强调（running）、绿（done）、红（failed）、琥珀（gate/warn/rej/rejected） |
| `.badge` | 红底白字（对比 3.0:1）、圆角 9 | 淡红底 + `--ink-bad` 字（跟 `st-failed` 同族）、圆角 7、与 `.pill` 同字号 |

写死值就永远是亮色主题的一档浅色；`color-mix` 让十个主题各自算，暗色下自动变暗。

## 二十一、侧栏到底挡没挡：查出来的真问题（2026-11-25）

作者问：“确定左侧工具侧边栏自己没有在挡住整个界面吗？” —— 实测之后，答案是**反的**。

### 21.1 先答“没挡”

| 视口宽 | 顶栏形态 | `#app` 左内边距 | 内容左边界 | 与内容重叠 |
|---|---|---|---|---|
| 1920 | 固定竖条 216px | 216px | 268（内容居中） | **无** |
| 1440 | 同上 | 216px | 216 | **无** |
| 1024 | 同上 | 216px | 216 | **无** |
| 900 | 同上 | 216px | 216 | **无** |

机制是“让位”不是“覆盖”：`#app { padding-left: 216px }` + `.topbar { position: fixed; width: 216px }`。
四个宽度下所有直接子元素的左边界都没有伸进侧栏区（overlap 为空）。

### 21.2 但反过来有个真 bug：抽屉盖不住侧栏，也盖不住顶部 103px

`.drawer-mask` 的 `inset` 用的是 `var(--topbar-h, 103px)` —— 那是**横向顶栏**的高度。
可宽屏下顶栏已经变成左侧竖条了，于是：

1. **顶部 103px 留了一条透明带**：抽屉打开时，那一行按钮（归档这本书 / 搬进书区…）仍然亮着、仍然能点；
2. **左侧导航整条没被盖住**：`.topbar` 的 z-index 是 5，而遮罩在 `.content`（z-index 1）的层叠上下文里 ——
   数字上 20 > 5 也没用，它压不出父级。结果是抽屉开着还能换页，**换页会直接卸载抽屉，
   绕过“未保存”确认**（`tryClose` 根本没被调用）。

第 2 条是**数据风险**，不是观感问题。

### 21.3 修法

```css
@media (min-width: 900px) {
  .drawer-mask { inset: 0 0 0 216px; }        /* 不再留 103px 透明带 */
  body:has(.drawer-mask) .topbar { pointer-events: none; }
  body:has(.drawer-mask) .topbar .tabs button { opacity: 0.45; }
}
```

## 二十二、“像临时弹窗，不像改稿平台”——根因与改法（2026-11-25）

作者看完抽屉截图后的原话。这句说到了结构上，不是外观问题。

### 22.1 根因：正文的主路径是“抽屉”

章节页签原来的默认视图是**列表**，点一行的“编辑”→ 打开 `ChapterEditor`，
而它是 `embedded=false` 的形态：

| 症状 | 来源 |
|---|---|
| 底下压着一层遮罩、整页变暗 | `.drawer-mask` |

| 看不到章列表 / 批注 / 设定 | 抽屉里只有一个右栏，还是可收起的 |

换句话说：**能改稿的三栏工作台一直在**（`ChapterDesk.vue`：左章列表 / 中正文 / 右依据与七维），
但它藏在右上角一个“打开审阅台”按钮后面，默认不给。主路径反而是“列表 → 弹窗”。

### 22.2 改法（两处，都小）

1. **章节页签默认进三栏审阅台**：`chapterView` 的默认值从 `"list"` 改成 `"desk"`，
   并记住你的选择（`mofang_chapter_view`）。列表仍在右上角“回到列表”。
2. **让三栏在 1440 宽能站住**：原来 左 220 + 右 280 + 阈值 1220，
   而 1440 下审阅台只有 1134 → 右栏被自动收起，看起来只剩两栏。
   现在 左 200 / 右 250 / 栏距 12，正文 660（≈39 汉字），1440 下三栏同时可见。

### 22.3 实测

| 指标 | 改前 | 改后 |
|---|---|---|
| 章节页形态 | 列表（点行→抽屉，带遮罩） | **三栏工作台，无遮罩** |
| `.drawer-mask` | 存在 | **null** |

## 二十四、中栏的折叠手段（2026-11-25）

作者：“改的部分加上，中栏就非常挤了，有没有折叠手段来管理？”

### 24.1 先量了一下“挤”在哪

改之前中栏顶部是**四行**（章导航 / 依据栏 / 层选择与字数 / 模式按钮），
其中有两处是**意外**，不是设计：

1. **同一组模式按钮被拆到两行**：`编辑` 被 `flex-wrap` 挤到第一行末尾，
   `阅读 / 段落批注` 掉到第二行开头 —— 看着像两组不相干的东西；
2. **依据栏按钮被一行常驻提示挤下去**：那句“改完记得保存（Ctrl+S）；不保存就切章会丢”
   占满了剩余宽度，把 `依据栏` 推到第二行。

### 24.2 已做：四行 → 三行，且顺序不再漂

| 行 | 内容 |
|---|---|
| 1 | 章列表 · ← 上一章 · 第 N 章 · 下一章 → ·（右）依据栏 |
| 2 | 第 N 章 · 原稿/检查稿/润色稿 · 字数与下限 |
| 3 | **编辑 · 阅读 · 段落批注**（左）…… 纯净阅读 · 侧栏 · 保存 · 重新加载（右） |

做法：头部拆成 `.ce-head-info` / `.ce-head-acts` 两个显式行（不再靠 wrap 随机折），
`spacer` 放到模式段之后 —— 左边“在哪一态”，右边“对这一态能做什么”。
删掉那句常驻提示（它说的事 `.desk-unsaved` 拦条已经兜住）。

**实测**：中栏顶部 chrome 总高 **97px**（原来约 140），正文起始 y 从 219 提到 175；
导航行从 2 行变 1 行（30px）。

### 24.3 给“改”预留的三条折叠机制（尚未实现，按这个做）

| 机制 | 形态 | 为什么 |
|---|---|---|
| 待改清单 | 中栏**右缘一条可收起的细栏**（≈28px，竖排显示“待改 2 条”），点开滑出 260px | 它是有内容的常驻件，不该挤占正文；收起时只留一个数字 |
| 选区动作带 | **选中文字才浮出**，贴着选区下方一条（改这段 / 加批注） | 不选中就不存在，零常驻高度 |
| 派单确认 | 覆盖层（用完即走） | 一次性决策，不该占常驻位置 |

原则一句话：**常驻的只有“你在哪”和“你下一步去哪”，其余按需出现。**

## 二十五、“改一句”的两件折叠件（2026-11-25）

### 25.1 待改清单：中栏右缘的可收起细栏

- 收起 28px（竖排“待改 2”），展开 260px；
- 它是 `.ce-body` 的**真实列**，不是浮层 —— 浮层会盖住正文，而正文只有 660 宽；
- 内容就是未收口的批注（第 N 段 + 意见 + 跳到这段）；
- 底部写明“派单改写还没接”，不做假按钮。

### 25.2 互斥展开：开清单就自动收依据栏

这是“折叠管理”的核心一条。1440 下中栏 660，若清单(288)与依据栏(250)同时开，
正文只剩 **372px ≈ 22 汉字/行**，读不下去。

规则：**同一时刻只开一个侧栏**。打开待改清单 → 依据栏自动收起（并记住这个选择）；
收起清单不会自动把依据栏弹回来（否则来回抖）。

**实测**：展开清单后 `.desk-mid` 660 → **922**、依据栏隐藏、正文 **605px ≈ 35 汉字/行**。

### 25.3 选区动作带：选中才存在

在阅读态选中文字 → 贴着选区浮出一条（第 N 段 + 输入框 + 记下）。
回车即写入批注、自动展开清单。**不选中就不存在，零常驻高度。**

为什么不在阅读态常驻一个“写意见”框：读者多数时候只是读，常驻输入框会把“读”
变成“准备改”。选中了才问 —— 这是这条的全部理由。

### 25.4 还没做

**派单确认**（覆盖层：改哪些段 / 影响面 / 成本区间 / 风险）。清单底部已写明未接，
等这一件做完再一起验。

## 二十六、派单确认（2026-11-25）

### 26.1 确认页说什么（都从真实数据算，不是写死的文案）
