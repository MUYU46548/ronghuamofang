## 二、产线（依赖顺序，不砍功能）

```
L0 数据安全（贯穿每一次写入，不排队）
   · 所有项目仓库 + 墨坊工作区：可备份、可校验、可回滚

L1 素材底座（《雾港纪年》专线，预计 10+ 会话）
   · 冲突逐条裁决 → 提炼新素材集
   · 判据见第三节；不设判据，10 个会话也收不了口

L2 交互：一句话改一段（墨坊通用，可与 L1 并行）
   · 选中 → 说一句 → 候选 → 采纳 → 撤回
   · 不依赖内容，先做它，因为“愿不愿意用”决定 L1 的会话质量

L3 成品质量（书专线，**必须等 L1 完成**）
   · 在错的设定上改质量 = 白改
   · 第一条判据见第四节
```

**并行规则**：L1 与 L2 同时推；L3 等 L1。L0 永远在路上，不占阶段。

## 三、素材底座：怎么算“整理完”（Q8 落地）

1. 每条冲突留**三样**：两方版本 / 裁决 / 理由与日期；
2. 裁决后**提炼新素材**，允许改写、合并、面目全非 —— 目标是“能用”，不是“保留原文”；
3. 每个条目带**来源**（来自哪份原始素材或哪次裁决）；
4. 判据：随手指一条设定，能在 30 秒内说清“它从哪来、冲突怎么解的”；
5. 完成信号：再扫一轮 **0 条新冲突**，且这套素材足以支撑大纲。

## 四、AI 腔：判据不是词表（Q10 落地）

作者给的三条真实例子：

```
今晚不用消化这个。睡。
两条腿都已有主
包括这条在内，也是话。
```

这三句**不是俗套，是病句**：主语缺失、动词悬空、连接断裂。一眼读不懂。

所以第一条判据是：**一句话必须一遍读懂。读不懂就是缺陷，不需要解释。**

- 现有 `utils/ai_voice.py` 是**词表式**（微微一笑 / 眼中闪过一丝），抓不到这类；
- 要补的是**句法级**：短句是否成句、主语是否缺失、连接是否断裂、指代是否有对象；
- 机器只标“这句读不懂”，**不改写**；改不改由作者定。
