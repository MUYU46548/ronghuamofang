# 墨坊冻结与交接：从“产品”转“工具位”（2026-11-17）

## 2026-11-17 追加定案（作者原话推翻了上一条的取向）

> “现在就是更多是在逐章读改，而不是在等它跑。而且不用绒花墨坊不是已经跑了好几本了吗？

据此修正：

- **主界面 = 墨坊**（读改台）。DSH 退成后台引擎（`engine: dsh` / 任务书），不占主界面位。
- **墨坊存在的理由不是“跑”，是“改”**：跑已经能在别处完成且不难；难的是逐章读改、
  逐条裁定、判定与回退。产品投入应全部落在这条链上。
- 冻结范围相应**收窄**：冻“跑”的那半边（流水线界面、新阶段、配置面板、发版节奏），
  **不冻“读改”那半边**（精修 diff、段落批注、改稿裁定、判定、历史回退、风格/连续性检查）。
- 方寸仍然不进书这条线（作者：书的账本进方寸绝对不能做）。

## 一句话

**停止墨坊的产品开发，保留它的判据与出口；工作台交给 DSH，账本交给方寸。**
不设“等方寸稳定”的前置条件——方寸与 DSH 的管子今天已经通了 0.6.0，串行等待等于永久冻结。

## 为什么冻（三条事实，不是情绪）

1. **根因已判明**：墨坊 90% 的痛点是“没有 agent 层，全是单轮调用 + 外层驱动”（AGENTS.md 的能力边界一节自己写着）。
   继续在墨坊里补交互（讨论、改稿、逐条裁定）等于用界面去补架构，投入产出最差。
2. **额度与节奏**：近两轮能做的全是零 token 的验收基建（e2e 八套、291 条单测、界面 327 条），
   真正的产线验证要真跑，而现在没有额度。产品层继续加功能只会堆更多没被真跑验过的东西。
3. **工作台已经有主**：DSH 是宿主（GUI + 会话 + 工具 + 插件 + skills + headless），
   方寸是账本（任务卡 + 派单 + 回写），两边今天已经用“派单文件 → 开新会话”接上了（dsh-fangcun 0.6.0，REV-014 定案：借 DSH，不自研 agent 循环）。

## 三层分工（冻结后各归各位）

| 层 | 谁 | 具体是什么 |
|---|---|---|
| 工作台 | **DSH** | 开书会话、多轮讨论、自己读写文件、跑命令；一本书一个会话 |
| 账本 | **方寸** | 任务卡、派单（`派给 DSH`）、上下文包、收工回写 |
| 尺与出口 | **墨坊（冻结态）** | 44 个 MCP 工具 + 零 token 判据（字数/退化/文风四指标/节级/判定）+ 三层稿与备份闸 + Word 出口（15 项模板校验） |

## 冻结清单（写死，免得下次又长回去）

**停**

- 界面新功能、导航改版、新面板（含手册扩写）
- 新阶段、新判据、新提示词模板（除非为跑通现有链路必须）
- 发版节奏：0.9.4 是冻结前的最后一版，不再按版本推进

**保**

- bug 修复（尤其数据安全类：备份、失败放回、覆盖保护）
- MCP 工具面与 HTTP 端点的稳定（DSH 侧要长期调用，接口不许随手改）
- 零 token 的自检入口（`nfctl doctor/status/reconcile`、e2e 八套）

**迁移（文档口径）**

- “书怎么跑”的说明从“墨坊 GUI 怎么点”改成“**在 DSH 会话里怎么用墨坊**”
