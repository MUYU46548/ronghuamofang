### 2. 多库同名冲突扫不到（第 2 条）——已修

**根因不是比对逻辑，是扫描面**：多库合并时每个库都在用**同一套五类目录**
（`obsidian_bridge.scan_vault` 里读的是全局 `vault_dirs`，`scan_vault_multi` 直接把同一个
`skip_dirs` 传进去）。你那两个自造库目录名一旦不同，两个库都扫出 0 条 →
自然“没有同名”。这正是账本里的 P1-3，原来排在 0.10.0，现在提前做掉了。

改成**按库各存一套**：

- `scan_vault(..., dirs=...)` 接受这个库自己的五类目录；
- `vaults.json` 的每个库多一个 `dirs` 字段；**当前库**那一套仍在 `system.local.yaml`
  （与“设定目录”面板同一个真源，不搬家）；
- 新的 `POST /config/vaults/dirs {path, dirs}`：当前库写 local 配置，其余库写进 `vaults.json`；
  只收五个键，**绝对路径 / 盘符 / `..` 一律 400**（会把扫描带出库外），未知键也 400 不静默忽略；
- 界面：设置 → 风格与提示词 → 设定目录，下面多了“**其他库的目录**”，一个库一行、五个输入框、
  各自一个保存按钮。三种状态分得开：
  - 自己配过 → 直接显示；
  - **没配 → 沿用当前库那套**（徽标“沿用当前库的目录”）：老用户两个库结构相同，不能突然扫空；
  - 沿用了却一条都没扫到 → 进 `meta.suspect_inherited_vaults`，界面点名“这个库可能结构不同，单独配一下”
    ——不再出现“扫空且不报错”。

用例 `tests/unit/test_vault_dirs_per_vault.py`（34 项）：两个结构不同的临时库同时读、各自计数正确；
一库配了/一库没配；沿用与自配的区分；入参校验（绝对路径/`..`/盘符/未知键）。
另有回归：`test_vault_multi.py` 仍然全过（沿用规则保住了老行为）。

真机目检：`Temp/gui_verify/ux091/S9_vault_dirs_per_vault.png`（乙库“沿用当前库的目录”、丙库“未启用不读”）。

### 6. 跳过阶段 / 复制后面的任务（第 6 条）

- **跳过**：以前只有“失败 / 打回之后”的恢复区才有入口，正常待办阶段找不到 —— 现在是每张待办阶段卡片直接有 **跳过**。
  跳过 = 标“完成 + 已审批”，**不生成任何文件**；已写好的产物一个字节不动；确认框会先列出“这一跳会缺哪些东西”。
- **复制后面的任务**：“复制任务”只是把一段文字（项目根 + 命令 + 要产出哪些文件）复制到剪贴板，
  是**只读**操作，不代表前序阶段齐了。真跑时缺输入会失败 —— 不会因为“能复制”就跳过依赖。
- **中间产物**：跳过不删任何东西；要清掉某个阶段的下游产物用 **打回**（会先快照，再按阶段清）。

### 9. 精修大纲“跟外部 agent 连不上”（第 9 条）——已修

原状况：`engine: self` 下 `/refine/outline` 被前置拒绝，返回一句“用不了”。
你的真实用法正是“墨坊出任务书 → 外部 agent 改”，所以这个拒绝等于把路堵死。

现在 `self` 下点 **AI 精修大纲**：

1. 先把当前 `data/outline/global.md` 备份到 `data/outline/history/global_v{N}.md`；
2. 写一份**自包含**任务书 `data/state/tasks/self/stage2/refine_outline_v{N}.md`：
   你的意见 + 当前大纲全文 + 写回路径 + 硬约束（章节数不变 / 每个章节节点要有具体事件 /
   保留卷章结构 / 中文标点 / 不许动 setting 与 chapters）+ 改完怎么复核；
3. 界面回报**任务书路径**（不是一句“已提交”），并说明下一步：交给外部写 `data/outline/global.md`，
   回来点“运行”（阶段 2）复核。

其余引擎（direct / hermes）**一个字节没改**，照旧走模型精修并返回 job。
用例 `tests/unit/test_self_refine_outline.py`（22 项）：self 出任务书、备份是旧内容、

### 11. 只写 1-5 章却写了一大堆（第 11 条）

**盘上的事实**（`workspace/data/state/progress.json`）：

- 阶段 4 的任务书**只发了一份**：`data/state/tasks/self/stage4/ch01.md`；
- `task_hint` 写的是“本次只出第 1 章的任务书（待写 10 章，全书 10 章）”；
- 但 `completed_chapters` 是 `1..10` —— 十章的正文全是外面执行方一次写完的。

也就是说：**管线没有越界派活，是执行方绕过了“一章一交回”**。
你自己的试跑复盘里也写了这一点（第 28 条：“为了一次过校验，10 章并行写完再统一重跑”）。

管线能做的两件事，这次**都做了**：

- **硬约束**：任务书正文里写明“本轮只交这一章，不要替后面几章一次写完（那些章的任务书会缺上一章衔接段与滚动摘要）”；
- **越界记账**（`scripts/stage4_writing.py`）：每次派单把“派了哪几章”“派发那一刻盘上已合格哪几章”写进
  `data/state/self_dispatch.json`；下一次跑的时候做差集 —— 多出来且没派过的章会被点名，例如：
  “越界：上一份任务书只派了第 1 章，盘上却多出第 2、3、4、5、6、7、8、9、10 章。
  这些章没有拿到管线给的上一章衔接段 + 滚动摘要，建议重写，至少逐章对照检查。”
  告警同时进任务返回的 hint（界面上“本次只出第 N 章……”那条会带上它），不会只躺在日志里。
  用例：`tests/unit/test_self_dispatch.py`（21 项，含“派过的章多写一遍不算越界”这种反向判据）。

**没做的**：它只**记账不拦**。多写的章可能质量不差，不该被自动删掉；但从现在起“哪几章没被派过”
是盘上可查的事实。要“拦住”得换机制（比如执行方只能写任务书点名的文件），那是 0.10.0 之后的事。

### 18. `<!-- quality -->` 会不会污染成品（第 18 条）

**不会**。两处都剥：

- Word：`scripts/stage7_convert.py` 的 `COMMENT_RE = re.compile(r"<!--.*?-->", re.S)`；
- Markdown 导出：`scripts/stage8_markdown_export.py` 同一个正则。

### 14. 点了“编辑”没有任何提示（第 14 条）

**根因：选中态根本没样式。**

`ChapterEditor.vue` 里“编辑 / 阅读 / 段落批注”是三个切换按钮，写的是
`class="mini" :class="{ on: mode === 'edit' }"`；全仓有 20+ 个组件都这么写。
但 `style.css` 里**从来没有 `.mini.on` 规则** —— `.mini:hover` 只有一点颜色变化，
`:disabled` 有透明度，唯独“选中”这一档没画。所以你点四次，看起来和没点一样。

顺带把两件事说清，免得误会：
1. 不是“点了没生效”——模式确实切了（现在 `aria-pressed` 也能读出来），只是**看不出来**；
2. 章节列表里那个“编辑”按钮是**能打开编辑器**的（真机点过：弹窗出现，`.ce` 组件 1 个）。
   你遇到的“按钮还在”，就是上面那个模式键。

**已改**：全局加 `.mini.on`（实心强调色 + 白字 + 悬停不回退），20+ 个切换按钮一起受益；
三个模式键补 `aria-pressed`；真机目检 `Temp/gui_verify/ux091/S5_desk_edit.png`。

### 15. 批注里意义不明的横线（第 15 条）

**根因：阅读/批注视图给每个设定名画了虚线下划线。**

`.ce-name { border-bottom: 1px dashed rgba(155,143,196,.85); background: rgba(155,143,196,.14) }`
—— 一页正文里几十个名字，就是几十条紫虚线压在字下面，读起来像校样符号。

改成：**默认与正文一模一样**（不画线、不改底色），只有鼠标移上去才有一层淡底 + 细线提示可点；
可点性由光标 + 面板顶部“点文中的名字看设定卡（共 N 个可点名）”承担。

同一族还有一处：阅读模式把标题原样渲染成 **`## 第1章 验收章`** —— 读者看到的是源文件记号。

### 附：按钮级派单（2026-11-08 新增 —— 回应“这些按钮不能点还有什么意义”）

第一版把“要模型”的按钮在 self 下**禁用 + 说明**，这是治症状。你问得对：
没用。真正缺的是**按钮级的派单通道** —— 阶段 1~6 早就会出任务书，
但“点一次按钮”没有对应的任务书与回写路径。

现在补了这一层（`scripts/utils/self_actions.py`），三段式：

1. **派单**：`POST /self/action/rewrite_chapter {n, feedback?}` → 自包含任务书
   `data/state/tasks/self/actions/rewrite_chNN_<时间>.md`（含这一章现有正文全文、本章大纲、
   判据、写哪个草稿路径）；**不碰正式稿**。
2. **判完成**：`GET /self/actions` 只看 `data/self_drafts/chapter_NN.md` 在不在、合不合格：
   有标题行 / 汉字数在 `chapter.target_words` 区间内 / 无占位符 / 不是原样复制。
   不合格会逐条说原因，界面上那一行显示“草稿 N 字（未过）”。
3. **回写**：`POST /self/action/apply {n, confirm:true}` —— 先备份旧稿到
   `data/chapters/rewrite_backup/`，再把草稿换进正式稿；`POST /self/action/drop {n}` 丢掉草稿，
   正式稿一个字节不动。

界面：章节页“重写”在 self 下**不再变灰**，点了出任务书并报出路径；那一行出现
“草稿 N 字 / 采用草稿 / 放弃”。用例 `tests/unit/test_self_actions.py`（33 项，含“按意见精修必须写意见”这条反向判据）。

### 附二：改一段的对比与采纳（P1-5，2026-11-08）

原来模型改完**直接写盘**，作者只能事后去段落历史里退回 —— 改得怎样没得选。

现在两段式（有模型 / 无模型都走同一条）：

1. **预览**：`POST /chapters/paragraph/preview` → 模型改完**立刻回滚整章**，
   候选进 `data/state/para_pending.json`（改前 / 改后 / 备份位置）；
2. **并排看**：`GET /chapters/paragraph/pending` → 编辑器侧栏两栏并排（窄屏自动上下堆）；
3. **采用**：`POST /chapters/paragraph/apply {confirm:true}` → 走 `save_paragraph_text`
   （整章备份 + 段落历史 + 标点归一 + “除目标段外逐字节不变”的硬校验）；
   `POST /chapters/paragraph/drop` → 候选删掉，正文一个字节不动。

`engine: self` 下同一个界面：预览不出模型，而是出任务书
（这一段原文 + 上下两段上下文，只要改后文本）；外部写到 `data/self_drafts/para_NN_pX.md`，
点“刷新候选”就能并排看，判据（非空 / 无空行 / 与原样不同 / 篇幅 0.6~1.8 倍）过了才能采用。

用例 `tests/unit/test_para_candidate.py`（24 项），其中最硬的一条是 **C1：不点采用，正文逐字节不变**
（用假客户端模拟“模型改了整章”，断言预览后文件与预览前完全相同）。
