# D1 探针：段身份能否跨八阶段传递（2026-11-04）

> 背景：11-01 产品基线把主指标定为 BROE（单点干预半径，目标=段），同时声明 **D1（段身份能否跨八阶段传递）未确认**。
> 2026-11-04 作者拍板：先做探针（不调模型），再决定按段做还是退回章级。
> 本文件是探针的**结论与证据**；工具是 `scripts/d1_probe.py`。

---

## 一、结论

**当前不能传递。** 系统里不存在"段身份"，只有"当前文本的数组下标"：

- `paragraph_index` 是位置，不是身份。插一段、删一段、甚至改一句话导致段落重排，后面全部错位。
- 四个写作入口（stage4 分段群 / 扩写 / 增量修订 / stage5 整章回写 / stage6 整章润色）之间，没有任何一层传递段 ID。
- 因此 BROE 的"改一处只重做一段"在现状下**不可能达成**，只能退到章级（这正是基线里"目标值需实测、不承诺可达"的含义）。

**但"按段接管"并非不可行**——只是要把身份从"位置"换成"内容指纹 + 重锚"，并且用真稿标定可识别率。探针已给出方法与判据（见第三节），真值待有真稿时测。

## 三、探针怎么判（口径写死，避免各模块各自解释）

段身份 = **规范化文本的 sha256 前 16 位**；改稿后重新切段，按内容认人：

| 分类 | 判据 | 含义 |
|---|---|---|
| `matched` | 哈希相同 | 一字未改的同一段 |
| `edited` | 哈希不同，但与某个未匹配旧段相似度 ≥ 0.60 | 同一段被改过（**不能算成删+增**） |
| `inserted` | 既不同、也不像 | 真新增 |
| `removed` | 旧段没被认领 | 真删除 |

**`carry_rate = (matched + edited) / 旧段数`** —— 这就是 D1 的可行性指标。

判定线（建议，待真稿校准）：

- `≥ 0.8`：按段接管成立，BROE 一期可以按段做；
- `0.5 ~ 0.8`：只在"轻改"场景成立（逐字精修），整章重写后失效；
- `< 0.5`：退回章级，别承诺段级指标。

阈值本身就是 D1 的一部分：`--threshold` 可调，但**一旦定了要写进口径表**（和 J10 一样，不许硬编码在调用点）。

## 四、给"按段做"的最小落地路径（如果继续）

1. stage4 落盘时生成 sidecar：`data/chapters/paragraphs/NN.json`，记 `[{id, hash, start, end}]`。
2. stage5 / stage6 改写后**不重建 ID**，而是用 `d1_probe.compare()` 做重锚（matched/edited 继承 ID，inserted 发新 ID）。
3. 段落精修接口从 `paragraph_index` 改成 `paragraph_id`（保留 index 兼容旧前端）。
4. 判定/缺陷单也按 `paragraph_id` 定位，跨版本可追溯"这句话上次被谁改过"。
5. 代价：约 2–3 天，不调模型；风险是大幅重写后 carry_rate 低，需要有降级路径（整章重来）。
