# 写作账本：这一章的改动，谁在什么时候改的

> 代码：`scripts/utils/write_log.py`（追加）· `GET /chapters/write_log`（读）·
> 界面：审阅台侧栏“这一章的改动”· 判据：`tests/unit/test_write_log.py` + `e2e_ux_verify.py` **O 段**

---

## 一、为什么要有它（P2-2“一任务一工作区”的诚实落地）

竞品台账里 P2-2 抄的是 Papilot 的“一任务一个 git worktree”。在绒花墨坊这条**不适用**：
正文在 `data/chapters/`，`data/` 不进 Git，没有分支可以开。但“一任务一个可追溯单元”
这件事本身是需要的 —— 审稿时最常问的一句是：

> 这一段怎么变成这样了？

答案原来散在三处：段落历史记**内容**、候选区记**待采用**、快照记**整章**。三处都对，
但没有一份**按章、按段、按时间**的流水。于是同一个问题每轮都靠翻文件回答。

## 二、做法

- **唯一写盘点插桩**：`refine_paragraph.save_paragraph_text` 是段落级唯一的落盘函数
  （手改 / 采用候选 / 回退都从这里过），在它写盘成功后追加一条 —— 一处插桩覆盖全部段落级改动。
- **不存正文**：只记 `at / chapter / paragraph / kind / note / before_chars / after_chars`。
  正文真源只有 `data/chapters/` 一份，账本再存一份就变成两份真源（迟早对不上）。
- **落 `data/state/write_log.jsonl`**（本机、不进 Git），JSONL 追加；超 `MAX_ENTRIES=2000`
  重写成最新那批（它是线索，不是归档）。
- **记账失败不挡写正文**：`record()` 吞掉 OSError；坏行读取时跳过、不连坐整份账本。
- **内容没变不记**：`save_paragraph_text` 在“内容没变，未写入”那条分支里提前返回，
  所以不会产生一堆“改了 0 字”的噪声。

## 三、界面

审阅台侧栏底部“这一章的改动（N）”：每条固定两行 —— 第一行“时间 + 来源”
（手改 / AI 段落改写（采用）/ 回退），第二行“第 N 段 + 字数变化”。

为什么放侧栏而不是正文顶上：它是**查**的地方，不是**配**的地方；但要能一眼看到条数
（标题带徽标），点“刷新”按盘上重读。审阅台里侧栏默认收起，切到“段落批注”会自动展开。

## 四、边界（如实声明）

- 只覆盖**段落级**与**整章保存**（`/chapters/save` 之后前端会重读列表，但整章保存本身
  还没插桩；章级记录目前只在“段落怎么写进去”的粒度上可见）。要把整章保存也记进去，
  得在 `nf_api_domains/chapters` 的写入口加一行 —— 列在这里，别当成已完成。
- **不做**“一任务一工作区”的隔离层（锁 / worktree 等价物）。判断依据：
  ① `RunLock` 已经保证同一时刻只有一个流水线 run；
  ② 副产品一律先落候选区（`checked_pending` / 段候选 / `_pending`），作者点头才进正式路径；
  ③ 段落级“候选出来之后这段变过”已有冲突闸（`paragraph_conflict`，Papilot ⑧）。
  再加一层跨进程锁，收益接近零，代价是多一个新的卡死点（锁没释放 → 作者改不了自己的稿）。
