用户 2026-11-05 三连批的原话：“根据你的截图没有任何问题被解决，界面反而更丑更难用了”、
“你真的懂前端吗”。两次都栽在同一件事 —— **只验证 DOM 里有类名，没验证人眼能不能看出来**。

## 硬规矩

1. 改完 `vite build` → 起 809x / 879x 冷端口 + `tests/e2e/mock_nf_api_state.py` →
   Playwright 截图 → `vision_analyze` 目检。**8091 被占就换端口，不抢端口、不杀别人的进程。**
2. 浏览器里没有 Electron 的 `window.mofangAPI`：用 `page.add_init_script` 注入最小
   `readPreview`（`config/project.yaml` 给 `chapters: N`，`data/chapters/*/NN.md` 给夹具正文），
   再用 `page.route` 覆盖审阅台依赖的端点。
3. 参考稿：与本仓库**同级**的 `SP-1026`（写作工作台 v0，纯前端原型）。照它的**结构**抄 ——
   三栏 `240 / 1fr / 280`、13px 字号、6–8px 圆角、白底 1px 边、状态三色点、信息密度克制。
   **不要自己发明配色或加装饰**（顶栏那次加灰底块 + 组前竖线，用户判“更丑”）。

## 三个已踩过的坑

| 坑 | 现象 | 正解 |
|---|---|---|
| **四列卡片** | 审阅台（三栏）内联 `ChapterEditor` 时，编辑器自带 `.ce-side` 又占 240px，与审阅台右栏并排成两列卡片 —— 用户看到“一堆重叠的卡片” | 内联时侧栏只在 `mode === 'paras'`（段落批注）出现；编辑模式正文吃满宽度 |
| **组名被当页签** | 给 `.tab-group` 加“写作/审校/系统”小字，读起来像多出三个页签 | 分组语义放 `aria-label`，界面上靠底色/间距表达，不新增文字 |
| **切章丢稿** | 改到一半点“下一章”直接换章，改动无声消失（顶部只有一行灰字） | `ChapterEditor` `defineExpose({ dirty, save })`；父组件切章前拦：保存并切换 / 丢弃并切换（标红）/ 留在这章 |

## 导航结构（2026-11-05 第二次返工）

用户原话：“顶部依然一大堆按钮，不好找也不好看。”——第一次我只调分组样式（灰底块 + 竖线），
被判“更丑”；第二次才动结构：**导航整体搬到左侧**。

- 左侧 216px 固定导航：三组带组标题（写作 / 审校 / 系统），竖排页签，底部工具栏
  （已连接 / 刷新 / 补救 / 日志），当前项紫色高亮。
- 顶部只留情境状态条（下一步 / 审批门 + 执行）。
- `#app { padding-left: 216px }`；`--topbar-h` 在 ≥900px 时归零 —— 侧栏是 fixed，
  它的“高度”等于整屏，写进 `--topbar-h` 会把内容顶下去一整屏。
- 组标题必须比页签**弱**（10.5px / 淡灰 / 加字距）；同字号同颜色会被读成“多了三个页签”。
- 书名用副标题样式（小一号灰字），不要做成按钮样 —— 否则像导航第一项。
- 窄屏（<900px）回退顶部横排，行为不变。

判断标准：**页签数量超过 8 个就不要横排**。竖排侧栏 + 组标题是唯一能让“17 项”看起来不乱的
结构；继续在横排里做分组样式，只是把乱的东西装饰一遍。
