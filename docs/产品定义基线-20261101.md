## 零、先看这一页

### 一句话诊断

**AI 能把字写出来，但作者接不住；接不住的那部分只能整章重来，而重来比自写还贵。**

所以「不可用」不是质量问题，是**接管路径不存在**——`T_接管 = ∞`。你已把"AI 写得差"设为常量并自愿接受（"全世界AI写的我都读不下去""已经把垃圾提升几千倍"），**质量因此不进可用性判定**。

### 主指标：单点干预半径（BROE）

**你改一处时，系统被迫连带重做的最小单位**——段 / 章 / 全书。
当前基线 = **整章**（最坏退化为全书）；目标 = 段（**目标值本身需实测，本团不承诺可达**）。

选它是因为它与"AI 写得好不好"完全正交：AI 再烂，半径是段，你敢逐段改；AI 再好，半径是章，你改一个字就得重赌一次。

### 评审给的两个一票否决（已修）

| 否决 | 原缺陷 | 处置 |
|---|---|---|
| A · 状态机矛盾 | 残稿可经「就这样接受」合法进入成品（`T08` 把 C2 列进字数门源状态集 → T14 → C6 可导出），R03 的全部意义归零 | 已改：T08/T09 源状态集删除 C2；§2.4 增补禁止转移 **Z1**（残稿只能经「人就地编辑」离开 C2） |
| B · 验收不可满足 | R04 判据①「暂停后 30 秒内 cost_log 无新增行」物理上不可能——已发出的调用返回必然记账 | 已改：判据改为「**暂停后新增请求数 = 0**」，原条降级为观察项 |

### 评审的一句话（最该看的一句）

> **"段是重算最小单位"这条在一期没有触发点：手改不产生重算，AI 段级重算被推到后续，所以一期只能证明"系统没有多做"，证明不了"系统能少做"。**

他还指出：**你每跑一轮流水线，标过的段会全部失效**，而跑流水线是你的常规动作。这是本方案最可能失败的地方（对应 §六 S-2 / S-5）。

## 一、业务界定

| 项 | 内容 |
|---|---|
| **服务对象** | 唯一作者，同时是唯一开发者；**永不用终端**，只有 GUI；不读日志、不读代码 |
| **不能做什么** | 不能承担"改一处 = 整章重来"的代价；不能同时维护四个写入入口的心智；不能用命令行验证 |
| **业务问题** | 见 §零 一句话诊断 |
| **「不可用」定义** | `T_接管 ≥ T_自写`；接管路径不存在时 = ∞。三条并行必要条件：C1 接管可发生（有"某一处"的入口）／C2 接管是局部的／C3 产物可信 |
| **业务价值** | 主指标 BROE（段/章/全书），基线整章 → 目标段（需实测）。辅助护栏：干预入口覆盖率、中止损失、判定一致率、下压可见性、产物新鲜度可见性、并发写安全 |
| **不做** | 文本质量提升（换模型/调提示词/加评分）、多人协作、账号与云同步、发布分发、**生成中共写**（与"就是快"冲突）、**引擎选型**（你的决定） |
| **一期不做** | 不重写八阶段结构、不新建第九阶段、不做评分体系（反而要**收缩**评分在状态判定中的权重）、不做存量数据追溯修复、**不以数据层重构为起点** |

## 三、产品定义

### 3.1 六层能力（串联，不是并列模块）

| 层 | 回答什么问题 | 缺了会怎样 |
|---|---|---|
| **L0 边界** | 允许多大范围、什么时候必须停 | 一跑就跑到整本，没有收手的落点 |
| **L1 定位** | 我要改的是哪一处 | 只能整章重来（C1 不成立） |
| **L2 就地** | 我能不能自己动手，而不是再许愿一次 | 只能"提交 job 等 diff"（C1 不完成） |
| **L3 局部** | 我改了这一处，系统还被迫重做多少 | **BROE 唯一承载**（C2） |
| **L4 可信** | 我看到的就是最终会印出来的吗 | C3 不成立，L3 的收益被复核成本吃掉 |
| **L5 秩序** | 我这一下会不会和别处正在做的打架 | 前五层成果被静默归零 |

### 3.2 BROE 的架构落点：可指名段

一段能被**单独指名、单独替换、单独核对**、且增删后仍指向自己的文字。四个属性：身份 / 边界 / 来源 / 独立生命周期。

**一期只动一半**：先立死约束「**任何重算请求的最小触发单元必须是段，不得是章**」，不做全书唯一身份、不做存量迁移、跨章能力到章为止。

**评审对这条的评价（要看）**：两个属性各有一半是实现细节（"过了哪几道工序"是流水线内部概念；"被重算"一期无路径）；且"章内位置 + 内容指纹"是研发决策，却已经决定了 R13 判据的写法——**建议标「待研发确认」**。

### 3.3 一期范围

评审判定：**`02` 的一期清单（21 功能）与它自己的通过判据（7 功能）不一致，属范围失控。** 建议按 7 功能 + 字数门 + 一个开关收缩（约 11 项），并承认 11 个场景不覆盖。

→ **这一项要你拍板**（§七 P1）。

## 四、需求规格

**36 条需求（R01–R36）**，一期 30 条。每条含：场景/能力层、需求描述、验收判据、**反证**（判据放宽就该变红）。

### 4.1 章节状态机（9 状态）

`C0 未开始` / `C1 生成中` / `C2 已中断·残稿` / `C3 待选版` / `C4 不达标·待处置` / `C5 达标·待署名` / `C6 不达标·已接受` / `C7 已确认可用` / `C8 疑似损坏`

**26 条转移 + 9 条禁止转移 + 8 条硬规则。** 其中两条是地基：

- **H1**：字数 < 下限 → 不得进入 `C5`/`C7`（"已确认可用"类）
- **H2**：模型自评分**不得单独决定**任何转移

**现状矛盾已逐条定到新模型落点**：2000 字判 ok → 应落 `C4`；停止丢整章 → 应落 `C2`；7184→2474 静默 → 应被字数门判 `C4`；成品悄悄过期 → 成品单列为附属对象（不计入章状态）。

### 4.2 权限与 actor

6 种 actor（人 / HTTP / MCP 外部 Agent / CLI / pipeline / system）。**5 项动作人专属**（含"确认可用""接受不达标"），Agent 禁止且必须给人话拒绝。
**并发裁决 = 后到者拒绝、不排队、给人一个"叫停对方"的动作。**

### 4.3 两条可绕过的路径（评审点名）

1. **产品自己开的合法出路**：10 次「就这样接受」→ 10 章全 `C6` → 全可导出。硬规则字面没破，业务结果回到现状。**不是漏洞，是设计，但验收必须分开记 `C5/C7` 章数与 `C6` 章数**，否则"他全接受了"和"他全改好了"无法区分。
2. **残稿**（否决 A）—— 已修。

## 五、交互定义

- **端型**：一端（Windows 桌面）。明确排除手机 / 浏览器远程 / CLI 作为用户端。**组织方式结论 = 部分改**（附全改与不改各自的反证）。
- **落点 A1–A18**：**不新增顶层页签**；处置"相邻不相连"的原则是**动作在「章节」，工具在原页签，不搬家**。
- **任务流 T1–T10**：每条三段式（步骤 / 可见反馈 / 失败分支），挂 S 编号；一期不可达的步骤标 `〔一期不可达〕`，**界面必须如实说出它不在这里**。
- **九状态界面表**：每个状态给显示 / 允许 / 禁止 / 空态加载态；另补 7 个特殊场景（空工作区、进程已死、并发被拒、产物过期、残稿、疑似损坏、**文件能读但段标记对不上**）。
- **文案**：27 条黑话→人话；**必须改掉的误导文案 14 条**（评审核出实际约 37 处）。
- **同一结论一个来源**：4 条总规则 + 当前会打架的 10 处 + 5 条零 token 一致性验收。

### 必须改掉的那句（交互设计师给的真话版本）

> **改前**：已暂停输出，可修改提示词后点恢复
> **改后**：已暂停（14:32）· 不再发起新的写作请求 · 上一次请求发出于 14:31，可能仍在进行并计费 · **暂停期间仍不能改稿**（本轮占着第 11 章的写权）；要改稿请点「停止并保稿」

它还补了一条更狠的：**暂停不释放写权，所以"暂停后可改稿"也是假的**——现有提示语是三重撒谎（模型照跑计费 / 那次 prompt 已发出 / 写权仍被占）。此点为**推论非实测**，已在文中标注。

现行 `chapter.target_words = [5000, 9000]` 是按"含标点"定的。改成只计汉字后，同一篇稿子的数字下降约 19.6%，**5000 汉字 ≈ 原口径 6200 字**，门槛实质变严。
