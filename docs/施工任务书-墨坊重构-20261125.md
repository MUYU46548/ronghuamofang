## 1. P0-1 · 章是原子单位

**目标**：`engine: dsh` 下默认整章单发；加强模式降级为"字数不足时的补救"。

**改哪里**

| 文件 | 改动 |
|---|---|
| `config/system.yaml` | `chapter.enhanced_mode` 出厂默认改 `false`；注释里写明"dsh 下默认整章单发，不足字数才降级" |
| `scripts/stage4_writing.py` | 拆群入口加判据：只有 `enhanced_mode == true` **或**“本次是字数不足的重试”才走段群；两条都不满足走整章单发 |
| `scripts/stage4_group.py` | 不改逻辑，加一句注释说明它现在是"降级路径" |

**判据**

```
单章端到端 ≤ 5 分钟（实测，不是估算）
单章 token/字 ≤ 8（cost_log: (tokens_in+tokens_out) / 汉字数）
6 章全书 ≤ 40 分钟
```

**自测方式**

- 用 `NF_API_ALLOW_FAKE=1` + fake_client 跑一个 3 章夹具，断言"调用次数 == 章数"（每章一次，不拆群）。
- 真机验证留作者：跑 1 章，看 `cost_log` 的 tokens_out 与汉字数之比。

**回退**：`chapter.enhanced_mode` 改回 `true` 即恢复旧行为（不需要回滚代码）。

## 4. P1-3 · 整卷会话 + 跨会话接力

**目标**：一卷一个 `session_id`；每章一次 `dsh --profile headless --session-id <id>`；水位 60% 换会话。

**改哪里**

| 文件 | 改动 |
|---|---|
| `scripts/utils/dsh_client.py` | 构造命令时支持 `session_id` → 追加 `--session-id <id>`；`run_task` 返回值带 `session_id`（若 dsh 的 NDJSON 事件里能读到，读不到就回传传入值） |
| `scripts/nf_api.py` + `nf_api_domains/chapters.py` | 新增 `POST /chapter/write {n, session_id?}`：写一章 = 一次 dsh 调用；返回 `{ok, words, tokens, session_id}` |
| `scripts/nf_api.py` | 新增 `POST /session/rotate {volume}`：生成本卷接力包、开新 session_id |
| `scripts/state`（progress） | `progress.json` 增 `sessions: {volume: {id, last_chapter, tokens_accum}}`；增 `volume` 与 `last_chapter` |
| `scripts/utils/canon.py`（新建） | 决策文件读写：`append_decisions(chapter, entries)` / `read_decisions()` |
| `console/src/App.vue` | 阶段 4 卡片显示“本卷会话 · 第 N 章 · 累计 X 万 token”；“换个会话”按钮 |

**水位 60% 的口径（作者拍板 A）**

```
分母 = 自设上限，初值 250,000 token
分子 = 本会话累计输入 token（每章实测 tokens_in 相加）
触发 = 分子 ≥ 0.6 × 分母
校准 = 换会话时若分母 < 180,000 判"换早了"、> 300,000 判"换晚了"，±10% 调参并记文档
```

**接力包四件（缺一不可）**

1. `data/canon/decisions.md`
2. 最近 3 章原文（`raw/NN-2..NN.md`）
3. 进度：写到第 N 章、本卷目标章数
4. 未回收伏笔清单（从 `decisions.md` 的 `[未回收]` 段取）

**换会话后的第一条任务书必须要求**：先复述"现在到哪、谁在做什么、下章接什么"，再写正文。不复述 = 判失败。

**暂停（作者拍板 B：随时）**

- 半章残稿落 `data/chapters/raw/.partial/第N章.md`
- 续写时把残稿给 agent，要求"接着写，不要重写已有部分"
- 字数统计把残稿计入本章

**判据**

```
换会话按 60% 触发（偏差 ≤ 10 个百分点）
换会话后首章字数 ≥ 前一章 80%
暂停 24 小时后再续，能接上（不重读全书：输入 ≤ 3 万 token）
半章残稿存在且能被续写
```

**风险**：`--session-id` 只接受已存在的会话；未知 id 报错。所以墨坊要**先建后传**（第一次不带 id，从 NDJSON 事件里拿 id 并落盘）。

**回退**：不传 `session_id` 即回到"每章新会话"。

### P0-1 施工记录（与计划不一致的地方，按实际改了）

1. **根因不在“出厂默认”**：`config/system.yaml` 一直是 `enhanced_mode: false`。
   真正把用户工作区写成 `true` 的是 `seedWorkspace()` 里的 **`ensureEnhancedMode`** ——
   2026-10-26 它给“缺这个键的老工作区”自动补了一条 `enhanced_mode: true`
   （当时为了治弱模型写不长）。用户那本 `%APPDATA%\绒花墨坊\workspace` 里那条
   带 `2026-10-26 自动补充` 注释的 `true` 就是它写的，不是作者设的。
   → 只改出厂默认**等于没改**（升级只补缺、不覆盖 config），必须改这个迁移。
2. **计划里写的 `scripts/stage4_group.py` 不存在**，实际模块是
   `scripts/utils/enhanced_chapter.py`；plan 中的“拆群入口判据”本来就已存在
   （`enhanced_mode` 或“字数 < 下限 60% 自动降级”），所以没有改 stage4 的分支逻辑，
   只把该模块的定位写成“降级路径”。
3. **迁移纪律**：只认 `2026-10-26 自动补充` 这个标记；用户自己设的值一个字不动
   （哪怕他是 `true`）。键缺失时**不再补键**（代码默认 false = 整章单发）。
4. **还没验的**：`ensureEnhancedMode` 只在 `seedWorkspace()` 判定 stale 时跑；
   真实生效要等下一次打包（版本号变化 → 代码 drift → 迁移执行）。作者真机跑一章
   记 `cost_log` 的 tokens_in/out 与汉字数，才算 P0-1 的判据拿到。

### P0-2 施工记录（只做了“不重复喂”，没动 prompts）

| 改造 | 文件 | 判据实测 | 回退方式 | 时间 |
|---|---|---|---|---|
| P0-2 上下文按需读 | `scripts/stage4_writing.py`（新增 `_write_setting_excerpt`；`{{path_setting}}` 改指每章摘录）· `tests/unit/test_stage4_context_on_demand.py` | 夹具：原设定集 39,655 B → 摘录 1,236 B（**3.1%**），无关角色 0 条；本章没命中条目时仍退回原设定集（不给空文件）；任务书正文 7,379 B | 删掉 `_write_setting_excerpt` 的调用，`path_setting` 退回 `Path(setting_path).resolve()` | 2026-11-25 |

**为什么这么改（计划外的判断）**：任务书里早就内联了本章的角色卡 / 地点 / 势力 /
时间线 / 情节碎片（`_extract_world_context` 等），模板那一行却仍让模型去读
**整本 126 KB 的 setting.json** —— 同一份料喂两遍，第二遍还是全本。
这是“单章输入 10.5 万”里最大的一块，而且**不用改 `prompts/**`**（前缀缓存纪律）。

**没做的两件，理由**：

1. 「任务书正文 ≤ 8 KB」：与作者要的“设定全读”（`_extract_world_context` 的
   `FULL_TEXT_CAP` / “全读是作者口径”那条注释）正面冲突。任务书 24 KB 里约 20 KB
   就是这些内联条目，砍到 8 KB 等于把设定重新拿掉 —— 那是另一个产品决定，要作者拍板。
2. 「单章输入 ≤ 30,000 token」：只有真跑才量得到。本轮把**重复的那一份**去掉了
   （设定集 126 KB ≈ 6 万 token 量级），预期能砍掉一半以上，但数要真机给。
