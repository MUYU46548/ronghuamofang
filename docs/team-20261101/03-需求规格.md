# 03 · 需求规格

> 依据：`00-事实基线.md`（下称〔基线〕）、`01-业务界定.md`（下称〔界定〕）、`02-产品定义.md`（下称〔定义〕）。
> 本文只写**可判定的需求**。不写代码、不定接口与数据库、不排期、不写版本号。
> 无实测依据的数一律标 **需实测** 并给测法；凡涉实现选择一律标 **待研发确认**。
> 上游已定、本文不改：① `T_接管 ≥ T_自写` 即不可用，质量不进判定〔界定·3〕；② 主指标 BROE，当前整章、目标段且目标值需实测〔界定·4〕；③ 一期只动"重算与核对的最小单元 = 段"，不做全书唯一段身份〔定义·3.6〕。

**判据书写规则（本文一律遵守）：**

1. 判据只允许二值（成立/不成立）或可数（次数、条数、字符数、行数），**禁止**"良好""及时""流畅""基本可用"。
2. 反证必须写清"把哪个判据放宽或删除，什么现象会变红"，不允许写"实现不到位则失败"。
3. 凡涉及"会不会伤到别处"的需求，判据里必须有 **未改动段落逐字 diff = 0** 这类硬判据（R09、R11、R12、R13、R15、R16 六条）。
4. 不得用"跑一章作者读一遍觉得行不行"作判据〔基线·五·2〕。

### L0 · 边界能力

#### R01 · 本轮范围指定
- **场景 / 能力层**：S01 / L0
- **一期**：否
- **需求**：GUI 必须存在"本轮做哪几章"的输入（章数或章节区间）；启动后流水线只处理该范围内的章，处理完即停，范围外的未完成章不得被顺带写入。
- **验收判据**：① GUI 存在该输入且可提交；② 启动后 workspace 新增章节文件数 = 设定值（误差 0）；③ `runs.db` 该 run 的章节记录数 = 设定值；④ run 结束后，范围外的未完成章状态仍为 `未开始`（逐章核对）。
- **反证**：删除 ②③ 只验"输入框存在"→ 控件在、一跑仍跑到所有未完成章也算通过，S01 判据②③ 失效。删除 ④ → 无法区分"跑到边界停"与"跑到边界后继续跑"。
- **不做的代价（须写明）**：一期一轮仍可能跑向所有未完成章；接管闭环可以在此前提下被验证（现有 10 章已够），但"接管对象由系统单方面决定"这一点在一期仍是红的〔定义·4.4〕。

#### R02 · 运行状态的三态自述（含失联）
- **场景 / 能力层**：S02 / L0
- **一期**：是
- **需求**：状态面板必须呈现 `运行中` / `已停止` / `失联` 三态。三态的判定来源必须是可核验证据（后端活动心跳、`runs.db` 最近写入时间、产物 mtime），**不得由界面计时器从开始时间推算**。必须优先显示"最后一次活动 xx:xx（已 N 分钟无响应）"。失联态提供唯一动作“标为已停止”；标为已停止后，界面不得自行回到运行中。
- **验收判据**：① 杀掉后端进程后，界面在超时窗口内**自行**切到 `失联`，无需刷新或点击（超时窗口需实测，见 M3）；② 失联态显示最后活动时间，且不显示持续递增的"已运行 X 小时"；③ 章节文件 mtime 已静止而界面仍显示 `运行中` → 判失败；④ 失联态点“标为已停止”后章进入可编辑；若进程其实仍在写，必须报冲突（R31/R32），不得两边都写；⑤ 标为已停止后 N 分钟内界面不自行复活（N 需实测）。
- **反证**：把 ① 的"自行"改为"刷新后"→ 作者不刷新就永远看到假的运行中，断点 2 原样保留，S02 判据② 失效。删除 ③ → "界面说在跑、文件已冻结"也通过。

#### R03 · 停止即保稿，残稿显式存在
- **场景 / 能力层**：S03 / L0、L3
- **一期**：是
- **需求**：停止后已完成章的文件字节与内容不变、可在 GUI 打开；正在写的章落为 `已中断·残稿`，显式标"未完成"，不计入合并与导出；停止后写入必须真正静止。残稿只用于"看见损失了多少"与就地接管（R09），**不提供从半截继续生成**〔基线·五·3〕。
- **验收判据**：① 停止前后已完成章文件字节数与内容逐字比对差异 = 0；② 被打断章存在，状态 = `已中断·残稿`，已写入字符数 > 0 时不得被删除；③ 停止后 30 秒内相关文件字节数不再增长（连续两次采样相等）；④ 导出件章数 = `达标·待署名` + `不达标·已接受` + `已确认可用` 的章数之和（残稿不计入）；⑤ 残稿可在 GUI 打开并进入 R09 的就地编辑。
- **反证**：删除 ④ → 残稿被静默计入成品，作者以为整章写完，S03 判据② 失效。把 ① 放宽为"文件仍存在"→ 停止过程覆写掉已完成章也通过。

#### R04 · 真暂停
- **场景 / 能力层**：S04 / L0
- **一期**：是
- **需求**：暂停 = 不再发起新的模型调用、不再产生新的计费；暂停态界面只出现暂停态下做得到的事。
- **验收判据**：① **暂停后新增请求数 = 0**（可数、可判定：比对暂停前后"发起的模型请求计数"，**已发出的在途调用返回时的记账不计入"新增请求"**）；② 暂停后 30 秒内无新增产物文件；③ 暂停态文案中不出现"修改提示词后点恢复"这类在暂停态无效的指令（逐字检查文案）；④ 恢复后从暂停点继续，已完成部分不重复计费（需实测：比对恢复前后 `cost_log` 是否出现重复条目）。
- **观察项（不作判据）**：暂停后 30 秒内 `cost_log` 是否无新增行。**为什么降级**：已发出的调用返回时必然记账，该现象的真假取决于按按钮的时点，不取决于系统行为，写成判据会出现"系统正确但判据变红"（评审否决 B）。
- **反证**：删除 ① → 假暂停必过，正是断点 2 现状。删除 ③ → 界面继续给无效指令，作者改完提示词发现无效，信任级崩塌（L4 被打穿）。

#### R05 · 章间方向修正
- **场景 / 能力层**：S05 / L0
- **一期**：否
- **需求**：运行中可提交一条方向修正，作用域**只限尚未开始写的章**；提交动作不产生新 run。
- **验收判据**：① 存在运行中提交修正的入口；② 提交后 `runs.db` run 行数不变；③ 后续章的请求体中可核验到该修正（验构造，不验效果）；④ 已写完的章逐字 diff = 0。
- **反证**：删除 ② → "提交修正 = 起一条新 run"（本质是重启）也通过，S05 判据③ 失效。删除 ④ → 修正倒灌已完章，半径从"后面几章"回到"全书"。

#### R06 · 非正常终止必须收拾章状态
- **场景 / 能力层**：S02、S14 / L0
- **一期**：是
- **需求**：run 以 `failed` / `interrupted` / 预算熔断结束时，相关章不得停留在 `生成中`；状态面板必须显示终止类别（预算熔断 / 上游错误 / 进程终止 / 未知）与终止时间；已写入内容按 R03 落为残稿。
- **验收判据**：① 构造一次失败 run，结束后 60 秒内该章不再显示 `生成中`；② 面板显示终止类别与终止时间；③ 该章可立即进入 R09 接管；④ 熔断场景下，同一屏可见"因触及预算上限而停止"与已消耗量。
- **反证**：删除 ① → 进程已死、章永远显示"生成中"，与 R02 的失联态相互矛盾，S02 判据② 失效。
- **与 R02 的边界**：R02 回答"它还在不在跑"，R06 回答"它已经不跑了，章被收拾成什么"。

### L1 · 定位能力

#### R07 · 段落清单（段 = 作者看得见的自然段）
- **场景 / 能力层**：S06、S07、S13 / L1
- **一期**：是
- **需求**：一章以"可逐条指名的自然段清单"呈现，条目边界 = 文件中的自然段（作者可见的分段），每条带章内位置与首句。切分必须是**确定性**的：同一文件重复打开，条数与每条边界完全一致；切分不得调用模型。
- **验收判据**：① 清单条数 = 文件自然段数（按空行/换行分隔，口径需实测见 M5）；② 每条首句与原文逐字一致；③ 同一文件连续打开 3 次，条数与每条起止位置完全一致；④ 切分过程 `cost_log` 无新增行。
- **反证**：删除 ③ → 切点每次不同，"段"不再是指称对象，R11/R12/R13 全部失去对象，整条 L3 变成 §3.4 的假动作。删除 ④ → 切分靠模型，同文件两次结果不同且产生费用。

#### R08 · 指到即到（双向、同屏）
- **场景 / 能力层**：S06 / L1
- **一期**：是
- **需求**：点清单任一段 → 正文对应段立即定位并进入可编辑；在正文点到某段 → 清单同步高亮；两侧同屏，不跳页。
- **验收判据**：① 定位落到的文本区间与清单条目逐字一致（起点与终点均对）；② 从"指到该段"到"可以敲字"不发生页面跳转、不需要第二次点击；③ 双向一致（清单→正文、正文→清单各测一遍）；④ 全流程 `cost_log` 无新增。
- **反证**：删除 ② → "指到一段要先切页签"也通过，S06 判据① 的"同一个页面内完成"失效。

### L2 · 就地能力

#### R09 · 就地编辑与即时落盘
- **场景 / 能力层**：S06 / L2
- **一期**：是
- **需求**：在该段上直接改，保存即落盘、即刷新可见；不提交 job、不排队、不等待 diff、不产生 run；重开应用不丢。该动作必须是改动一段的**可用路径之一**，不得被强制转去异步 job。
- **验收判据**：① 改动后文件内容已变，且变更区间仅限该段（区间外字符差异 = 0）；② `runs.db` run 数增量 = 0；③ 从敲字到落盘无异步等待控件（无进度条/无"提交中"）；④ 关闭应用重开后内容仍在且逐字一致；⑤ 不提交任何 job 也能完成一次改动。
- **反证**：删除 ⑤ → "就地编辑存在，但保存后又必须提交一次 job 才生效"也通过，等于 C1 未成立，S06 判据② 失效。删除 ④ → "改完重开回滚"，作者不敢动。

#### R10 · 改写请求降为可选旁路
- **场景 / 能力层**：S06 / L2
- **一期**：否
- **需求**：原有"选段→填意见→提交 job→看 diff"保留为可选辅助（作者说得出想要什么时用），其产出必须落回同一段身份，不得整章重写。
- **验收判据**：① 提交改写请求后，未涉及段落逐字 diff = 0；② 产出落点是段，不是整章文件整体替换；③ 产生的 run 记录可归属到该段。
- **反证**：删除 ①② → 整章被重写仍算通过，则它不是"旁路"，是"唯一路径"的旧形态（断点 8）。
- **一期的替代保证**：R09 判据⑤ 已保证"它不是唯一路径"，故一期不做改造不构成缺口。

### L3 · 局部化能力（主指标 BROE 的唯一承载）

#### R11 · 段是唯一重算单位 ★
- **场景 / 能力层**：S07、S10 / L3
- **一期**：是
- **需求**：任何针对某一段的重算请求只作用于该段；系统不得因为"某段变了"而自行重算整章或全书；**任何重算请求的最小触发单元必须是段，不得是章**〔定义·3.6〕。
- **验收判据**：
  - ① 一次纯手改（替换某段若干字）后，全书其余**所有**自然段逐字比对，字符差异数 **ΔD = 0**；
  - ② 该动作前后 `cost_log` 新增 token **ΔT = 0**；
  - ③ 该动作前后 `runs.db` run 数增量 **ΔR = 0**，且成品文件未被整体重出（mtime 与字节数均不变）；
  - ④ 任何 AI 段级重算的请求体只含该段及其必要上下文，不含整章全文（验构造，不验效果）；
  - ⑤ 该段变更后，下游阶段自动重跑次数 = 0（要重跑必须作者显式发起）。
- **反证**：把 ① 放宽为"ΔD 很小"立即失效——当前整章重写在多数情况下 ΔD 也不大（只有被改的那章变了），此时"改一段"与"整章重生成"在判据上**不可区分**。删除 ③ → 无法区分"段级"与"全书重出"。删除 ⑤ → 段变了以后下游自动重跑一遍，BROE 暗中回到章。

#### R12 · 未改动区不变，且当场可见
- **场景 / 能力层**：S07 / L3
- **一期**：是
- **需求**：每次改动后，当场指给作者看"只有这一段变了，其余 N 段一个字都没动"；该结论必须能被独立复核（不依赖界面自述）。
- **验收判据**：① 改动前后对全书逐字比对，实际改动字符数 = 预期改动字符数（**不是"约等于"**）；② 界面显示"其余 N 段未改动"中的 N，与实际比对得到的未改动段数相等；③ 界面声称"仅此段变更"时，实际 ΔD 必须 = 0；④ 不经界面、直接比对文件得到的结论与界面一致。
- **反证**：删除 ④ → 界面说"只改了这段"而文件别处也变了，作者无法证伪，"可信"变成表演（L4 空转）。把 ① 的"逐字"降为"段落级"→ 段内被整段替换也判通过。

#### R13 · 段增删后的位置稳定
- **场景 / 能力层**：S06、S07 / L3
- **一期**：是
- **需求**：在一章内增加 / 删除 / 拆分 / 合并自然段后，其余段仍指得准——上次标记的那一段，增删之后还是同一段。
- **验收判据**：① 删掉第 3 段后，原第 5 段通过清单定位到的原文首句，与删除前逐字一致；② 增删后清单条数 = 新文件的自然段数；③ 连续增删 5 次后（次数需实测），标记不漂移到其他段；④ 无法对齐时必须显式报告（走 R14），不得静默错位。
- **反证**：删除 ③ → "删一段之后 A 段标记跑到 B 段身上"也通过，作者不敢标记，等于没有可指名段〔定义·3.2〕。

#### R14 · 段身份失配的显式降级
- **场景 / 能力层**：S06、S07 / L3
- **一期**：是
- **需求**：当段身份无法与当前文本对齐（大幅改写、整章重生成、外部写入破坏结构）时，系统必须显式声明"该段已无法对应到当前文本"，把该章退回"需重新指认"，**不得**把旧标记就近挂到相邻段。
- **验收判据**：① 构造一次整章重生成，旧段标记不得映射到新文本的任意一段（映射成功数 = 0）；② 界面给出"原标记已失效，需要重新指认"的可读提示，并指出是哪一段；③ 失配发生时，该章不得停留在 `已确认可用`；④ 失配率（失配次数 / 增删或重生成次数）**需实测**（M5 相关）。
- **反证**：删除 ① → 系统把旧标记"就近"挂到某段，作者以为标记有效、实际改错了段——这是比没有标记更坏的结果。

#### R15 · 段级重算失败不回退整章
- **场景 / 能力层**：S07、S10 / L3
- **一期**：是
- **需求**：某一段的重算失败，只让这一段失败并可重试；不得把整章打回、不得丢弃该段原文、不得改动其余段。
- **验收判据**：① 断网/断模型后发起段级重算，该段原文逐字不变；② 其余段逐字 diff = 0；③ 章状态不回退（不得因一次段级失败从 `达标·待署名` 变为 `未开始` 或 `已中断·残稿`）；④ 恢复后可直接重试该段，已完成段不重复计费（`cost_log` 无重复条目）。
- **反证**：删除 ③ → 一次失败把整章打回重来，BROE 立刻从段放大到章，断点 6 的形态复现。

#### R16 · 单段补长
- **场景 / 能力层**：S10 / L3
- **一期**：否

- **场景 / 能力层**：S12 / L5

- **场景 / 能力层**：S12、S13 / L4+L5

- **需求**：外部 Agent **允许**：读取全部产物与状态、写段落/章节文本（须持锁）、发起段级重算（须持锁且单位为段）。**禁止**：R35 五项、解除或绕过锁、修改判定阈值与字数下限配置、删除章文件、改写"接受/确认"记录。拒绝时文案须含动作名与一句可读说明，禁止只回错误码。
- **验收判据**：① 白名单 3 类动作在持锁下成功（3/3）；② 黑名单 6 类动作全部被拒（6/6）且状态 diff = 0；③ 拒绝文案含动作名 + "该动作只能由作者在界面上完成"句式；④ 尝试绕过锁的写入在文件层被拒（文件字节不变）。
- **反证**：删除 ② → agent 可删章，R24/R20 的记录可被抹掉，C3 名存实亡。删除 ④ → "锁在前端、写在后端"，直接调用端点即可绕开，R31 变成假锁。

## 2. 核心业务对象状态机：章节

> **现状病灶**：字数不达标仍为 `ok`、`quality` 8~9（10/10 章），状态与事实脱钩〔基线 §2.2、断点 5〕。本节把"达标事实"与"作者署名"拆成两个正交维度，使系统不能再用一个 `ok` 同时表达两件事。

### 2.1 状态集（9 个章状态）

| # | 状态 | 含义（可核验定义） | 可否计入导出 |
|---|---|---|---|
| C0 | `未开始` | 无该章文件，或文件为 0 字节 | 否 |
| C1 | `生成中` | 该章正在被写入，且证据源在超时窗口内有活动 | 否 |
| C2 | `已中断·残稿` | 写入被停止/失联/失败打断，留下字符数 > 0 的不完整文本 | 否 |
| C3 | `待选版` | 该章存在 ≥2 个候选版本且字数差异超阈值，作者未指定采用哪一版 | 否 |
| C4 | `不达标·待处置` | 当前定稿版本字数 < 配置下限，且作者未处置 | 否（须先接受或改到达标） |

## 3. 权限与 actor

### 3.1 actor 字段与取值

每个写操作必须携带一个可核验的 actor 标识，落盘后成为该次改动的来源记录（R25 依赖它）。

| 字段 | 取值 | 说明 |
|---|---|---|
| `actor.kind` | `human` / `http` / `mcp` / `cli` / `pipeline` / `system` | 六类。`human` = GUI 内由人点击或键入 |
| `actor.id` | 具体标识（如 `mcp:agent-name`、`pipeline:stage4`、`system:wordgate`） | 用于 R25 的来源标注与 R32 的"谁在写" |
| `actor.via` | 入口（GUI / HTTP / MCP / CLI / 内部） | 与 `kind` 可不同（GUI 后端可能走 HTTP），用于并发裁决与排查 |
| `actor.session` | 会话标识 | 用于判断"同一入口的连续动作"与"两个入口同时动作" |

**为何要区分 `http` 与 `human`**：GUI 可能经本地 HTTP 转发请求。若把 GUI 的写入也记成 `http`，则 R35 的"只有人能确认可用"无法执行，R25 的来源也说不清"是人在界面上点的，还是脚本发的"。区分方式属实现（**待研发确认 D6**），但**产品要求是：来源必须可辨，且人专属动作必须能证明是人**。

### 3.2 只允许人执行的动作

| 动作 | 场景 | 拒绝时必须给出的文案要点 |
|---|---|---|
| 确认可用 | S15 | "确认可用只能由你在界面上完成。当前请求来自：<actor>" |
| 接受不达标 | S08 | "接受不达标只能由你在界面上完成。它会成为你署名的依据。" |
| 标为已停止 | S02 | "标为已停止会释放写锁，只能由你在界面上完成。" |
| 选定最终版本 | S09 | "采用哪一版只能由你决定。当前待选版本：<n> 个。" |
| 导出 | S11、S15 | "导出只能由你在界面上触发。" |

**文案硬要求（R36 判据③）**：必须含动作名 + 一句原因，**不得**只回 403 / 错误码 / "无权限"。

### 3.3 外部 Agent 的允许与禁止

| 类别 | 动作 | 条件 |
|---|---|---|
| 允许 | 读取章节、段落、状态、成本 | 无需持锁（读不阻塞状态面板，R31 判据④） |
| 允许 | 写段落文本 / 写整章文本 | **必须持锁**；整章写会触发 T25 的告知 |
| 允许 | 发起段级重算 | **必须持锁**，且请求单位为段（R11 判据④） |
| 禁止 | 确认可用 / 接受不达标 / 标为已停止 / 选版 / 导出 | R35，20/20 必拒 |
| 禁止 | 解除或绕过锁 | 文件层拒绝（R36 判据④） |
| 禁止 | 修改字数下限、判定阈值、预算配置 | 改阈值等于改判定，等于自己给自己发合格证 |
| 禁止 | 删除章文件 | 会让 R20/R24 的记录失去载体 |
| 禁止 | 改写"接受/确认"记录 | 同上 |

### 3.4 同一对象上两个 actor 同时要改：裁决规则

**规则：先到者持有，后到者被拒绝，不排队。**

| 情形 | 裁决 | 需求 |
|---|---|---|
| 两个写请求同时到达同一章 | 先取得锁者进行，后到者立即被拒，返回 R32 文案 | R31 判据①②、R32 |
| 人被 agent 锁住 | 人**不排队**；界面给人一个“叫停对方”的动作，叫停后 agent 侧该章落 `C2`（T04 同路径） | R32 判据③ |
| 人先改、agent 后到 | agent 被拒 | R31 |
| 两个读 + 一个写 | 读不受影响，写独占 | R31 判据④ |
| “标为已停止”时进程其实还活着 | 报冲突，不得双写（T04 条件） | R02 判据④、R31 |

**为何不排队**：排队会让作者以为自己在改、实际在等；等待一长他就重开一个入口，那正是"必炸"的由来〔定义·4.3-Q4 第 2 条〕。**代价**：人可能被 agent 挡一次，需要点“叫停对方”——这个代价被显式接受，写进 R32 的验收里。

**锁粒度**：产品只要求"同一份稿同一时刻只有一个写入者"。章级还是段级属实现（**待研发确认 D1**）。

## 4. 异常与空状态

> 每条给：用户看到的文案要点 / 系统状态 / 可执行的下一步 / 关联需求。文案只给**要点与示例句**，不给最终定稿。

### 4.1 跑到一半进程死了
- **文案要点**：“失联 · 最后一次活动 15:04（已 12 分钟无响应）· 常见原因：进程已退出”+ 唯一动作“标为已停止”。
- **系统状态**：run 侧为失联；章侧停在 `C1` 或已被 T04/T05 收为 `C2`；锁仍被死进程占着（需可被"标为已停止"回收）。
- **下一步**：点“标为已停止”→ 锁释放 → 该章进入 `C2 已中断·残稿` → 可进入 R09 接管或显式整章重生（T25）。
- **关联**：R02、R03、R06、R31、R32。

### 4.2 用户主动停止
- **文案要点**：“已停止（你于 14:32 叫停）· 已保住 10 章 · 第 11 章留下残稿 1,240 字（未完成）”。
- **系统状态**：已完成章 `C5`/`C6`/`C7` 不变；当前章 `C2`；30 秒内文件不再增长。
- **下一步**：打开残稿看损失 / 进入接管 / 显式整章重生。**不提供续写**。
- **关联**：R03（判据①–⑤）。

### 4.3 token / 预算熔断
- **文案要点**：“因触及预算上限而停止 · 本轮已用 X · 上限口径：<口径> · 停止原因：<类别>”；若配置实际不生效则叠加"本轮不受硬停保护"（R29）。
- **系统状态**：run 终止；当前章按 T05/T06 落 `C2` 或 `C0`；状态面板不得再显示 `运行中`。
- **下一步**：查看已消耗（R33）→ 决定是否继续；界面须显式说明"继续会产生新费用"。
- **关联**：R06、R29、R33、R34（非一期）。

### 4.4 并发写冲突
- **文案要点**：“《潮汐档案》第 07 章正在被 <来源> 写入（已写到第 3 段）。你可以：① 等它写完；② 叫停它并接管。”
- **系统状态**：后到者未写入任何字节；先到者继续；锁仍被持有；读功能正常。
- **下一步**：二选一，两个动作都可执行；“叫停”后先到方落 `C2`。
- **关联**：R31、R32。**禁止**：排队等待、静默覆盖、只回错误码。

### 4.5 产物过期
- **文案要点**：“成品已过期 · 第 07 章在 16:20 被你修改 · 上次出成品 15:40”+ 两个动作“重新出成品”“查看改动”。
- **系统状态**：成品标记 `过期`；相关章回落 `C5`（T19）；过期标记只能靠重新出成品 + R26 核对清除。
- **下一步**：重新出成品 → 核对差异 = 0 → 才可再次“确认可用”。
- **关联**：R23、R24、R26。

### 4.6 章节文件损坏或为半截
- **文案要点**：“第 05 章文件无法解析（可能被其他程序改动或写入中断）· 该章不计入成品”/“第 11 章为残稿，1,240 字，未完成”。
- **系统状态**：损坏 → `C8`（禁止自动覆写，H7）；半截 → `C2`。
- **下一步**：查看原始内容 / 另存残稿 / 人工修复后重新判定；损坏章导出前必须提示"预计导出 10 章，实际 9 章"。
- **关联**：R27、R03。

### 4.7 段边界在改写后无法对齐
- **文案要点**：“第 03 章第 12 段的标记已失效：该章内容发生了整体变化，原标记无法对应到当前文本。需要重新指认。”并指出具体是哪些段失效（条数可数）。
- **系统状态**：失效标记不映射到任何新段（R14 判据①）；该章不得停留在 `C7`；该章进入"需重新指认"。
- **下一步**：重新打开段落清单 → 重新指认 → 继续接管。
- **关联**：R13、R14。**禁止**：就近映射、静默丢弃标记。

### 4.8 预算配置不可用
- **文案要点**：“预算上限 10,000,000（口径：输出 token）— 本轮实际用量不触及此口径，**本轮不受硬停保护**”。
- **系统状态**：配置存在但未生效；不得展示成有效护栏。
- **下一步**：显式说明如何让它在下一轮生效（口径/键位），或由作者决定忽略。
- **关联**：R29、R34（非一期）。

### 4.9 无任何产物（空工作区）
- **文案要点**：“当前没有可接管的稿子。你可以：① 启动本轮写作；② 导入已有章节。”不得出现"加载中"、不得出现"0 章 · 全部达标"。
- **系统状态**：章集合为空；不得有任何汇总型结论。
- **下一步**：两条动作均可执行。
- **关联**：R30。
