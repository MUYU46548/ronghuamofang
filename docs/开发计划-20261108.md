## 二、下一阶段的目标

不是再加生成功能，而是把三件事做实：

1. **装上去就能跑**：安装版真机五条验收通过，出问题有一个小版本修掉。
2. **写完能交**：一章从“判定 → 勾事件 → 放行/打回 → 改 → 再判”走通一次，有记录。
3. **改得动**：改一段只动这段，改完能回退，导出的是改后那版。

这三件都不依赖模型强弱；模型越强，它们的价值越高。

## 四、P1：把“能交”做实（约 4–6 天）

按价值排序，前两项不花 token。

### P1-1 去 AI 腔基线（0.5 天，零 token）

- **为什么**：现在只有检测（五类特征 + 同质化六指标），没有一次“改前/改后”的数。
- **做什么**：拿 3 章真实稿，统计每千字命中；你盲评同篇幅两段哪段像人写的；出一页报告。
- **通过标准**：得到一组基线数；改后命中下降 ≥ 40%、盲评选“改后”≥ 4/5，才算工具可用。
- **不做**：在拿到数之前，不把它做成出章硬门。

### P1-2 一致性体检一页（1–1.5 天，零 token）

- **为什么**：设定引用过期、伏笔、结构指标、判定提示现在分散在四个地方，没人一页看完。
- **做什么**：新增一页只读汇总：本章/全书各多少条、点进去看原文；复用现有确定性检查，不调模型。
- **通过标准**：一页能回答“这本书现在有哪些地方对不上”；每条都能点回原文。

### P1-3 多库：五类目录按库独立（1 天）

- **为什么**：现在多库能同时读，但“角色/地点/势力/概念/年表”五类目录是全局一套；两个库结构不同时，辅库会扫空。
- **做什么**：`vaults.json` 每库存自己的五类目录；界面切库时显示该库的映射；缺配置时明说“这个库没配目录”。
- **通过标准**：两个结构不同的库同时读，各自都能扫到条目；用例覆盖“一库配了、一库没配”。

### P1-4 字数达标（0.5 天 + 真跑，需 token）

- **为什么**：账本里唯一还完全没实证的硬指标。
- **做什么**：装好后真跑 1–2 章，记录汉字数、章号、当时的每章字数设置；不达标就定位是提示词、补长还是模型上限。
- **通过标准**：每章汉字 ≥ 4000，或明确记录“接受不达标 + 导出清单确认”。

### P1-5 改一段的对比与回退（0.5–1 天，改界面）

- **为什么**：段落重写现在直接替换，只能靠历史回退；改完好不好，没有并排看的地方。
- **做什么**：重写返回后给“改前/改后”并排，点“采用”才写盘；不采用保留原文。
- **通过标准**：不点采用，正文一个字不变；采用后历史里有上一版；截图目检通过。

## 六、不做清单（明确不做，免得反复讨论）

- **不再加“生成类”功能**（更多题材模板、更多一键成书）：模型强度决定上限，加了也不会更好。
- **不引 UI 框架**（Element/Tailwind）：全仓是手写 CSS + 主题变量，引框架等于重写 60 个组件。
- **不做多库自动合并**：同名条目只做“当前库优先 + 点名”，自动合并会改你的设定。
- **不把去 AI 腔做成硬门**：先有基线数，再谈是否卡出章。
