# 出厂预设模板与“作者模板不混入打包”（2026-11-07）

> 作者的话：**“重新造一个新的预设模板，防止我的真实模板混入打包带来麻烦。”**

## 一、查到的事实（先说清楚原来是什么状况）

1. 仓库里的 `templates/小说格式模板V1.3.dotx` 与作者电脑上
   `文档\自定义 Office 模板\小说格式模板V1.3.dotx`（作者电脑上的原件）
   **sha256 完全相同**（`0985bbfd…`）—— 就是作者本人的模板。
2. 它被“出厂化”了三处：
   - `console/package.json`：`../templates → payload/templates`（**打进安装包**）
   - `console/main/index.js`：`SEED_CODE_DIRS = ["scripts","prompts","templates"]`（**每次启动复制进工作区**）
   - `scripts/nf_api_domains/project.py`：`DEFAULT_WORD_TEMPLATE`（**默认落点 / 恢复默认的落点**）
3. 这份仓库是 **public**（`gh repo view` → `visibility: PUBLIC`）。

## 三、做这一步时踩到并修掉的坑（值得记）

第一版预设**漏了 `[请输入文本]` 正文锚点**，于是用预设导出的成品**没有目录**：

- `stage7` 找不到正文锚点时会退化成“拿最后一个段落当锚点”；
- 而最后那一段正好是刚插入的 TOC 域 → 接着被“清空锚点”这一步抹掉。

症状是“成品看着正常，但目录是空的”，肉眼很难发现。现在：
- 预设带 `[请输入文本]`（导出前校验本来也会拦缺锚点的模板）；
- 用例 `test_factory_template`【4】真跑一次导出，断言 `TOC` 指令 + `fldChar` 都在。

## 四、还没做的一件（要作者点头）

作者模板**仍在 public 仓库里**（打包已经不带了，但仓库本身谁都能下载）。
要不要把它从仓库删掉？两种做法：

- **只删当前版本**：`git rm templates/小说格式模板V1.3.dotx` —— 目录里看不到，但历史提交里仍能翻到；
- **连历史一起清**：需要重写 git 历史（filter-repo），影响所有已有克隆，风险高，建议单独评估。

（作者电脑上的原件不受任何影响：`Documents\自定义 Office 模板\` 里那份一直在。）
