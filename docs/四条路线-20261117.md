## 各线 P0 / P1（按这个顺序推进）

### 一、讨论（继续投入）

**P0 ✅｜讨论结论落成批注**（零 token，已完成）
- 现状：讨论能产出 `suggest_edit / rewrite_chapter / refine_paragraph`，但 `suggest_edit`
  只是一段文字，落不回段落。
- 做法：动作里带 `quote` → 按当前正文定位段号（复用批注的重定位逻辑），
  一键写成批注（来源写进批注正文，批注列表显示“来源：讨论《主题》第 N 轮”）。
- 判据：动作没有可定位引用时**拒绝落批注**并说明原因（不许猜段号）；
  落成后 `GET /chapters/annotations` 能看到；同一条建议重复落要拒绝。

**P1｜讨论轮内联候选**（花钱）
- 讨论说“这段太直”，直接在同一轮给出改前/改后候选（复用 `/chapters/paragraph/preview`）。
- 判据：候选必须走 preview（不落盘），采用仍归作者在编辑器点。

### 二、多写几版（继续投入）

**P0 ✅｜结构六项证据进候选**（零 token，已完成，见上）

**P1 ✅｜每版附“判定依据预览”**（零 token，2026-11-18 已完成）
- 把判定引擎的确定性规则（`utils/judge/rules`）对每版跑一遍，给出“这版会触发哪几条”。
- 判据：规则只产依据、档位不由打分器决定；缺口径时显式说缺（与结构指标同一纪律）。
- 落地：`best_of_n._judge_evidence()`（与阶段 5 同一份 `analyze_chapter`，**不 bootstrap**），
  结果落 `result.json` 的 `judge` 与 `judge_defaulted / judge_outline_missing`；
  界面三态：有依据（规则名+处数+改法+为什么）/ 一条都没触发 / 没算出来。
  缺阈值的判据点名（规则会回落到代码默认值，如实说“这不是按你的口径算的”）；
  没章纲时明说“章纲类两条无从判断”，不显示成“0 处 = 通过”。

**P2｜按段落多写（Best-of-3 段落版）**（花钱，单价低）
- 复用一个调用出 3 条候选的机制，按段落而不是整章；整章版保留给“整章重写”。
- 判据：段落版不得产生整章重写；采用仍走候选闸（GUI 双因子）。

### 三、沙盒（继续投入）

**P0 ✅｜设定冲突预检**（零 token，已完成）
- 候选进沙盒前，与 `data/setting/setting.json` 做同名/近名/字段冲突检查，
  队列里逐条点名“与已有词条 X 冲突：年龄 30 vs 32”。
- 判据：只报冲突、不改文件；`setting.json` 缺字段时标“无从比较”，不许当成“无冲突”。

**P1｜从本章提取设定候选**（花钱，可预演）
- 复用 `entity_extract`，把章节里新出现的人/地/物写成沙盒候选（永不写 vault）。
- 判据：提取结果必须落在沙盒目录；vault 一个字节不动（现有硬边界用例继续钉住）。

### 四、成书提炼（继续投入）

**P0 ✅｜分章摘要可检索**（零 token，已完成）
- 做法：`scripts/book_search.py X --query … [--character …] [--chapter N]`：
  在 `summaries/*.json` 里找章并给上下文；没摘要的章点名；**不建索引、不写文件**
  （补跑成书提炼后结果立刻是新的）。
- 判据：查询只读、文件一个字节不变；索引缺章时明说“这一章还没摘要”，返回空但**不冒充查过**。

**P1 ✅｜并库前冲突清单**（零 token，2026-11-18 已完成）
- `merge` 预演里逐条列出“同名角色但身份不同 / 同名设定但内容不同”，作者勾选后才写。
- 判据：不勾选 = 不写；写前备份 `data/setting/history/`（现有纪律不放松）。
- 落地：`merge_into_setting(..., overwrite=[...])` 返回 `conflicts`（字段级差异）/ `overwritten`
  / `skipped_same` / `pending_conflicts`；CLI `--take`、界面复选框、API `take` 三处同源。
  覆盖只换内容字段，**保留原 `id` 与 `locked`**（锁定条目勾了也不动，报告写“已忽略这次勾选”）；
  `world` 行就地替换不追加第二行；同名且一致的进 `skipped_same`（不算冲突）。

**P2｜续作模式**（花钱）
- 写作/读改时自动带“前作分章摘要 + 相关角色卡”，与滚动摘要同口径。
- 判据：上下文里必须标来源（哪本书、第几章），不许把前作内容当本章事实。

## 明确不做

- 不把讨论做成编辑器、不在讨论里直接改正文。
- 不让打分器决定“写得行不行”（打分只排序；结论归判定引擎与作者）。
- 沙盒永不写 vault（这条红线不因“继续投入”而松动）。
- 成书提炼不自动改写原书，只抽正典。

## 验收口径（每条线都适用）

1. 新行为必须有一条**会变红**的用例（改回旧行为立刻红）。
2. 花钱的动作必须先能零 token 预演 / 先用确定性判据给证据。
3. 界面文案按作者向写（术语当场解释），`ui_copy_audit --check` 必须 0 命中。
