## 一、对标结论（2026-10 实查）

看过的一圈产品，按"能不能抄进本地桌面 + 按章烧 token"的标准分两类。

### 值得抄的（机制，不是文案）

| 来源 | 抄什么 | 为什么我们现在需要 |
|---|---|---|
| **ainovel-cli**（voocel） | ① **弧（Arc）层**：卷 → 弧 → 章三级，骨架弧只有 goal + 预估章数<br>② **指南针（Compass）**：终局方向 + 活跃长线 + 规模估计，卷边界更新<br>③ **step 级 checkpoint**（plan/draft/check/commit）<br>④ **审美维度**（七维之一，细分 5 子项） | 我们只有卷→章两层，卷内 20 章的"节奏形状"没人管；一章内失败要整章重跑；七维全是逻辑正确性，**没有一条评"写得好不好"** |
| **NovelAI** | Character Card 的**关系网驱动互动**（角色之间"自动化学反应"） | 我们的角色卡是静态卡片，关系只作为文本注入；没有"这两个人同场时会怎么说话"的约束 |
| **Sudowrite** | **Describe**（一句叙述 → 感官细节场景） | 我们的扩写只解决字数（`stage4_expand`），不解决"这段缺画面" |
| **笔灵 / 蛙蛙写作** | **去 AI 腔改写** + **平台文风预设**（起点/番茄/知乎的节奏差异） | 我们有同质化检测（只报），没有"按平台口径改一遍"的动作 |
| **阅文 WriteClaw** | **情节评论分析**（把读者视角的吐槽结构化） | 我们的审稿全是"作者/编辑视角"，缺"读者会不会在这里弃书" |

### 明确不抄的（附理由，免得反复讨论）

| 不抄 | 理由 |
|---|---|
| 多 Agent 自主调度（Architect/Writer/Editor 互调） | 我们是 `direct` 引擎 + 外层 Agent，**没有 agent 层**。抄它等于重写架构，而用户要的是审批权在自己手上 —— 自主调度正好相反 |
| 图文联动（NovelAI 插画） | 与"出 Word 稿"的产品目标无关，且要额外模型与版权处理 |
| 云端账号 / 发布 / 变现闭环（百度作家、蛙蛙） | 本地工具，隐私优先；发布是作者自己的事 |
| 500 章无人值守 | 定位是半自动，审批门是特性不是缺陷 |

## 三、v0.7 审美与弧（最优先，因为它决定"写得像人"）

### 7.1 七维补审美维（抄 ainovel-cli 的审美细分）

现在七维（plot/timeline/space/reference/relation/persona/commonsense）全是**正确性**，
一篇逻辑无懈可击但干巴巴的稿子能拿满分。补第八维 `aesthetic`，细分五项：

描写质感 / 叙事手法 / 对话区分度 / 用词质量 / 情感打动力 —— 每项仍要原文举证。

- 落地：`utils/review_ledger.py` 的 `DIMENSIONS` 加一维 + 子项；`gates.review_ledger`
  阈值按维统计（审美不参与"完整"判据，单独统计 —— 否则老账本全部变不完整）
- 判据（预计 20 条）：五项缺一即该维作废；**重复用同一个句子给五项举证 → 只认第一项**
  （现实里模型最爱这么偷懒）；审美分进 `summary.json` 的独立小节

### 7.2 弧层骨架 + 节奏模板（抄 ainovel-cli）

现状：卷纲（20 章逐章目标）+ 章大纲，中间没有"弧"。一卷 20 章平铺直叙也能过卷纲判据。

- 新增 `utils/arc_plan.py`：卷 → 2-4 个弧（每弧 3-8 章，`goal` + 预估章数 + 弧型）
- 5 种弧型与密度参考（成长突破 / 竞技对抗 / 探索发现 / 恩怨冲突 / 日常过渡）——
  **写成数据不是写成提示词**，stage3/4 注入的是"本弧是恩怨冲突型，参考密度：冲突点 2-3 处 / 章"
- 判据（预计 30 条）：弧章数之和 == 卷章数（缺章/重叠都判不合格）；弧型必须在枚举内；
  相邻两弧不得同型（"连续 40 章日常过渡"是真实会出现的退化）

### 7.3 指南针（Compass）

替代"global.md 定终身"：`data/outline/compass.json` = 终局方向 + 活跃长线（最多 5 条）
+ 规模估计（预计总章数 ±30%）。**卷边界自动提示更新**，改动要留 diff。

- 判据（预计 15 条）：活跃长线 >5 条时拒绝写入并说清（长线太多等于没有主线）；
  终局方向变更必须记 `history/`；compass 与已写章节摘要矛盾时告警不阻断

### 7.4 上下文健康度

现在有预算，但用户看不到"这一章吃掉了多少"。`GET /state` 加 `context` 段：
本轮平均输入 token / 预算占比 / 最近 5 章趋势；GUI 流水线加一条健康度条（绿<70%/黄<90%/红）。

- 判据：口径与 `cost_tracker` 同源（不另算一份）；无数据时明确"未统计"

## 四、v0.8 可控写作

### 8.1 step 级 checkpoint（抄 ainovel-cli）

现在断点在**章**：第 7 章失败 → 第 7 章整章重跑（烧完整章 token）。
改为章内四步落盘：`plan`（章内节拍）→ `draft`（正文）→ `check`（自检）→ `commit`。
重跑从失败的那步开始。

- 判据（预计 25 条）：四步各写 `data/state/checkpoints/NN.json`；**只读 checkpoint 不够，
  必须校验产物 sha256**（磁盘被手改过就作废重跑）；`reject.py` 清章时一并清 checkpoint

### 8.2 写作中实时干预

审批门是"停下来问"，但用户常在看到第 3 章就想改方向。加 `POST /intervene`：
写入一次性指令，下一章写作前注入（不改大纲、不重写已写章节），并标"作者干预"。

- 判据：干预只影响**下一章及以后**；同一章只认最后一次（不叠加）；注入块里必须有
  "这是作者当面要求，优先级高于大纲的软约束"

### 8.3 逐章验收开关

`gates.chapter_approval: false|true`：开了之后每章写完全停，等 GUI 放行（与 `approve.py`
同一套状态机，不新造）。默认关。

### 8.4 角色关系网约束（抄 NovelAI 的机制）

现在角色卡注入 `relations` 文本。改为生成前算一次"同场角色对"：本章涉及的角色两两取关系
（直接/间接/敌对），生成"互动约束块"（谁不会先开口、谁必须称呼对方什么）。

- 判据：无关系的角色对不得编造亲密度（判据是"注入块里每对都有来源"，来源必须是设定集
  里的 relations）；章大纲角色 <2 时不生成该块

## 五、v0.9 成品化

### 9.1 去 AI 腔改写器

同质化检测（已有 6 指标）负责**发现**，新增 `scripts/deai_rewrite.py` 负责**改**：
按检测出的具体项（复读/句长单一/比喻堆砌/元话语）生成定向改写任务，只改命中的段落。

- 判据：改写前后**同质化指标必须真的下降**，否则判失败（"改了但没变好"是最常见的假修）；
  不得改变段落数（防偷偷删内容）；默认 `gates.deai_rewrite: false`

### 9.2 平台文风预设

`config/project.yaml` 的 `book.platform: qidian|fanqie|zhihu|none`，各自一套节奏参数
（章末钩子强度、对话占比区间、爽点密度）。注入 stage3/4，并在同质化检测里加"平台口径对比"。

- 判据：三套预设的参数字面量各不相同且有测试锁死（防止"三套预设其实一套"）

### 9.3 读者视角审稿

在七维之外加一份"读者反应预测"：三个虚拟读者（老书虫/新读者/弃书点）各给"会不会在这里
弃书 + 理由 + 原文位置"。**只报不改**，进 `data/review/readers.json`。

- 判据：弃书点必须带章内位置（段落序号）；无弃书点时明说"未找到弃书点"，不许空数组糊过去

### 9.4 导出增强

分卷目录、章节字数统计、字数总计、可选"仅正文"模式（去掉注释行）。stage7 扩展。
