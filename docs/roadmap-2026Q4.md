## 一、对标结论（2026-10-20 两轮实查）

> **二轮补记（2026-10-20 晚）**：第一轮只按"AI 写作工具"搜网页，漏了两家**直接同类**。
> 补入：**书童 Pagekin**（`EthanYoQ/AI-Novel-Writer`，Electron+TS，1.7k★，GPL-3.0，
> 本地优先，2073 个文件，几乎同一产品形态）与 **催更姬**（`mistnest/dsh-cuigengji-plugin`，
> DeepSeek Harness 插件，6 个 phase skill + DSH/MCP 双适配器）。
> **方法修正**：以后每季度按 GitHub topic 扫一遍（`gh search repos --topic novel-writing
> --topic ai-novel --sort stars`），只搜网页关键词会漏掉最有参考价值的同行。

### 值得抄的（机制，不是文案）

| 来源 | 抄什么 | 为什么我们现在需要 |
|---|---|---|
| **书童 Pagekin**（直接同类） | ① **写作 Skill 导入**（提示词型 `SKILL.md` + references，装前展示全文，绑定到规划/写稿/审稿/修稿阶段）<br>② **伏笔生命周期台账**（埋设→推进→解决，按章记）<br>③ **章节蓝图四字段**：主角小目标 / 冲突与转折 / 悬念钩子 / 出场人物<br>④ **失败恢复候选**（生成失败但已写出的文字保留，可复制或放弃）<br>⑤ 运行侧页三态（进行中 / 历史 / 诊断，可取消、批量暂停） | ① 这是"文风由用户自己定"的**正确实现**（见下方不抄清单）；② 我们的 `story_state` 只记死亡/物品/年份，**伏笔断了没人知道**；③ 我们的章大纲是"核心事件/涉及角色/功能/衔接"，缺"小目标"和"钩子"这两个真正指导写作的字段；④ 我们现在失败就是失败，已生成的半章白扔 |
| **催更姬**（DSH 插件） | ① **能力拆成 phase skill**（plan / write / revise / memory / project / maintenance 六个 `SKILL.md`，由宿主 Agent 编排）<br>② **handoff 交接文本**（把当前作品状态生成一段人可读、可直接粘给别的模型的交接稿）<br>③ **作品级预设**（文风、视角等要求跟着作品走，可切换）<br>④ 情节**画布**（卡片/连线/讨论框/便签）<br>⑤ 原子写入 + 文件事务 | ① 我们已有 25 个 MCP 工具和 3 个 skill，但**没有按写作阶段编排**，外部 Agent 得自己猜顺序；② 我们只把上下文拼进 prompt，**没有一份能带走的交接稿**（换模型/换会话就重来）；③ 我们的写作要求散在 `project.yaml`，不能存档多套 |
| **ainovel-cli**（voocel） | ① **叙事深化（原 Arc 层）**：卷 → 深化段 → 章三级，段骨架只有目标 + 预估章数<br>② **指南针（Compass）**：终局方向 + 活跃长线 + 规模估计，卷边界更新<br>③ **step 级 checkpoint**（plan/draft/check/commit）<br>④ **审美维度**（七维之一，细分 5 子项） | 我们只有卷→章两层，卷内 20 章的"节奏形状"没人管；一章内失败要整章重跑；七维全是逻辑正确性，**没有一条评"写得好不好"** |
| **NovelAI** | Character Card 的**关系网驱动互动**（角色之间"自动化学反应"） | 我们的角色卡是静态卡片，关系只作为文本注入；没有"这两个人同场时会怎么说话"的约束 |
| **Sudowrite** | **Describe**（一句叙述 → 感官细节场景） | 我们的扩写只解决字数（`stage4_expand`），不解决"这段缺画面" |
| **笔灵 / 蛙蛙写作** | **去 AI 腔改写**（检测项 → 定向改写） | 我们有同质化检测（只报），没有"按检测结果改一遍"的动作 |
| **阅文 WriteClaw** | **情节评论分析**（把读者视角的吐槽结构化） | 我们的审稿全是"作者/编辑视角"，缺"读者会不会在这里弃书" |

### 明确不抄的（附理由，免得反复讨论）

| 不抄 | 理由 |
|---|---|
| **平台文风预设**（起点/番茄/知乎各一套节奏） | **文风只能用户自己定**（用户 2026-10-20 明确砍掉）。而且两家直接同类（书童、催更姬）都用"用户导入 Skill / 作品级预设"，**没有一家做平台预设** —— 说明这条路业界已经验证过不成立。替代方案见 9.2「写作 Skill 导入」 |
| 多 Agent 自主调度（Architect/Writer/Editor 互调） | 我们是 `direct` 引擎 + 外层 Agent，**没有 agent 层**。抄它等于重写架构，而用户要的是审批权在自己手上 —— 自主调度正好相反。**但"按阶段编排的 skill 包"可以抄**（见 9.3），那是编排而不是代跑 |
| 图文联动（NovelAI 插画） | 与"出 Word 稿"的产品目标无关，且要额外模型与版权处理 |
| 云端账号 / 发布 / 变现闭环（百度作家、蛙蛙） | 本地工具，隐私优先；发布是作者自己的事 |
| 500 章无人值守 | 定位是半自动，审批门是特性不是缺陷 |
| 酒馆（SillyTavern）资料导入 | 那套是为角色扮演会话设计的（世界书/注入深度），语义与"长篇叙事设定集"不同，硬兼容会污染我们的 schema |

## 三、v0.7 审美与叙事深化（最优先，因为它决定「写得像人」）

### 7.1 加「审美五问」（七维不动，另开一块）

现在七维（plot/timeline/space/reference/relation/persona/commonsense）全是**正确性**，
一篇逻辑无懈可击但干巴巴的稿子能拿满分。

**术语决定**：不叫"第八维"，也不改"七维评审"这个名字 —— 七维是既有品牌词，改了要动
prompt / 测试 / GUI / 账本四处。新增的是一块**独立字段** `aesthetic`，人话叫「审美五问」：

> 这章写得好看吗 —— 描写、手法、对话、用词、打动人心，各问一句，各引一句原文。

- 落地：`review_ledger.check_aesthetic()` 独立校验；`dims` 契约一个字不动（老账本照样能读）
- **不参与"完整"判据**：`complete` 仍只看七维；审美单独给 `aesthetic_complete`
- 判据（预计 22 条）：五问缺一即整块作废；**同一句原文重复给多问举证 → 只认第一问**
  （模型最爱这么偷懒，实测在七维里就出现过）；五问分数进 `summary.json` 的独立小节

### 7.2 叙事深化（卷内分段）

**为什么叫这个**：原方案叫"弧层"，用户判断——难听、看不懂。改叫**叙事深化**：
一卷 20 章不是一条直线平推，中间要有 2-4 个"深化段"，每段有自己的目的与节奏形状。

- 现状：卷纲（20 章逐章目标）+ 章大纲，中间什么都没有。一卷 20 章平铺直叙也能过卷纲判据。
- 新增 `utils/story_deepen.py`：卷 → 2-4 个**深化段**（每段 3-8 章，`goal` + 预估章数 + 类型）
- 5 种**深化类型**（成长突破 / 对抗竞技 / 探索发现 / 恩怨冲突 / 日常过渡）——
  **写成数据不是写成提示词**，stage3/4 注入的是"本段属恩怨冲突型，参考密度：冲突点 2-3 处/章"
- 判据（预计 30 条）：各段章数之和 == 卷章数（缺章/重叠都判不合格）；类型必须在枚举内；
  相邻两段不得同型（"连续 40 章日常过渡"是真实会出现的退化）
- **UI 文案一律用"叙事深化 / 深化段"**，不出现 Arc / 弧层（用户看不懂的词不进界面）

### 7.3 指南针（Compass）

替代"global.md 定终身"：`data/outline/compass.json` = 终局方向 + 活跃长线（最多 5 条）
+ 规模估计（预计总章数 ±30%）。**卷边界自动提示更新**，改动要留 diff。

- 判据（预计 15 条）：活跃长线 >5 条时拒绝写入并说清（长线太多等于没有主线）；
  终局方向变更必须记 `history/`；compass 与已写章节摘要矛盾时告警不阻断

### 7.4 上下文健康度

现在有预算，但用户看不到"这一章吃掉了多少"。`GET /state` 加 `context` 段：
本轮平均输入 token / 预算占比 / 最近 5 章趋势；GUI 流水线加一条健康度条（绿<70%/黄<90%/红）。

- 判据：口径与 `cost_tracker` 同源（不另算一份）；无数据时明确"未统计"

## 四、v0.8 可控写作

### 8.1 step 级 checkpoint（抄 ainovel-cli）

现在断点在**章**：第 7 章失败 → 第 7 章整章重跑（烧完整章 token）。
改为章内四步落盘：`plan`（章内节拍）→ `draft`（正文）→ `check`（自检）→ `commit`。
重跑从失败的那步开始。

- 判据（预计 25 条）：四步各写 `data/state/checkpoints/NN.json`；**只读 checkpoint 不够，
  必须校验产物 sha256**（磁盘被手改过就作废重跑）；`reject.py` 清章时一并清 checkpoint

### 8.2 写作中实时干预

审批门是"停下来问"，但用户常在看到第 3 章就想改方向。加 `POST /intervene`：
写入一次性指令，下一章写作前注入（不改大纲、不重写已写章节），并标"作者干预"。

- 判据：干预只影响**下一章及以后**；同一章只认最后一次（不叠加）；注入块里必须有
  "这是作者当面要求，优先级高于大纲的软约束"

### 8.3 逐章验收开关

`gates.chapter_approval: false|true`：开了之后每章写完全停，等 GUI 放行（与 `approve.py`
同一套状态机，不新造）。默认关。

### 8.4 角色关系网约束（抄 NovelAI 的机制）

现在角色卡注入 `relations` 文本。改为生成前算一次"同场角色对"：本章涉及的角色两两取关系
（直接/间接/敌对），生成"互动约束块"（谁不会先开口、谁必须称呼对方什么）。

- 判据：无关系的角色对不得编造亲密度（判据是"注入块里每对都有来源"，来源必须是设定集
  里的 relations）；章大纲角色 <2 时不生成该块

### 8.5 残稿可见可采纳（✅ 2026-10-20 已完成）

`_post_chat` 截断时已经把残稿隔离到 `data/state/truncated/`（含 `last.json` 判据）。
**缺的是人看不见它**：失败之后用户只看到"失败"，不知道模型其实写了 3000 字。

- `GET /truncated` 列出残稿（章号 / 字数 / 时间 / 原因）；GUI 章节行显示"有残稿"
- 「采纳为草稿」= 把残稿写进 `raw/NN.md` 并标记 `truncated_adopted`（**不假装是完成稿**，
  仍然要走 stage5/6）
- 判据：采纳后 `is_chapter_complete` 必须仍判「未完成」（残稿就是残稿）；不采纳时
  `reject.py` 清章要一并清残稿（防"上一轮的残稿被这一轮误采纳"）

## 五、v0.9 成品化

### 9.1 去 AI 腔改写器

同质化检测（已有 6 指标）负责**发现**，新增 `scripts/deai_rewrite.py` 负责**改**：
按检测出的具体项（复读/句长单一/比喻堆砌/元话语）生成定向改写任务，只改命中的段落。

- 判据：改写前后**同质化指标必须真的下降**，否则判失败（"改了但没变好"是最常见的假修）；
  不得改变段落数（防偷偷删内容）；默认 `gates.deai_rewrite: false`

### 9.2 写作 Skill 导入（**替代原「平台文风预设」，用户已明确砍掉那条**）

**文风只能用户自己定。** 我们不提供"起点风/番茄风"，而是给作者一个**装自己的规则**的口子
（形态抄书童，两家直接同类也都是这么做的）。

- 目录：`materials/skills/<name>/SKILL.md` + `references/*.md`（纯提示词）
- **装前把全文展示给用户看**，确认后才落盘 —— 不偷偷装东西
- 绑定到阶段：规划 / 写稿 / 审稿 / 修稿，各阶段可各绑一套；注入时只取正文不带 frontmatter
- **绝不执行代码**：只收 `.md`，不装脚本 / hook / 子代理（安全边界，不是可选）
- 判据（预计 25 条）：非 `SKILL.md` 结构拒装；目录里出现 `.py/.js/.sh/.bat` 即拒装并点名文件；
  references 声明了却缺失 → 拒装；阶段未绑定 → 不注入且任务里写明"未绑定"；
  删目录后索引不留孤儿

### 9.3 伏笔生命周期台账（✅ 2026-10-20 已完成前半：抽取 + 推进 + 人工回收）

现状：设定集只有 `plot_fragments`（一团碎片），`story_state` 只记死亡/物品/年份。
**一条伏笔埋了没回收，没人知道。**

- `data/state/foreshadow.json`：`id / 一句话 / 埋设章 / 推进章[] / 回收章 / 状态(open|advanced|closed|abandoned)`
- 来源只用两个**确定性**入口：七维评审 `plot` 维的原文举证 + 章大纲「钩子」字段（v0.7 新增），
  **不额外烧 token**，也不信任自由文本
- 判据（预计 20 条）：`closed` 必须有回收章；`open` 超过 30 章未推进告警（阈值可配）；
  同 id 不得两条；推进章 < 埋设章 → 判失败
- GUI：章节页签「未回收伏笔 N 条」，点开看埋设章与原文

### 9.4 读者视角审稿

在七维之外加一份"读者反应预测"：三个虚拟读者（老书虫/新读者/弃书点）各给"会不会在这里
弃书 + 理由 + 原文位置"。**只报不改**，进 `data/review/readers.json`。

- 判据：弃书点必须带章内位置（段落序号）；无弃书点时明说"未找到弃书点"，不许空数组糊过去

### 9.5 导出增强

分卷目录、章节字数统计、字数总计、可选"仅正文"模式（去掉注释行）。stage7 扩展。

## 五-B、v0.10 可带走（抄催更姬）

### 10.1 handoff 交接文本

把"这本书当前的状态"生成一份**人可读、可直接粘给任何模型**的交接稿：
`data/handoff/第N章后.md` = 设定摘要 + 未回收伏笔 + 最近 3 章摘要 + 下一章大纲 + 写作要求。

- 为什么：现在换模型 / 换会话 / 换机器，上下文全靠重跑；交接稿是"作品的可携带形态"
- 判据：新会话只靠这一份文件就能写出接得上的下一章（用 fake 客户端验证"交接稿必须含下一章
  大纲的全部字段"）；不含本机绝对路径（复用 `strip_protocol_markers` 的判据）
- CLI：`nfctl handoff --chapter N`；GUI：章节页签「导出交接稿」

### 10.2 阶段 skill 包（抄催更姬的 6 个 phase skill）

我们已有 25 个 MCP 工具，但外部 Agent 得自己猜调用顺序。补 5 个 `SKILL.md`
（`skills/nf-{plan,write,revise,memory,project}/SKILL.md`），每个只说"这一步该调哪几个工具、
判据是什么、什么时候该停下来问作者"。

- **这是编排，不是代跑**：skill 里不写自主循环，仍一次一个阶段、审批门照旧
- 判据：`nf_mcp_handshake_check` 扩一条断言 —— skill 里提到的工具名必须都在 `MCP_TOOLS` 里
  （防文档写了不存在的工具）；新增工具而 skill 未同步 → 测试红

### 10.3 作品级多套预设

`data/presets/writing/*.json`：视角 / 人称 / 节奏要求 / 文风 Skill 绑定，可存档多套并切换。
与 `config/project.yaml` 的关系：preset 是**可切换的层**，project.yaml 是**当前生效值**
（切换 = 写回 project.yaml + 留一份 history）。

- 判据：切换后读回 `project.yaml` 的值必须真的变；preset 里出现未知键 → 拒绝并列出

## 九、竞争定位与许可证边界（本轮补充）

### 甲、对手强项，以及我们不该拼什么

| 对手强项 | 我们怎么办 |
|---|---|
| 书童的 **UX 成熟度**（纸墨界面、运行侧页、逐段对比、一键更新） | 追，但按需追。UX 是他们的护城河，不是我们的 |
| 书童的 **Skill 生态**（可导入别人的写法） | **要抄**（9.2），因为它把"文风"这件事交还给用户 |
| 催更姬的 **宿主生态位**（装进 DSH，白得一群用户） | 不追。我们做 skill 包（10.2）+ MCP，让任何 Agent 宿主都能用，不做某个宿主的插件 |
| 两家的 **功能数量** | **不追**。功能数量是最容易输的一场仗（1.7k star 的项目天天在加） |

### 乙、真正的护城河（别在「抄」的过程中弄丢）

1. **可验证的质量**：确定性判据 + 原文举证 + 126 个测试文件。两家都没有"评分必须引原文，
   引不上就不算分"这种东西 —— 这是本项目唯一别人短期抄不走的东西。
2. **深度流水线**：8 阶段 + 审批门 + 分卷滚动规划 + L1/L2/L3 记忆分层（不是"塞上下文"）。
3. **MCP 25 个工具**：外部 Agent 可以编排（两家都没有）。
4. **Word 模板输出**：直接出可交付的 docx（两家都只出 Markdown/TXT）。

判断标准：**新功能要么让"质量可验证"更强，要么让"作者改起来更快"。两条都不占的，不做。**

### 丙、许可证红线（不看这条会出事）

| 项目 | 许可证 | 我们能做什么 |
|---|---|---|
| 书童 Pagekin | **GPL-3.0** | **只抄机制与交互思路，一行代码都不许抄/改写**。GPL 有传染性，混进 MIT 仓库会让整个项目被迫 GPL |
| 催更姬 | MIT | 可以借代码，但要保留版权声明并注明来源 |
| ainovel-cli | MIT | 同上 |

变成事实上的复制）。确实要参考 MIT 项目的代码时，在 `THIRD-PARTY.md` 记来源。
