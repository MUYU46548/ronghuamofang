## 四、作为"方寸问卷系统"缺的机制（本次测试的真正产出）

方寸现状：`registry.yaml` 里 `fangcun-base` 的路线图写着"AI 规划跑通第一单"、说明写着"AI 规划还是零单"；仓库内 grep `问卷` / `decision-log` **零命中**；问卷要落的 `shared/mofang/decision-log.md` 全盘不存在。所以这不是"接进方寸"，是"从零建"，而且问卷本身没带 schema。

建议的最小 schema（每题一条，机器可校验）：

```json
{
  "id": "mofang.judge.defect_ratio",
  "question": "缺陷段占比阈值",
  "baseline": { "repo": "NovelForge", "commit": "982f149", "generated_at": "2026-11-04T09:20+08:00" },
  "current": { "state": "defaulted", "value": 0.2, "evidence": ["data/judge/caliber.json#J10"] },
  "options": [{ "key": "keep", "label": "确认 0.2", "cost": { "token": 0, "days": 0 }, "reversible": true }],
  "requires": [],
  "conflicts": ["mofang.schedule.anchor"],
  "acceptance": { "check": "judge.py run 后每章有档位", "artifact": "data/judge/records.json" }
}
```

对应的 8 条纪律：

1. **基线指纹**：出卷必须带 `commit + generated_at`；答题时若仓库 HEAD 变了，先重算受影响题。本次全部过期问题都源于没有这一条。
2. **已答检测**：决策 key 稳定（如 `mofang.stage6.max_tokens`），出卷前比对 decision-log，已答且现状未变的不再问。
3. **现状字段**：每题必须有 `current.state ∈ {done, partial, pending, defaulted}` + `evidence[]`；选项要标 `already_done`。
4. **依赖图**：`requires` / `conflicts` 显式化（例：M2=C ⇒ M1 验收降级为"未验证"）。
5. **代价字段**：每选项带 token / 人天 / 可逆性，否则作者只能凭描述长度判断。
6. **延期 ≠ 决定**：`deferred` 单独记，不写进 decision-log；"到时再说"不应成为选项。
7. **出处结构化**：`{path,line}` 或 `{url,commit}`，出卷脚本校验存在性 + 引文命中，红项不许进卷。
8. **决定与任务分离**：decision-log 只存决定（带 key、日期、生效范围）；任务拆分进方寸卡片（方寸是账本，无派发能力）。

## 五、最小修订（只改这 8 处，不动版式）

1. **M1**：拆成"已落地（预算 / 判定引擎）→ 请确认"、"部分（拆锁：writing 已拆，group/refine 未拆）→ 选是否补完"、"待做（10 章回测 / 口径标定）→ 选做不做"三段；删掉预算数值，改成"现状 40000/25000"。
2. **M2**：加条件——选 C 则 M1 验收线自动改为"未验证"（写进卷面，不靠人记）。
3. **M3**：改成确认题：`当前出厂 0.2（未标定），确认 / 改值 ____ / 暂不标定`。
4. **M4**：收成单轴三选：第三条证据（"感受标准"）由 **你 / 模型 / 不做** 出；删掉 A 的"同款"叙述（它就是现状）。
5. **M5**：改成确认题（"维持 10-11 口径"是唯一现实选项，B 标"已否决"）。
6. **M6**：拆两题——①时间锚（同窗 / 提前小批量 / 缓行）；②现在是否接零 token 项（是/否）。删掉 C。
7. **M7**：改开放式，由执行方先盘出素材清单（路径 / 篇数 / 用途）再让作者勾，不给猜测项。
8. **M9 / M11 / M12**：措辞从"采纳 A 方案"改为"把已有后端接到界面 / 补哪一段"，并在 `current` 里写明"后端已存在"。

出处部分：删掉不存在的路径与英文原话；催更姬的三条改指 `skills/cuigengji-project/SKILL.md`、`skills/cuigengji-plan/SKILL.md:20`、`skills/cuigengji-memory/SKILL.md`，并注明"机制可借鉴，不是未验证的新做法"。
