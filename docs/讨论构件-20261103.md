# 讨论构件（2026-11-03 立）

> 作者判词：**"踢一脚跑一下"不是感觉，是结构事实。** 墨坊的真身是单发执行管线
> （丢任务→跑批→出 Word），**讨论余地不是没做好，是架构里没有这个构件。**
> 对标仓库：`https://github.com/mistnest/dsh-cuigengji-plugin`（催更姬，MIT）。

这份文档做两件事：**逐条认账（带取证）**、**写清这次补了什么、还缺什么**。

---

## 一、四条逐一对账

### ① 资料工具（AI 可查阅维护）—— 未实装

| 现状 | 证据 |
|---|---|
| 素材/设定是**流水线输入文件**：`materials/`、`data/setting/setting.json` | `stage1_consolidate.py` / `stage2_outline.py` 读它们 |
| AI 拿到的是**任务文件里内联的片段**，不是"可以查的作品资料" | `stage4_writing.md` 里是 `{{character_cards}}`、`{{kb_context}}` 这类预组装块 |
| 没有"按需检索 + 回写"的工具层 | 全仓无 lookup/notes 类端点；MCP 37 个工具里没有一个是"查设定" |

**催更姬的做法**（`docs/architecture.md`）：设定/规划/正文各有 index + 分文件，
**先读摘要索引、再读相关全文**；工具与 Skill 注册给会话，AI 与作者写同一份数据。

**结论**：这一条**没做**。素材库方案 10-31 仍在纸上。

### ② 讨论留下来 —— 构件缺失（这次补的就是它）

| 现状 | 证据 |
|---|---|
| 有一个"提案 → 批准 → 写回章大纲"的**单轮审批** | `utils/discuss.py`（`submit/apply_proposal/reject`） |
| 但**没有任何 stage 读它** | `grep -n "discuss" scripts/stage4_writing.py scripts/stage3_chapter_outline.py` → **零命中** |
| 于是定稿后的正文不会变 | 2026-10-25“潮汐档案”03/05 章讨论过、也重写过，`refined/` 仍是旧稿 |

**根因**：讨论产物是"给人看的一份提案"，不是"写作阶段必须落实的约束"。
中间没有机械通道 —— 改了讨论，正文不会因此重写，提示词也不会因此不同。

### ③ 接着推进 —— 半有

| 现状 | 证据 |
|---|---|
| 阶段级/章节级断点续跑是有的 | `is_chapter_complete` + `todo` 过滤 |
| 讨论/未决提议的恢复语义没有 | 讨论此前没有状态机，谈不上"接着聊" |

**结论**：写稿能续，**讨论不能续**（这次给了讨论 `open/decided` 两态与只追加稿，
"接着聊"成立；但"续做一次被中断的讨论生成"仍没有）。

### ④ 编辑式讨论 —— 语义层空缺

| 现状 | 证据 |
|---|---|
| 阶段 5“逻辑检查”是**确定性脚本判据** | `utils/judge/*`、`quality_checklist`：零 token、规则表 |
| 没有"这段为什么不对、怎么改"的语义讨论 | 有 `nf_review_chapter`（确定性缺陷单）+ 段落精修，但没有讨论 |

**结论**：这一条**没做**，且作者已认（11-01）："逻辑检查用脚本 = 压根没有逻辑检查"。

## 二、这次落地了什么（② 的最小可用形态）

**一句话**：讨论从"一份给人看的提案"变成"一份会传导到正文的数据"。

### 数据

```
data/discuss/<章号>/<主题>.md     # 只追加的轮次稿 + 【结论】段（人读）
data/discuss/<章号>/<主题>.json   # 机读：status(open|decided) / rounds / decided_at /
                                 #        constraints{must, must_not, voice,
                                 #                    foreshadow_plant, foreshadow_payoff}
```

### 三个通路（缺一不可）

1. **进提示词**：`discussion.render_for_prompt(n)` 渲染成"本章讨论结论（必须落实）"块，
   注入 `prompts/stage4_writing.md`（整章）与 `prompts/stage4_group.md`（**加强模式，
   默认路径**）的 `{{discussion_block}}` 占位符。没有已定稿讨论时渲染为空串，不占提示词。
2. **定稿晚于正文 → 该章重写**：`discussion.stale_chapters(raw_dir)` 按 **mtime** 判
   （与 `is_usable_output` 同口径），命中的章进 stage4 的 `todo`。这条是“潮汐档案”
   那次的正面修复：讨论改了，正文自己会旧，不靠人记得。
3. **有地方落、能接着聊**：`open / say / decide` 三动作，稿子只追加不改写；
   `decide` 写【结论】段（重复定稿替换而非叠加）。

### 接口

| 方法 | 路径 | 谁可以用 |
|---|---|---|
| GET | `/discuss/list`、`/discuss/read` | 任何人（只读） |
| POST | `/discuss/open`、`/discuss/say` | Agent 也可以用（开讨论、留发言） |
| POST | `/discuss/decide` | **只有作者**（`agent_mode` 下 403，已进 `FORBIDDEN_IN_AGENT_MODE`） |

MCP 新增四个工具：`nf_discuss_list / nf_discuss_read / nf_discuss_open / nf_discuss_say`
（`decide` **不暴露** —— 我不知道"作者怎么想"）。

### 判据

`tests/unit/test_discussion.py`（31 条，全部零 token）：

- D1/D2 开题与轮次只增不改；D3 **没有一条约束不许定稿**；D4 定稿写盘且可重复；
- D5 多主题合并；D6 渲染块（空讨论不占位、每维有条数上限、截断说明还有几条）；
- D7 `stale_chapters` 双向（旧稿报、新稿不报）；
- D8/D10 两个写作入口都接线；D9 模板占位符真的能渲染。

真机零 token 验证（2026-11-03，工作区）：开会话 → 追加一轮 → 定稿 → 用
`build_group_task` 渲染出的**任务文件里确实带着约束**（截图见提交说明）。

## 三、还缺什么（诚实版，按催更姬对照）

| 缺口 | 为什么难 | 下一步的最小动作 |
|---|---|---|
| **① 资料工具层** | 现在的"设定"是给流水线消费的 JSON，不是给 AI 查的索引；直接把全量塞提示词会顶爆 | 给 `data/setting/setting.json` + `materials/` 建**摘要索引**（名字/一句话/关键属性），加 `nf_lookup(kind, q)` 与 `nf_note_add`（写沙盒待审，不碰正典） |
| **③ 讨论的断点续做** | 讨论的产出是"人 + AI 的往复"，中断点在"AI 该说什么"上 | `data/discuss/*.json` 加 `next_ask`（下一步该谁说话、问什么），前端/Agent 据此续 |
| **④ 语义审稿（编辑式讨论）** | 现在的 stage5 是规则表，改成 LLM 判据要重新定"什么算好" | 先做**窄口**：只对"这一章的情绪曲线/视角漂移"做一次 LLM 讨论，产出的是**讨论稿**（不是分数），落在 `data/discuss/` 的审稿类主题下 |
| 讨论出现在界面上 | 端点与 MCP 都有了，GUI 还没有入口 | 章节页签加"讨论"抽屉：列表 + 轮次 + 定稿表单（复用 `discuss/list|read|decide`） |

## 四、与旧“讨论落地协议”的关系

`utils/discuss.py`（2026-10-18，提案 → 批准 → 写回**章大纲**）**保留**：
它管的是"改大纲"，是 ②的一个子集。本次新增的 `utils/discussion.py` 管的是
"改这一章怎么写"，落在提示词与重写判据上。两者不重叠，因此没有合并。
