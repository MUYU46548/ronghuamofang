## 一、先回答你问的三件事

### 1. 最终用法：墨坊当审阅台，DSH 当执行层

任务主体在墨坊。DSH 不占界面位，它是墨坊调用的一层执行能力；插件留着，但定位是
"让 Agent 替我干活"，不是"让我去 DSH 里审稿"。

三条理由，都可核：

| 理由 | 依据 |
|---|---|
| 逐章读改要的是 diff、并排、勾选、回退、段落定位 —— 聊天窗口这四件事都做不好 | **[账]** 11-17 你的话："跑不是难事，改才难"；`docs/冻结与交接-墨坊转工具位-20261117.md` 据此定"主界面=墨坊" |
| 候选→采纳是**有状态的多步操作**，放进聊天等于拿自然语言当进程间通信 | **[账]** 纲领第二铁律；[码] `nf_paragraph_pending` / `nf_paragraph_diff` 就是为这套状态机写的 |
| 所以判定要放在能承受"结构化比较"的地方；聊天适合讨论，不适合裁定 | 见第三节抄来的 HITL 共识：把 agent 动作当 PR 审 |

**但有个前提必须一起接受**：界面不能假装 AI 是实时的。见下一条。

### 2. 交互强度：做不到"实时 AI 编辑"，只能做"异步工单"

**[码]** 每一次模型调用 —— 包括"改这一段" —— 都走 `make_client` → `DshClient` →
起一个 `dsh --profile headless --json -` 子进程（`scripts/utils/dsh_client.py:591`，
`timeout` 默认 1800 秒，headless 无交互式续接，一次调用只跑一个任务）。

也就是说：**改一段的代价是冷启动一个 agent 进程**，不是一次补全请求。

这条决定了一切：

- 不能做"选中就出候选"的即时体验（那是 Cursor 的模型，不是墨坊的）；
- 正确的形态是：**提交 → 队列 → 完成通知 → 回来逐条裁定**；
- 好消息是这套状态机已经存在（`paragraph/preview` 返回 job，`paragraph/pending` 列候选），
  界面要做的是**把它显示出来**，不是发明新机制。

### 3. 每个环节都无懈可击了吗：没有。而且现在有一条是阻断级

**[码]** 我刚只读查了 `logs/runs.db`：

```
chapter_log  0 行
cost_log     4 行
runs        15 行
```

`chapter_log` 是"真写出一章"的唯一凭据。它是 0 —— 意味着**`engine: dsh` 下，
一章都没有真正落盘过**。这不是"界面问题"，是链路终点没验过。
`未完成总账` 里 E2/B 组的写法是"等 DSH 插件"，但插件和"跑出一章"是两件事：
插件是给人用的入口，`chapter_log` 是引擎本身。后者不验，前面所有界面都在演示一个
没跑通的系统。

其余断点见第三节。

## 五、重排后的五层（替换原来的 6 轮）

顺序不可换：**地基没定就改页面，等于把返工做两遍。**

### L0 形态与信息架构（只出文档与导航图，不动代码）
- 定第一屏（问卷 S2）
- 15 个入口收成 3 组（S9）
- 确立三张面：**读一章 / 改一句 / 判一章**
- 交付：页面清单，每页一句"用户在这里做什么"。写不出这一句的页面，合并或删。

### L1 基座（一次解决原第 2/3/5/6 轮）
- shadcn-vue + Tailwind（你 11-23 已批 Q2=B，至今未动工：`console/package.json` 里没有 tailwind）
- 令牌：8pt 间距栅格 · 字号 7 档（已有）· 行高 3 档 · 圆角 2 档 · 阴影 2 档 · **强调色 1 个**
- 组件：按钮三档、输入、下拉、开关、徽标、卡片、表格、空态、骨架、提示条
- 判据（会失败的反证）：未定义 CSS 变量必须红；新组件不许自写近似样式；
  截图基线前后对比
- 这一层做完，栅格、层级、表格密度、图标这四件事大部分自动消失 —— 不是靠逐页调。

### L2 三张面（每张一轮，各出一组同页前后截图）
1. **读一章**：全屏阅读、行内标记可一键关、右栏问题清单、j/k 翻段
2. **改一句**：选中 → 动作条 → 进队列 → 回来逐条裁定（改前/改后 + 字数差 + 来源）
3. **判一章**：一句话结论 + 折叠明细 + 一键转批注

### L3 其余页面套用
素材 / 设定 / 大纲 / 分章 / 审稿 / 校对 / 文风 / 成本 / 项目 / 设置 / 导出。
每页只做两件事：换成组件、删掉重复入口。**不新增功能**。

### L4 护栏与目检
- 真客户端截图基线（已经有 `--remote-debugging-port` + CDP，别再拿 mock 截图充数）
- 四条常驻护栏：令牌白名单 / 组件复用 / 文案口径 / 数字格式
- 内置手册 10 篇与界面文案同批改

### 每轮的验收口径（统一，不容许改）
1. 同页**改前/改后**截图各一张，同一窗口尺寸；
2. 四条护栏全绿，且**至少一条反证**（改源码能变红）；
3. 一句话说明"这一轮让读一章 / 改一句 / 判一章 的哪一步更短"。
   说不出来 = 这轮不该做。
