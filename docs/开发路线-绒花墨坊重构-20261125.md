# 绒花墨坊重构路线（v2 · 作者已拍板四条）· 2026-11-25

> 依据：2026-11-25 打包态客户端实跑（《测试用书-1125》，44 篇素材，engine=dsh/headless）。
> 全部数字来自 `logs/runs.db` 与本次实测，不是设想。
> v2 变化：按作者 2026-11-25 17:55 的四条拍板重写（审批门不降 / 整卷一会话 / 不换模型 / 半成品导出默认关）。

---

## 0. 一句话

**绒花墨坊退成“状态机 + 账本 + 闸门 + 编辑台”，把"写"整个交给 DSH 会话；一卷是一个会话，会话靠 `--session-id` 持久化，换会话靠接力包续上。**

它现在的身份是“流水线 + 模型代理”，两个都不是它该干的活。

---

## 1. 诊断：三个矛盾

### 矛盾一：模型是 agent，调用方式是 completion

| 现在的做法 | 背后的假设 | 在 dsh 上的后果 |
|---|---|---|
| 一章拆 6 段群，每群一次调用 | 模型写不长 | 6 倍固定开销 |
| 每群重发全书上下文（单次输入 10.5 万 token） | 模型不记得上一轮 | 输入 ×6、prefill ×6 |
| 每次调用起 `cmd → DeepSeek Harness.exe → node`，且**不传 session-id** | 模型是个无状态 HTTP 端点 | 36 次冷启动 + 36 次失忆 |

**关键事实（2026-11-25 实测）**：`dsh --profile headless` **支持 `--session-id <id>`**——

> `dsh --profile headless --session-id session-… "continue"` — resume an existing Session

也就是说：模型不是不记得，是**墨坊从来没给它机会记得**。每次调用都是新会话。

**2026-11-25 实测补充**（`dsh --profile headless --json "Reply with exactly: OK"`）：

- 第一条事件就是 `{"type":"session","sessionId":"session-29cd2fdd-…","cwd":"…"}`；
- `final` 事件也带同一个 `sessionId`；
- `step_end` 的 `usage` 给 `{inputTokens, outputTokens, totalTokens}`。

结论：**"先建会话、从事件里拿 id、下次带 id 续"这条路可行**；"水位"也有实测数可算（不用估）。
另一个数字：**一次"只回 OK"的空任务，inputTokens 已经 26,383**——这是系统提示 + AGENTS.md 的固定开销，也是拆 6 群成本爆炸的原因之一。

### 矛盾二：长文本在文件里，却每轮重发全书

实测：单段群输出 **74,628 token**，正文 **1482 字 ≈ 2,200 token**。

> **正文占输出 3%，97% 是思考——其中大部分是"把同一本书重新理解一遍"。**

四个阶段的恶化曲线：

| 阶段 | 输出 token | 产物 | token/字 |
|---|---|---|---|
| 1 素材归并 | 105,183 | ~3 万字 | ~3.5（正常） |
| 2 整体大纲 | 132,402 | ~8,500 字 | ~15.6 |
| 3 逐章细纲 | 111,856 | ~3,300 字 | ~34 |
| 4 正文 | 74,628 | 1,482 字 | **50** |

**同一个引擎、同一个模型**，任务越偏创作，重复思考越多。不是模型的问题，是"每轮重新建立理解"的问题。

### 矛盾三：承诺是成品，出口只有一个

7 阶段全绿才导出 Word。这次阶段 1–3 全部成功、大纲与细纲都在盘上，但 `output/` 是空的。

（作者拍板：**半成品导出默认关**——离开墨坊，那些中间件不是通用件，不要拿它当交付。）

## 2. 目标架构

### 2.1 职责切分（按"确定性"分，不按"阶段"分）

| 归墨坊（确定性，唯一真源） | 归 DSH（判断，天然多轮） |
|---|---|
| 状态机：哪章落盘、哪步做完 | 写这一章 |
| 账本：token / 产物 / 快照 | 自检长度、不够就续 |
| 闸门：花多少、要不要停 | 评：这章哪里不对 |
| 编辑器：大纲/章节/素材的界面与落盘 | 改：按意见重写某段 |
| 审批：作者签字的每一道门 | 讨论、提方案、自己找证据 |
| **会话账本：session_id / 章号 / 接力点** | **在会话里连续写下去** |

**交接面是“产物文件 + 状态 + session_id”，不是“提示词”。**

### 2.2 三条通道

| 通道 | 用途 | 现状 |
|---|---|---|
| **整卷会话（主）** | 一个 session_id 写一整卷；每章一次 `dsh --session-id` 调用 | 能力已有，墨坊没接 |
| **API 式（回退）** | `/stage/N/run`，批量/自愈/无会话环境 | 已有，假设要换 |
| **读改式** | `mofang_*` 工具 / MCP，改稿与查看 | 已有，保留 |

### 2.3 数据流

```
素材 ──► 设定集 ──► 大纲 ──► 逐章细纲
                                  │
                                  ▼
                  ┌──────────────────────────────┐
                  │ 卷会话（session_id 持久化）   │
                  │  第1章 → 第2章 → … → 第50章  │
                  │  每章：读决策+最近2章+本章细纲 │
                  └──────────────┬───────────────┘
                                 │  上下文到水位 / 章数到上限
                                 ▼
                  ┌──────────────────────────────┐
                  │ 接力包 → 新 session_id        │
                  │ decisions.md + 最近3章 + 进度 │
                  └──────────────┬───────────────┘
                                 │
                       合并 ──► Word（全章齐才导）
```

## 3. 六个改造（v2：审批门不降，删掉换模型）

### 改造 1 · 章是原子单位（P0）

**现状**：`chapter.enhanced_mode: true` 默认把一章拆 6 段群，逐群调用、逐群落 `_parts/`，最后拼装。

**目标**：
- `engine: dsh` 下**默认整章单发**（一次调用写完整章）。
- 加强模式**降级为补救**：只在"整章产出不足字数"时启用，且最多补一次。
- `_parts` 机制保留但默认不用。

**判据**：
- 单章端到端 ≤ 5 分钟
- 单章 token/字 ≤ 8（当前 50）
- 6 章全书 ≤ 40 分钟

**改动点**：`stage4_writing.py` 的拆群入口按 `chapter.enhanced_mode` + 引擎判据；`config/system.yaml` 默认值改 false。

**施工状态（2026-11-27）**：`chapter.enhanced_mode` 默认 false；新增
`dsh.text_writing: true`，stage4 整章/段群改成“一次纯文本 completion + 墨坊 Python 落盘”
（`DshClient.run_text_task_stream`，所有工具禁用）。判据见 `docs/agents/dsh-text-writing.md`
与 `tests/unit/test_stage4_text_writing.py`。真机单章 ≤5 分钟待实跑确认。

---

### 改造 2 · 上下文按需读（P0）

**现状**：每个段群的提示词把设定集、大纲、前文全量塞进去（单次 10.5 万 token 输入）。

**目标**：
- 任务书只写**"读哪几个文件"**，不写文件内容；
- agent 用 `read_file` 自己读需要的部分；
- 一章的输入预算 ≤ 3 万 token。

**判据**：单章输入 token ≤ 30,000（当前 105,579）。
**改动点**：`dsh_client.write_task` 的输入文件段改为"只给路径 + 说明"，与 `engine: self` 的任务书风格对齐（那套已经是"给路径不给内容"）。

---

### 改造 3 · 整卷会话 + 跨会话接力（P1，**v2 核心**）

**现状**：每次调用是一个新 dsh 进程、新会话，写完即失忆。

**目标**：

1. **一卷一个 session_id**（墨坊生成并记进 `progress.json`，如 `nf-测试用书-1125-v1`）。
2. 每章一次调用：`dsh --profile headless --session-id <id> --json -`，任务书只说"写第 N 章，读决策 + 最近 2 章 + 本章细纲"。
3. **暂停不丢**：章与章之间停；会话状态在 DSH 侧持久化，下次带同一个 session_id 继续。
4. **换会话**：上下文到水位或章数到上限 → 生成接力包，开新 session_id；接力包 = `decisions.md` + 最近 3 章原文 + 进度 + 未回收伏笔清单。
5. 换会话后第一件事：agent 读完接力包，先**复述**"现在到哪了、谁在做什麼、下章要接什么"，再写第 N 章。

**判据**：
- 第 50 章的输入 token ≤ 第 1 章的 3 倍（会话内自然增长）；
- 换会话后首章的字数/质量不低于前一章；
- 暂停 24 小时后再继续，能接上（不需要重读全书）。

**改动点**：
- `scripts/utils/dsh_client.py` 增加 `session_id` 参数与 `--session-id` 传递；
- `nf_api` 新增 `/chapter/write`（带 session 语义）与 `/session/rotate`；
- `progress.json` 增加 `sessions: {volume: {id, last_chapter, tokens}}`；
- GUI 每章卡片显示“本卷会话 · 第 N 章”。

---

### 改造 4 · 决策文件，不是摘要（P1）

**现状**：`data/summaries/rolling.md` 是模型的第二次生产——先想一遍、写成摘要、下一章把摘要喂回去、再想一遍。

**目标**：
- 新增 `data/canon/decisions.md`：**只记结论**，不记过程。
  - 人物语气：周砚清说话不超过 12 字、从不问句
  - 伏笔状态：f002 已在第 3 章回收
  - 禁用词：本书不出现"灵力/封印"
  - 时间线：穗历 940 冬 → 941 春
- 每章会话结束时，agent **追加**（不重写）本卷新增的决策。
- 下一章/下一卷读决策，不读全书。

**判据**：第 6 章会话的输入 ≤ 第 1 章的 1.5 倍。

**改动点**：新增 `utils/canon.py`；stage4 的任务书把 "读 rolling.md" 换成 "读 decisions.md"。

---

### 改造 5 · 闸门与通知（P0）

**现状**：
- `per_request_max_tokens` 默认 10 万，阶段 1 实测 13.3 万入 / 10.5 万出 → 撞穿；
- 熔断后 `paused` 没有界面清除入口，点“恢复运行”等于点了没反应；
- 通知只说"卡住了"，不说"怎么办"。

**目标**：
- 预算闸按**单章预算**计（不是单请求），默认 20 万；
- `paused` 在界面有清除按钮，且“恢复运行”先检查它；
- 通知三件套：**卡在哪 + 我建议怎么办 + 一个按钮**。

**判据**：人为触发一次熔断，用户能在界面上一键恢复，不需要外部查文件。

**改动点**：`cost_tracker` + `orchestrator._budget_gate`；GUI 增加 `/budget/resume`（GUI-only）。

---

### 改造 6 · 会话账本与接力 UI（P2）

**目标**：界面上能看见“这一卷写到第几章 / 用了多少 token / 会话还剩多少余量 / 下次换会话在什么时候”。

**判据**：不用查文件，从界面能回答"我要不要现在换个会话"。

## 4. 审批门：保留全开（作者拍板）

`require_approval: [1,2,3,4,5,6]` **不减、不合并**，且默认全勾选。

要修的不是门数，是**门的行为**：

| 现状 | 目标 |
|---|---|
| 点“确认阶段 1”只写 `approved`，不自动继续 | 点确认 = **确认 + 启动下一阶段**（一个动作） |
| 门被预算熔断遮住，用户看不到"待确认" | 熔断与审批分开显示，各自可处理 |
| 门的状态没有入口 | 流水线页每道门显示“等待你确认 / 已确认 / 被挡住（原因）” |

判据：6 道门，每道门点一次就继续，不需要外部再发请求。

## 5. 整卷工作单元：一次会话的完整流程

### 开卷（一次）

墨坊生成 `session_id`，写进 `progress.json`，界面上显示“第 1 卷会话已开”。

### 每章（循环）

**输入（墨坊准备，≤3 万 token）**：

```yaml
卷: 1  章: 3  标题: 四十秒、北堤与垂星台
细纲: data/outline/chapters/03.md
必读:
  - data/canon/decisions.md     # 只读结论
  - data/chapters/raw/02.md     # 上一章（衔接）
目标: 7000-12000 汉字
禁: 本章不按下静默令
```

**过程（agent 在会话里）**：

1. 读 3 个文件
2. 写第一稿
3. `wc -m` 数汉字 → 不够 → 续写（不重写）
4. 自查：本章细纲的 4 个事件是否都写了？伏笔有没有漏？
5. 落盘 `raw/03.md`
6. 追加 `canon/decisions.md`（本章新增的 2–3 条）

**输出（墨坊收）**：文件 + token + 状态；界面卡片“第 3 章 · 8,412 字 · 3 分 12 秒”。

### 换会话（触发式）

| 触发 | 动作 |
|---|---|
| **上下文水位 60%**（作者拍板 2026-11-25） | 生成本卷接力包 → 开新 session_id |
| 作者手动“换个会话” | 同上 |

> 60% 的分母不是"模型窗口"（墨坊拿不到），而是**本会话累计输入 token / 自设上限**。
> 上限初值按实测取：今天单次输入 13–20 万 token，先设 **25 万**，跑两卷后用实测曲线校准。
> 校准规则：若换会话时实测累计 < 18 万（换早了）或 > 30 万（换晚了），调整上限并记进文档。

**暂停粒度（作者拍板）：随时可停。** 写到一半也可以停，残稿落 `data/chapters/raw/.partial/第N章.md`；
下一轮从残稿续写，不重写已写部分。字数统计把残稿计入“本章已写”。这是"不丢进度"的具体含义。

接力包四件：`decisions.md`、最近 3 章原文、进度（写到第 N 章）、未回收伏笔清单。

### 收卷

全书章节齐 → 合并 → Word。**全章齐才导**（作者拍板：半成品默认不导）。

## 7. 分期

### P0（1–2 天）：先能跑出一本书

- 改造 1（整章单发）+ 改造 2（按需读）+ 改造 5（闸门与通知）
- **判据：6 章全部落盘、能导出 Word、总耗时 ≤ 1.5 小时、单章 token/字 ≤ 8**

这一步做完，产品就"能用"了。哪怕还是老架构（无会话），至少能交货。

### P1（3–5 天）：整卷会话

- 改造 3（session-id）+ 改造 4（决策文件）
- **判据：换会话按 60% 水位触发（偏差 ≤10 个百分点）；换会话后首章质量不降；随时暂停后 24 小时能接上；半章残稿不丢**

### P2（1 周）：收尾与打磨

- 改造 6（会话账本 UI）
- 审批门行为修正（确认即继续）
- 界面：进度一条线、按钮三态、通知带建议
- 素材页签人话化

### P3：不做（明确排除）

- **不降审批门**（作者拍板全留、默认全勾）
- **不换模型**（模型没问题，是墨坊的调用方式有问题）
- **不加新功能**（讨论、判定引擎、多版本对比维持现状）
- **不默认导出半成品**（离开墨坊不是通用件）
- 不重写 GUI、不动 vault 边界、不碰 prompts 前缀纪律

## 8. 风险

| 风险 | 影响 | 对冲 |
|---|---|---|
| dsh 会话的上下文增长由 DSH 自己管理，墨坊不知道它何时压缩 | 接力点可能估错 | 墨坊记录"每章实际输入 token"，用实测曲线定水位 |
| 一卷 50 章 × 8000 字 = 40 万字，会话可能撑不到 | 中途中断 | 接力包设计成"随时可接"，不依赖"恰好写满" |
| 决策文件写歪了会传染 | 后续章节跟着错 | 只追加、每章可见、作者可改 |
| 整卷一会话跑歪要重来 | 浪费 | 每章落盘 + 快照；坏章可 reject 单章重写 |
