> 读数：`data/state/fidelity_probe.json` + `.md`。
> 样本：试跑工作区 `%APPDATA%\绒花墨坊\workspace`（**测试用书，不是真书**，12 章 / 三层齐全 / 一份成品 docx）。

## N2 · 成品与源稿的差异（原本是"说不清"）

| 项 | 数 |
|---|---|
| 成品 | `测试用书1104_完整版.docx` |
| 段落 | 成品 2722（非空 2719） / 源稿 2729 |
| 差异 | 14 处 = **内部注释 12** + **成品附加页 2** + **真丢失 0** |
| 汉字 | 源稿 49,014 / 成品 46,114（差 −2,900，其中注释里 2,914 字） |

结论：**保真没问题，问题在口径** ——

- 每章末尾的 `<!-- summary: … -->` / `<!-- quality: … -->` 是流水线自己的元数据，**本来就不该进成品**；
- 成品多出来的两段是封面书名与"按 F9 更新目录"提示，属于成品附加页。

## 由此抓到并修掉一个真缺陷：R07“成品已过期”永远红

`utils/judge/artifact.py` 原来把内部注释算进源稿字数，于是**每一本正常导出的书都被判过期**：

```
修复前（12 章）：第1章 成品 4343 / 源稿 4512 → 过期
                第2章 成品 4191 / 源稿 4404 → 过期
                …12 章全红
修复后（12 章）：docx_words == src_words（4343 == 4343），stale = False，"成品与源稿一致"
```

三处改动：

1. **两边都剥掉 `<!-- … -->` 再数字数**（`strip_internal_comments`，幂等）；
2. 容差从 1% / ≥30 字收紧到 **0.5% / ≥10 字** —— 原来的容差太松，
   成品里真丢一整段对白（30~60 字）都会被吃掉，判据等于不存在；
3. 章号清单从"只列 raw"改成 **raw ∪ refined** —— 原来 raw 被清理、只剩成品层的工作区循环一次都不跑，
   直接报"一致"（假绿比报错更糟）。

回归锁：`tests/unit/test_artifact_fidelity.py`（9 条，含**反例**：故意让成品少一段，必须判过期并给出字数凭据）。

## N4 · 存量双版留存率

- 12 章，`raw` / `checked` / `refined` **各 12 份**，raw + refined 齐全 **12/12 = 100%**
- 结论：**存量可回放** —— 版本回溯不是"只有新写的章能用"

## N5 · 自然段切分口径

| 输入写法 | 切出段数 | 三次一致 |
|---|---|---|
| 空行分隔（`a\n\nb`） | 3 | 是 |
| 单换行（`a\nb`） | 3 | 是 |
| 混合 | 3 | 是 |

- 口径：**换行即分段**（单换行也切），空行只是"多一个空段被丢掉"；
- 两处实现（`refine_paragraph.split_paragraphs` 与 `utils.annotations.split_paragraphs`）**同源**，结果一致；
- 结论：**确定** —— "三次切分一致"这句承诺有口径可依。

## N3 / C5 · 残稿（C2）可接管性

在第 01 章的**临时副本**上截到 55%（3,125 字，收尾补个省略号模拟写断）：

| 判据 | 结果 |
|---|---|
| 残稿仍能切出可指名段 | **83 段** |
| 原件是否被判完整 | True（它是完整稿） |
| 残稿是否被判完整 | **False**（不会被当成品放行） |
| 补齐后半段后 | **True**（就地编辑真能救回来） |
| 原件被改动 | 否（sha256 前后一致） |

结论：**残稿可接管** —— "C2 只能经人就地编辑离开"这条路成立；机器不会把残稿当成品放出去。
