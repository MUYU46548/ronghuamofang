## 二、真正的距离：两个缺口 + 一个记录问题

> **口径先说清**：跑通不是问题（已试 3–4 次、出过 Word）。真正卡人的是“交稿之后”。

### 缺口一（卡死级）· 收尾没有动线

收尾要做的五个动作，散在五个页签，彼此不相连：

| 动作 | 现在在哪 | 人在这一步要干什么 |
|---|---|---|
| 看这本书能不能交 | 章节 → 判定报告（I1） | 读三档结论 |
| 看这章哪句不行 | 章节 → 单章详情（I2） | 逐条读缺陷单 |
| 看模型把稿改成什么样了 | 审稿 → 三稿对照（I6） | 看 diff，**但只能看** |
| 改 | 精修 → 段落级工作台 | 手填意见、单段/批量重写 |
| 改完再验 | 回“章节”刷新判定 | 重跑判据 |

**这不是"功能不存在"，是"该按的那个按钮不在你眼前"。** 你说"界面上什么都点不了，等于功能不存在"，我理解成：**能点的太多，不知道下一步该点哪个** —— 而收尾是一个有明确顺序的动作链，界面却按功能模块切。

对照 10-28 的交互定义：它已经设计了 I1–I6 六个落点、并明确"不新增顶层页签"。**问题不在设计，在于六个落点各自成立、彼此没有串成一条路。**

**为什么它卡死**：收尾工时是全产品唯一可达的验收指标（§三判断一）。这个指标测不出来，每一版"改进"都无法判断是改好了还是改坏了 —— 只能靠"读两章感觉一下"，而那个判据永远不会亮（你的原话：AI 写的我都读不下去）。

### 缺口二（信任级）· 改稿与裁决没有分离

| 现状 | 位置 | 后果 |
|---|---|---|
| 模型自填 `<!-- quality: X/10 -->`，系统按 ≥6 判 `ok`，<6 判 `needs_rewrite` | `prompts/stage4_writing.md:140`；`stage4_writing.py:1132` | 模型给自己打分的稿子，状态就是"完成" |
| 阶段 5 由模型改稿，改完的 `checked/` 直接成为下游输入 | `stage5_check.py:5` | 模型替你做了"改不改、怎么改"的决定 |
| 确定性判据很厚，但**只做诊断，不做裁决** | `utils/judge/*`、`verify_chapter`、`homogeneity`、`story_state` | 判据说"这章有 7 处要改"，状态栏仍可能写"完成" |

【判断】该动的不是"取消自动改稿"（作者已拍板保留，见 §三判断三），而是**把改稿结果降格为提案**：模型可以改，但改完的每一处要能被你接受或拒绝，**未经裁决不进成品**。

### 记录问题（不是能力问题）· 全链结果不可复验

| 项 | 值 |
|---|---|

**为什么仍然要记一笔**：不是怀疑能不能跑，而是“改了代码之后，产出有没有变好”这件事，现在只能靠感觉。本项目自己的纪律是“验证优先”“不要假成功”——延伸一步就是：**每次全链的结果要留下一份可对照的记录**（哪版代码 / 哪套素材 / 几章 / 多少字 / 缺陷数 / 你判了几句可用），否则下次改动没有可比对象。

## 三、方向判断（选择什么、放弃什么）

> 你说"钱必须花在规划上，选择大于努力"。以下三条是我愿意押的判断，不同意请直接推翻。

### 判断一：“实用”的定义必须换，否则永远验收不过

你的原话是"全世界 AI 写的我都读不下去"。这句话同时说明了两件事：

- **相对基线**：从"完全不可读"到"能看一点"是巨大进步；
- **绝对基线**：仍然"读不下去"。

只要验收标准是"读完觉得好"，**这个判据永远不会亮**（交接单 5.1 已自我否掉一次，是对的）。而在不自训模型的前提下，"写得好"不在可达范围内。

**所以唯一可达、可测、且与你"就是快"的定位一致的目标只有一个**：

> **从 AI 交稿到你能发出去，人花多少小时。**

这也正是交接单 6.1 与 6.2 的答案：**6.2 不该被回答成"质量的量化阈值"，而该被回答成"收尾工时的量化阈值"。** 事实矛盾数、AI 腔密度这些指标是**手段**（帮你更快找到要改的地方），不是**验收标准**（书好不好）。

### 判断二：功能线冻结，直到收尾工时被测出来

v0.8 / v0.9 上还挂着 6 项没做：写作中干预、逐章验收开关、角色关系网约束、去 AI 腔改写器、读者视角审稿、写作 Skill 导入。

**这 6 项全部预设"稿已经够用"** —— 而稿够不够用、差的那些量你改起来要多久，一次都没测过。

【判断】**在收尾工时测出来之前，这 6 项一项都不做。** 理由不是"优先级"，是：没有基线的改动，好坏都判断不了。这个项目已经付过一次代价（09-29 才查出 stage5/6 空壳的真根因是批次列表写裸文件名）—— 不是能力不足，是**缺一个能对照的样本**。

### 判断三（已被作者否掉一半，保留一半）：不动流水线，但要给改稿装"逐条裁定"

**我原本建议**阶段 5 降为"只出缺陷单"。**作者 2026-11-01 拍板：保留自动改稿。**

所以验收权不在"取消改稿"，而在**让改稿变成可逐条裁定的提案**。形态参照 Revise（修订模式，逐条接受/拒绝）：

| | 现在 | 拍板后的目标 |
|---|---|---|
| 阶段 5 干什么 | 模型读 raw → 直接改写 → 写 checked/ | **不变**，仍自动改稿 |
| 改的结果算不算成品 | 算。checked 一路变成 refined → Word | **不算**。checked 是**提案**，未经裁定不进成品 |
| 人做什么 | 只能看 diff（I6） | 逐条：接受 / 拒绝 / 换一种改法 / 不改 |
| 成品从哪来 | refined（模型改了两遍的） | raw + **人接受过的改动** |

**代价必须说明**：这条路比"只出缺陷单"难一个量级。

- "只出缺陷单"只需定位（已有一半：`judge` 每条命中带段号+原句）；
- "逐条 diff 裁定"需要**稳定的段落/句子锚点** —— 模型改动后仍能认出"这是原来第 7 段第 2 句"，人拒绝时能精确还原原文。这正是交接单 6.3 至今未决的题。
- 工程量从 3–5 天变成 **1–2 周**，且 V3 的验收从"检查清单"变成"锚点在模型改写后仍稳定"。

**我的解法（待评审）**：不追求"任意改写后仍稳定"，而是**先锚定 raw，把 checked 看作对 raw 的补丁集**：

```
raw/07.md  ──(模型改写)──▶  checked/07.md
                                 │
                       逐段 diff → patch[01..N]
                                 │
                    {seg: 7, old: "...", new: "...", why: "..."}
```

- **锚点取 raw 的段落序号 + 该段首 12 字 sha**，不追"句子级"；
- 段落没变 → 无 patch；段落被改 → 一个 patch（整段替换，不拆句）；
- 拒绝 = 丢弃该 patch，raw 原文不动；接受 = 替换该段；
- 段落被模型**合并或拆分** → 标 `structure_change`，**不许自动合入**，强制人工确认。

**为什么锚到段落而不是句子**：段落是 markdown 里天然的分隔（`\n\n`），改动前后段落数大多守恒；句子级锚点在中文改写里几乎必然断（模型改标点、拆长句都会断）。**锚点越细，误判越多，人越关掉它**（交接单 6.5 说的问题）。

**风险（须记入 V3）**：模型大幅重写时整段 patch 会很大，人就懒得逐条看，变成"一路接受"——等于变相放弃裁定权。**缓解**：patch 里标 `改动比例`，>60% 的段落折叠并提示"这段基本重写了，建议直接读"。

### 不建议做的三件事（顺手否掉，免得反复讨论）

| 不做 | 理由 |
|---|---|
| 补齐 23 个无入口端点 | 入口不是越多越好。`/plan` 该进（有明确动作），`/kb/search` 该进（收尾时要查设定），其余按需。**"补全入口"会把 16 页签变成 23 页签** |
| 照抄 NovelAI / Sudowrite 的"边写边介入" | 与"就是快"直接冲突（交接单 5.4 已否决，我同意） |
| 让判据变成"打分" | 本项目最值钱的资产就是"只产依据、不产档位、每条命中必须定位到段号原句"。改成打分等于自毁护城河 |

| 成本 | 3 章 ≈20 万 token、5 章 ≈32–35 万（`estimate_tokens.py` 实测口径，订阅内 ¥0）；你的时间 ≈1–2 小时（读 + 精修 2 章） |
| 验收 | 四段耗时有数、每段能说出"卡在哪一句话上"，并按附录 C 模板记进 `docs/evidence/` |
| **反证** | 若四段加起来 <45 分钟/2 章，说明"收尾工时"不是主要矛盾 → **本方案作废，重排优先级**。这条必须留着，防止我把它做成一厢情愿 |

**为什么必须掐表而不是拍脑袋**：整份规划只押了一个指标，就是这个数。它错了，后面 V2/V3 全白做 —— 所以要给它留一条"会失败的反证"。

### V2 · 收尾动线（1–2 周）

**目的**：把五个页签的入口串成一条“第 N 章 → 读 → 判 → 改 → 验”的路。

不做新页签（沿用 10-28 的 I1–I6 纪律），做法是**在“章节”页签里加一个"本章收尾台"视图**：

```
┌─ 左：正文（raw 或当前稿，可切层）  ─┬─ 右：缺陷单（判据命中，逐条带段号+原句）─┐
│  段落可点选 → 高亮对应缺陷          │  每条：为什么 / 怎么改 / [采纳] [换改法] [不改] │
│  选中段 → 就地编辑 / 填意见重写      │  顶部：三档结论 + 本章还剩 N 处待处理        │
└──────────────────────────────────┴────────────────────────────────────┘
                    底部：[重跑判据]  [导出本章]  [下一章 →]
```

| 项 | 内容 |
|---|---|
| 复用而非重建 | I2 单章详情、I6 三稿对照、ParagraphRefinePanel 的段落重写、judge 的缺陷单 —— **四块已有，只做"并置 + 导航"** |
| 新增的最小件 | ① 缺陷 ↔ 段落的双向定位（点缺陷跳到段，点段筛缺陷）；② 缺陷的处理状态（未处理/已采纳/已忽略），落 `data/state/`；③ `[下一章]` 连续推进 |
| 明确不做 | 不做富文本编辑器（正文是 markdown，改就用 textarea）；不做多标签/撤销树；不做协作 |
| 验收 | 你从"打开界面"到"改完一章并确认判定更新"，**不需要切页签**；缺陷单里每条都能一键定位到原句 |
| **反证** | 删掉"缺陷→段落定位"这一条，若流程仍能跑通，说明这个视图是装饰品 → 判失败 |

**判断**：V2 的价值不在"多一个界面"，在于它把"收尾"从**五个功能**变成**一个动作**。这是你"看不到、点不了"的真实解法。

### V3 · 改稿可裁定（1–2 周，按 D2 拍板调整）

> 因作者决定**保留自动改稿**，V3 不再"拦改稿"，而是"给改稿装逐条裁定"。工程量由 3–5 天升到 1–2 周。

| # | 做什么 | 验收 | 反证 |
|---|---|---|---|
| 1 | **段落锚点**：`checked` 视为对 `raw` 的补丁集，锚 `raw` 段落序号 + 首 12 字 sha；段落被合并/拆分标 `structure_change` | 模型改写后，未改动的段落 100% 能对上原段号；合并/拆分**必须**被标出 | 锚方案换成"句子级"后，中文改写（改标点/拆长句）导致锚点全断 → 说明段落级是必要的 |
| 2 | **逐条裁定**：每处 patch 可接受 / 拒绝 / 换改法 / 不改；未裁定的 patch 不进成品 | 拒绝全部 patch → 成品正文 == raw 原文（逐字一致） | 拒绝后成品与 raw 有任一字符差异 → 红 |
| 3 | **大改折叠**：patch 改动比例 >60% 的段落折叠并提示"基本重写了，建议直接读" | 造一段全改写 → 必须折叠并提示 | 不折叠时人一路点"接受" → 说明判定阈值失效 |
| 4 | 模型自评分降级为**参考信息**，不再决定 `status` | 自评分 9/10 但确定性判据报 7 处缺陷 → 章状态**不是** `ok` | 把闸门改回看 quality → 断言必须红 |
| 5 | 章状态只由"确定性判据 + 人的裁定"产生，口径写进 `caliber` | 口径变更后存量重判（已有 F09，复用） | 造一章判据全过但人标"要重写" → 必须显示"要重写本章" |
| 6 | `/setting/canon`、`/kb/search` 给入口（收尾时要查设定） | 收尾台内可弹出正典事实 / 搜知识库 | 无 |

**最大风险**：patch 太碎人就一路接受，太粗人就懒得看 —— 等于变相放弃裁定权。这是"误报多了作者就会关掉它"（交接单 6.5）的同款病，**必须在 V2 的收尾台上实测一次再定阈值**。

### V4 · 之后（明确排在 V1–V3 全绿之后）

## 五、"可以实用"的判据（怎么算过了）

> 阈值分两类：**结构性**（现在就能定）与**数值型**（V1 标定后校准，此处先给暂定值，不许提前当结论用）。

| 维度 | 判据 | 类型 |
|---|---|---|
| 能跑通 | 全链一次跑完，退出码 0，Word 能打开、目录与正文就位（**已达成**，作为回归项保留） | 结构 |
| 字数合格 | ≥5000 字的章占比 ≥80%（当前口径 `chapter.target_words=[5000,9000]`） | 数值·暂定 |
| 判据可信 | 系统判"可开始逐字改"的章，你否决 ≤1/6 | 数值·暂定 |
| 收尾可承受 | **单章收尾净耗时 ≤ 你写同章耗时的 40%**（这是替换"真人一半水平"的可测形态） | 数值·V1 定 |
| 收尾不倒退 | 改完一章后，判定缺陷数**净下降**（不是"改完又冒新的"） | 结构 |
| 无假绿灯 | 每条判据都有"会失败的反证"测试；`release-check` 全绿 | 结构 |

**注意**：上表刻意不含任何"文本质量分数"。理由见 §三判断一。
