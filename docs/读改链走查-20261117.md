# 读改链走查（2026-11-17，按暮雨“你自己走一遍”）

> 目的：把“批注 → 等 AI → 改完”这条链上**系统替你做了什么、你只能自己扛什么**摊开。
> 全部结论来自代码与落盘位置，不靠印象。

## 一、有两个入口，语义不同（这是第一处坑）

| 入口 | 端点 | 行为 |
|---|---|---|
| 章节页 → 编辑器 → 选一段 → 写意见 → 让 AI 只改这一段 | `POST /chapters/paragraph/preview` | **只算不落**：候选进 `data/state/para_pending.json`，正文一个字不动；再点“采用”才写 |
| 精修页签（ParagraphRefinePanel） | `POST /refine/paragraph` | 走 `run_paragraph_refine(preview=False)`：模型写回整章后**直接落盘**（旧稿进 `history/`），没有采用步骤 |

同一个心智（改这一段），两条行为。第二条没有“先看再落”的机会。

## 二、一条完整的“只算不落”链路（逐步，含落点）

1. **点“让 AI 只改这一段”** → 请求体只有 `{chapter, paragraph_index, feedback, annotation_id?}`。
2. **先备份整章**：`data/chapters/history/chNN_vM.md`。
3. **写任务文件**：`data/state/tasks/stage4_refine_chNN_pK.md`，内容是：
   整章正文（`{{current_chapter}}`，**不只目标段**）+ 目标段原文 + 你的意见原文（`{{feedback}}`）
   + 本章大纲路径 + 设定集路径 + 候选文件路径。
4. **调模型**：要求它**把整章写回文件**（目标段改、其余逐字不变），并另写一个文件放 3 条候选（`===CAND===` 分隔）。
5. **确定性闸**：段落数变化 >2 → 判失败、保留备份（防“整章被重写”）。
6. **只算不落**：把整章回滚到备份，候选只进 `para_pending.json`（带 `feedback` 与 `context`）。
7. **界面能看到的**：改前 / 改后 / 3 条候选 + `context` chiclets（整章正文 N 段 M 字、本章大纲、设定集，
   以及“这次没带：上一章衔接段 / 滚动摘要 / 范文”）。
8. **采用**：`POST /chapters/paragraph/apply`（`confirm:true`）→ 冲突检测（这一段在候选生成后又被改过 → 409 +
   现在/候选基于/候选 三份证据）→ 写回 → 旧稿进 `history/`；**放弃**走 `/drop`，正文不动。

## 三、你问的两件事，直接回答

### (a) AI 到底收到没有

- **能证“送到”**：任务文件里有整章 + 目标段 + 你的意见原文；候选记录里存了 `feedback` 与 `context`，
  界面能显示出“这条候选是按哪条意见、带了什么上下文生成的”。
- **不能证“懂了”**：模型回来的只有“改写结果 + 3 条候选”，**没有一句“我理解你要改的是 X”**。
  所以“收到没”可证，“理解对不对”只能等你读 diff。

### (b) 改完还要不要再改

批注状态机（`utils/annotations.py`）：`open` →（生成候选即）`addressed` →（你手点）`resolved`。
设计上是“生成候选 ≠ 你满意”，但落到这条链上有两个洞：

1. **采用候选后状态不动**：`/chapters/paragraph/apply` 不碰批注状态，也不会重算任何指标。
   于是一条批注会停在 `addressed`，你还得逐条手点 `resolved`，而点的时候心里没底。
2. **没有“按原批注重算”的闭环**：批注若是“连排对白太多 / 段末短句太多”这类指标命中项，
   改完**没人再算一次那个指标**。0.9.3 的分布型指标（`utils/judge/structure.py`）本来就能算，
   只是没接在“采用之后”这一步。

结论：现在“要不要再改”完全由你读 diff 判断，系统一侧没有闭环。

## 四、三个真问题（按对“改”的伤害排序）

| | 问题 | 证据 |
|---|---|---|
| A | 采用后不重算、不自动收口，addressed 停在半路 | `refine.py::handle_paragraph_apply` 只写正文；`annotations.mark_addressed` 只在 preview 成功时调用 |
| B | 两个入口语义不同（一个先候选、一个直接改盘） | `ChapterEditor.vue` → `/chapters/paragraph/preview`；`ParagraphRefinePanel.vue` → `/refine/paragraph` → `preview=False` |
| C | direct 引擎 + 长章会截断 | 任务要求模型吐**整章**（4000–7200 汉字），模板 `max_tokens: 4000`；截断时回执只说“段落重写子会话失败”，不说被截断（hermes 引擎无此旋钮，但慢） |

## 五、最小改法（都在“改”这条链上，不属于“跑”）

1. **采用后按原批注重算指标**：达标 → 自动 `resolved` 并显示“指标已回到线内”；不达标 → 保持 `open`
   并显示“仍越线（连排对白 3 处）”。这一条直接回答“还要不要再改”。
2. **精修页签也走 preview**（或明确改名“直接改正文”，默认关闭）。
3. **失败回执带原因**：截断 / 超时 / 段落数变化，三种分开说；并在开跑前算一遍“这次要吐整章，
   预算装不装得下”，装不下就拒（与 stage5/6 的预算—篇幅校验同一口径）。
4. （可选，成本最低）**候选卡加一行“模型复述的修改点”**：让它先说自己理解要改什么，再给结果。
