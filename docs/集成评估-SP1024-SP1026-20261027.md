| ① 一致性检查 | 卡+新章 → 冲突清单（5 类，带 B 位置/A 依据/严重度） | `story_state` 账本（死亡/物品/时间锚）+ `check_chapter` 的"提没提角色"；**没有挂卡逐条比对** | ✅ **移植**（与账本互补） |
| ⑥ 伏笔台账 | 摘要/正文 → 台账增量（埋设/推进/回收/矛盾） | `utils/foreshadow.py` 从**章大纲的悬念钩子**抽（零 token）；数据源不同，正文侧是空白 | ✅ **移植**（正文侧台账） |
| ⑦ 病灶词扫描 | 词表 → 命中/密度/位置示例 | `homogeneity` 看 12-gram/句长/对话同质；**没有词表维度** | ✅ **移植**（零 token） |

## 4. 已落地的集成（可验证）

### 4.1 吃书管线

```bash
python scripts/eat_book.py init 旧稿.txt --name old-book
python scripts/eat_book.py run old-book --dry-run      # 零 token：报章数与调用数
python scripts/eat_book.py run old-book                # 真跑（config 的模型）
python scripts/eat_book.py status old-book
python scripts/eat_book.py merge old-book --yes        # 只增不改 + 写前备份
```

产物 `data/eatbook/<name>/`；代码在 `scripts/utils/eatbook/`（提示词逐字保留），
编排在 `runner.py`，LLM 适配在 `llm.py`（走 `client._post_chat`，截断即失败）。

**三条设计取舍**（都写进了 `docs/agents/eat-book.md`）：

1. 去掉 emit/ingest 文件搬运，改成进程内分批 —— 本仓不需要人工贴提示词；
2. **保留断点**：摘要落盘即算完成，失败章重跑只补它（"报错自愈"在吃书上的落地）；
3. **并库只增不改**：同名角色一个字都不动，写前备份 `data/setting/history/`。

### 4.2 病灶词扫描

- `python scripts/nfctl.py cliche [--chapter N] [--file F] [--wordlist W]`
- `quality_checklist` 末尾追加一段**只报告、不阻断**的逐章密度；
- 词表优先级：`--wordlist` > `config/system.yaml` 的 `quality.cliche_wordlist` > 内置 20 条。

## 5. 没移植的，一句话理由

- **SP-1026 全部交互模块**：本仓是「服务端真相 + 桌面端」架构，它那套 localStorage 单页
  搬过来等于重写一套并行状态；其中规划/风格/成本/多书四块本仓已经更强。
- **SP-1024 的 ④⑤**：④ 与开局方案卡重叠且是生成类；⑤ 不如 `stage4_expand`。
- **`campaign` 人机通道**：本仓有模型客户端，保留它只会多出四份文件负担。
- **Best-of-N / 溯源 / 节拍 / 引用漂移批注**：价值成立，但都需要前端或数据模型改动，
  且 Best-of-N 先要 Token 账算得过来 —— 列进下一步，不硬塞进这一轮。

## 6. 建议的下一步（按性价比排序）

1. **吃书 GUI 入口**：项目页签加「吃书」—— 选文件 → 预演（章数/预计调用）→ 跑（进度条）
   → 合并预览。理由：现在只有 CLI，而用户不用终端；`/chapters/*` 已有现成的进度与 SSE 范式。
2. **词表的 GUI 配置**：合规词表/病灶词表现在只能改 `config`，设置页加一个编辑器即可复用。
3. **Best-of-N 作为 stage4 可选开关**：只在"重写低分章"时开，先量同一章 N=3 的分数差与 token 账。
4. **选区改写的一步撤销 + 溯源**：前端小改，收益直接（用户改坏了能立即退回）。
5. **吃书末尾的 NER**：③ 之后跑一遍"正文里出现但没登记的人名/地名"，把漏网实体补进卡库。
