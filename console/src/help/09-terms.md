# 界面上那些词，到底指什么

这份不是操作步骤，是**词典**。界面上见到不认识的词，先来这里查一句；
每一篇手册和界面提示里也尽量在第一次出现时随手解释一遍。

## 一、最常撞见的几个

| 界面上的说法 | 说人话 |
|---|---|
| **流水线 / 阶段 1–7** | 一本书从素材到 Word 的七道工序。1 素材→设定集、2 全书大纲、3 逐章大纲、4 写正文、5 逻辑检查、6 润色、7 出 Word |
| **产物 / 生成的文件** | 程序跑完一步之后写到你硬盘上的东西（设定集、大纲、正文、报告）。没有产物 = 那一步还没真的跑过 |
| **审批门** | 程序停下来等你点头的地方，只在阶段 2（大纲写完）和阶段 6（润色完） |
| **打回 / 放行** | 打回 = 不满意，退回去重做（会清掉这一步和它之后的结果）；放行 = 认可，继续往下走 |
| **断点续跑** | 上次跑到哪，这次就从哪接着跑；已经写完的章不会重写 |
| **快照 / 回滚** | 快照 = 动手前把整个项目复制一份；回滚 = 拿那份复制品盖回来 |
| **精修 / 润色** | 精修 = 按你的意见改某一处（一条大纲、一段正文）；润色 = 整章过一遍文字 |

## 二、素材与设定

| 界面上的说法 | 说人话 |
|---|---|
| **结构化卡片** | 整理好格式的素材卡（有名称、类型、描述），阶段 1 会读它 |
| **原始碎片** | 你随手记的零散文字。只留档，不会直接进设定集 |
| **归并** | 阶段 1 把一堆素材卡合并、去重，整理成设定集 |
| **设定集** | 这本书的人物 / 地点 / 势力 / 概念的正式清单（`data/setting/setting.json`） |
| **正典** | 你已经定稿、后续写作必须遵守的设定。手册里说“检索正典”就是查这些 |
| **知识库** | 你的 Obsidian 库。程序只读，从不写入 |
| **词条** | 知识库里的一篇笔记 |
| **否决记录（旧称“墓碑”）** | 你否掉过的设定条目。留着它是为了防止下次归并又把同名条目带回来 |

## 三、检查与判定

| 界面上的说法 | 说人话 |
|---|---|
| **体检 / 自动检查** | 不花钱的规则检查（空泛节点、缺项、字数、重复句）。只报告，不改稿 |
| **判定** | 判断“这一章行不行”。机器只测能测的；有没有推进由你勾 |
| **三档结论** | 合格 / 需定点重写（改某几段）/ 需重写本章 |
| **回测** | 拿硬盘上现有的稿，把判定跑一遍。零花费、不改稿 |
| **判定标准** | 判合格的那几条线和界线。改它会产一个新版本，旧结论留作历史 |
| **缺陷单** | 判定给出的逐条问题清单：第几段、哪一句、为什么、怎么改 |
| **七维 / 七个角度** | 逻辑检查的七个观察面（人物、时间、因果、信息、场景、语言、推进）。每维要求引原文作证 |
| **审美五问** | 另开的五个偏“写得好不好”的问题。它不给文学分，只提示你抽读 |
| **未举证** | 模型说“这一维有问题”，但它引的那句话在正文里找不到 —— 这一维**不计分**（不是扣分） |
| **水章 / 凑数的章** | 一章里没有真正改变人物处境、信息、关系或目标的事 |

## 四、引擎与花费

| 界面上的说法 | 说人话 |
|---|---|
| **直连** | 程序自己拿你的 API Key 去调模型，按用量付钱 |
| **外部助手（子会话）** | 由你编程工具里的助手来调，走你的订阅额度 |
| **自任务（self）** | 程序完全不调模型，只写一份“该做什么”的任务书，你或别的助手去执行 |
| **token** | 模型计费的单位，大约可以理解成“字数碎片”。输入和输出都算钱 |
| **止烧 / 上限** | 花到这条线就自动停，防止一夜之间烧穿 |
| **上下文包** | 写这一章时，程序到底把哪些资料带给了模型（设定、前情、伏笔……） |
| **MCP** | 一种让外部 AI 工具连上本程序的通用接口。设置页能一键生成配置 |

## 五、发现看不懂的词怎么办

在“使用手册”的搜索框里搜它。搜不到就说明这是**该改的文案**，
记下来告诉我们 —— 界面上不该出现只有开发者才懂的词。
