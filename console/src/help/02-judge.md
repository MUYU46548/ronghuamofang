# 判定怎么用：这一章行不行

判定不是让模型给自己打分。它只做三件事：

1. **系统测能测的**——重复句、空泛形容词、可以替换的骨架句、缺陷段占比；
2. **你判测不了的**——这一章到底有没有推进（靠「这一章发生了几件事」勾选）；
3. **两者都不糊弄**——测不出来就给「不可判定」，绝不给「合格」。

## 一、先回答最常见的问题：「几件事」怎么算

**动作不算事，状态变了才算事。**

| 章纲里写的 | 算不算 | 为什么 |
|---|---|---|
| 他去档案室查底档 | 不算 | 动作。读完这行，世界没有变化 |
| 他抄下编号 | 不算 | 同上 |
| 他发现编号是伪造的 | **算** | 他知道的事变了 |
| 他决定去找老周 | **算** | 他的目标变了 |

所以判据是一句话：**这件事发生后，某个东西不一样了。**

四类就是"什么东西变了"：

- **人物处境**：被抓、受伤、被辞退、身份暴露、欠下债
- **信息占有**：得知真相、被瞒住、误会解开、拿到了不该有的情报
- **关系**：结盟、翻脸、背叛、认亲、断交
- **目标**：决定复仇、放弃、改主意、立下承诺

选错类别不影响结论，但会影响你以后回看这张表——类别是给将来的自己看的。

## 二、为什么下限是 2 件

一章只有一件事，篇幅再长也是水章。这是长篇的常识判据，写在口径 `J12`（默认 2，可改）。

**这个数不是系统算出来的，是你勾出来的。**系统不替你数——它没有资格替你判断"这算不算一件事"。

## 三、怎么操作

1. 进「分章」页 → 左侧点一章；
2. 拉到章纲卡片下方，就是「这一章发生了几件事（你来定）」；
3. 章纲「核心事件」里写了哪几条，这里就列哪几条；
4. 逐条过一遍，每条只能落三种状态之一：

| 你的动作 | 含义 |
|---|---|
| 打勾 + 选一类 | 认定：这是一件事 |
| 点「不算一件事」 | 已判断：这只是动作，不算 |
| 什么都不做 | 还没看（界面会显示「已过目 2/4」） |

5. 点「保存勾选」。

**「不计入」是什么意思**：勾了但没填"哪句原文能看出来"，这条仍算你认定的事，但**不算进"至少 2 件"这条线**。
这条规矩来自需求 R24（没举证的不计入下限）。填一句原文不是义务，但填了你以后回看会感谢自己。

## 四、勾完之后会发生什么

保存后判定会重算该章，落三档之一：

| 档位 | 什么时候 |
|---|---|
| **合格** | 认定 ≥ 2 件，且缺陷段占比没超阈值 |
| **需定点重写** | 认定够 2 件，但缺陷集中在某些段落（会告诉你第几段） |
| **需重写本章** | 认定只有 1 件（甚至 0 件），或章纲密度虚高 |
| **不可判定** | 没正文 / 没章纲事件 / 三稿被压缩两次（结论不可信时**不给档位**） |

**没勾完之前，结论是「待作者勾选」，不是「合格」。** 这是刻意的：没意见和没看是两件事。

## 五、几个实际问题

**章纲没写核心事件怎么办？**
先去章纲把「核心事件」写清再回来。零事件时判定直接给「不可判定：无章纲」，因为病因无法对账。

**四条里有一半是同一场戏怎么办？**
界面会按**字面重合**提示一句（比如"第 3、4 条读起来像连续动作"）。但系统抓不到语义上的"同一场戏"——它只比字面。抓不到不代表没问题，算几件事仍然由你定，系统不替你合并。

**为什么只能在客户端里勾，外部 Agent 不行？**
勾事件和逐句裁定是作者的判断。这两个端点在 Agent 模式下是禁止的——外部 Agent 可以读，不能代替你签字。

**改了口径（下限从 2 改成 3）会怎样？**
口径改动会产新版本，旧结论留档。改完要在判定页点一次重跑，旧档位才会按新口径重算。

## 六、每条判据凭什么这么说

「改标准」页（合格标准表）最右侧有一列 **「本书里的一个例子」**——显示这条判据在你**这本书**里命中的第一句原句，并标出第几章第几段。

- 引文是**从正文切句里取的**，不是编的；取不到就显示「最近一次回测里没命中」；
- 显示"没命中"有两种可能：这一章确实没问题，或者这条判据没生效——所以别把"没命中"当成"通过"。

## 七、如果判据"睡着了"

判定页会出现一条红色提示：**「⚠ 判据可能已失效，建议人工抽检」**。

触发条件：某章上一次判定命中 ≥5 处（字数/句长类 F01 + 可替换骨架 F03），这一次 **0 处**，而字数仍然达标。

系统**分不清**两种情况：稿子真的改好了，或者判据对你现在的写法失效了（措辞变了，判据还在找旧特征）。所以它只提醒，不改任何结论。

你该做的：抽检那一章，自己读两段，确认不是"没人检查"。

## 八、整本否掉

整本判定页最底部有 **「整本否掉」**：看完全部章之后，如果你的判断是"这本书不行"而不是"某几章要改"，就在这里记一笔。

- **理由必填，至少 8 个字**——半年后你得看得懂当时为什么；
- 只落一条记录（理由 + 时间），**不会删除或改动任何稿件**；
- 记下后页面顶部会有横幅，随时可以**撤销**（撤销的记录留在历史里，不是凭空消失）；
- 外部 Agent 可以读这条判断，但不能替你点——这是作者的判断。

### 否掉之后：归档这本书

同一个位置还有个 **「归档这本书」** 按钮。它做的事只有一件：**把整本搬走**。

| | 归档 | 删除 |
|---|---|---|
| 稿子去哪 | `data/books/<书名>/`（含素材与配置） | 进系统回收站 |
| 还能拿回来吗 | 能，在「项目」页点恢复 | 只能在回收站里找 |
| 谁会做 | 你点「归档这本书」 | 你点归档列表里的删除 |

- 归档**不删任何东西**。搬之前系统还会自动打一个回退点（快照）；
- 归档原因会写进归档的 `_meta.json`（优先用你填的否掉理由）——
  半年后翻归档列表，看得见「这本当初为什么被收起来」；
- 归档之后怎么办（留着、恢复重写、彻底删掉）**都是你的事**。
  系统不替你清产物——那一步风险太高，做错了没法挽回。

## 九、三稿对照：哪一步把 6000 字削成了 2000

单章详情右上角有 **「三稿对照」**：**原文（stage4）· 检查稿（stage5）· 润色稿（stage6）** 三栏并排。

- 顶部给两段缩减率：**原→检 40% · 检→润 24%**，超过阈值会明说“疑似整章重生成”；
- 三栏**各自滚动，不做逐行对齐** —— 段数一变行就错位，那样看着整齐、实际更误导。
  用每段前面的**段号**横向找同一段；
- 缺哪一版就明说“**这一版不存在**”，并告诉你缺的是哪个阶段。
  空栏不会冒充“没变化”——那是两件完全不同的事。

怎么用：读原文第 3 段，再去检查稿看它是被删了、还是被改短了，然后看润色稿又动了什么。
判断“检查阶段删得对不对”，只有并排看才有依据。
